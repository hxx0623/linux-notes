## 踩过的坑（备忘）

- VMware 控制台粘贴多行会出现 `^[[200~` 并被拆行 → 改用 Windows PowerShell `ssh` 进去操作，或逐条手打。
- `ls -l /` 输出末尾出现绿色 `END` → 是 `less` 分页器，按 `q` 退出。
- `systemctl is-active ssh` 显示 `inactive` 属正常（Ubuntu 24.04 用 `ssh.socket` 激活）。
- **`sudo systemctl isolate multi-user.target` 之后桌面回不来**（10-22 实测）：
  gdm 会停在 `inactive (dead) … status=0/SUCCESS`（干净退出，不是崩溃）。
  `isolate graphical.target` **不会**把它拉起来（`gdm.service` 是 `static`，靠 `display-manager.service` 别名拉起）。
  恢复：`sudo systemctl start gdm3`；屏幕停在别的虚拟终端时再补 `sudo chvt 1`。
  **不要用 `Ctrl+Alt+F1` 切 VT**——VMware 把 `Ctrl+Alt` 当“释放鼠标”的全局热键，按键进不到客户机。
- `systemctl is - system-running` → `Unknown command verb 'is'`：命令名里多打了空格，`systemctl` 只认出第一个词。
- **UEFI 机器开机按 Esc 进不了 GRUB，反而停在固件 Boot Manager**（10-22 实测）：Esc 按得比 GRUB 早，
  卡在固件层的蓝色「Boot Manager」（Boot normally / Ubuntu / EFI VMware … / Enter setup）。
  根因是 Ubuntu 默认 `GRUB_TIMEOUT=0` + `GRUB_TIMEOUT_STYLE=hidden`，**GRUB 菜单根本不显示**。
  解决：改 `/etc/default/grub` 为 `GRUB_TIMEOUT_STYLE=menu` + `GRUB_TIMEOUT=10`，再 `sudo update-grub`；
  然后重启**什么都别按**，等菜单自己出来。备份在 `/etc/default/grub.bak`。
- **`sudo 命令 > 文件` 一定失败**（10-23 实测）：报错是 `bash: /home/info.txt: 权限不够`。
  前缀 `bash:` 就是证据——**打开文件的是 shell，不是 `ls`**，所以 `sudo` 只提权了 `ls`，重定向仍是普通用户身份。
  `cd ~` 也没用（路径是绝对的）。三种正确写法：
  `命令 | sudo tee 文件`（覆盖）、`命令 | sudo tee -a 文件`（追加）、`sudo sh -c '命令 > 文件'`（整条提权）。
- **`adduser -g` 会报歧义**：`adduser: Option -g is ambiguous (gecos, gid, group)`。
  `adduser` 是 Debian 的友好脚本（`-g` 是 gecos 备注），**跟 `useradd` 不是一回事**。
  要指定主组：`adduser --ingroup wudang zwj`，或用 `useradd -m -s /bin/bash -g wudang zwj`。
- **大小写三连坑**：`$SHELL`（当前 shell）≠ `$shell`（空）；`pwd -P`（真实路径）≠ `pwd -p`；
  `date +%Y`（2026）≠ `date +%y`（26）。Linux 处处区分大小写，拼完先怀疑这一点。
- **`locate` 系**：`locate` 默认没装（`sudo apt install plocate` 后可用）；`sudo updatedb` 会报
  `/var/lib/plocate/: Permission denied`——**不是文件权限问题**，但 plocate 装好时已建好索引，
  且 `plocate-updatedb.timer` 每天自动跑，**所以 `locate` 照样能用，不必管这个报错**。
- **拼错命令时，Ubuntu 的安装建议不能照做**：`cai link.txt` 被 `command-not-found` 建议
  `sudo apt install emboss`——那是生物信息学大套件，里面恰好有个叫 `cai` 的程序。
  **`command-not-found` 只按名字匹配，不看你想干什么**；看到陌生建议先 `apt show` 看一眼，别直接装。
- `cp -r demo deno2`（把 `m` 打成 `n`）之后 `tree demo demo2` 报 `demo2 [error opening dir]`：
  **`cp` 本身没错，错在两行之前那个字母**。排查时先往上看，别死磕报错那一行。
