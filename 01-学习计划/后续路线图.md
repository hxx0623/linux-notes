| 线 | 内容 | 部署位置 | 归哪个会话 |
| --- | --- | --- | --- |

| **副线（本节）** | **香橙派 5 开发板**：刷机 → 跑 Android → 在板子上做项目 | **单板 / 边缘** | 本会话（Ubuntu） |

### 学习者原意（很重要，别搞错方向）

> 「我一开始以为是在**开发板上面**搞安卓虚拟化。」

他原本把「Android 虚拟化」和「香橙派开发板」当成**同一件事**（在板子上做虚拟化实验）。
**2026-11-05 确认：不覆盖 —— 两条线都留。**

### 两条线其实是同一个技术栈的两个部署位置

```
        同一个目标：在一台机器上跑多个 Android
                    │
        ┌───────────┴───────────┐
   服务器侧（主线）          边缘侧（副线）
   云手机：容器 / namespace   香橙派 5：单板跑 Android
   数十 ~ 上百实例            资源少、有真实硬件
   搭子会话负责               本会话负责
```

**所以它们能互相印证**：主线给「原理与方案」，副线给「真实硬件上的落地、驱动、性能」。

### 建议顺序（供参考，可推翻）

**先在虚拟机上把虚拟化跑通，再上板子。**

理由：板子资源少、调试手段少（串口 / ADB 而已），先懂原理再上硬件少走弯路。
反过来也行，但容易卡在硬件问题上把节奏拖死。

### 学习者起点

> **"这一阶段我什么都不会，需要你教我怎么一步一步做。"**

→ 教学方式要从"讲课件"切换到 **手把手 SOP**：每一步给命令/界面截图位置、说明为什么、出错怎么回退。

### 技术栈（需要学的东西）

| 环节 | 要掌握的内容 |
| --- | --- |
| 硬件 | 板子接口、供电、HDMI、USB、TF 卡、eMMC、串口（UART） |
| **刷机** | 镜像下载、`RKDevTool`（Windows）/ `upgrade_tool`（Linux）、**Maskrom/Loader 模式**、USB-OTG 接线 |
| 系统 | 安卓镜像烧写位置（TF / eMMC / SPI）、首次启动、恢复出厂 |
| 调试 | **ADB**（`adb devices/shell/logcat/push/pull`）、`fastboot`、串口日志 |
| 开发 | Android Studio、跑 Demo、交叉编译、NDK（视项目而定） |
| 进阶 | 设备树（DTB）、内核编译、分区表、SDK 源码编译 |

### 平台背景（Orange Pi 5 = 瑞芯微 RK3588S）

- 官方提供 **Android 12/13 镜像**（官网下载页）
- 刷机主要靠 **RKDevTool**（Windows GUI，最省事）
- **SDK 源码编译**需要 Linux 环境，官方文档一般要求 **Ubuntu 20.04 / 22.04**

### ⚠️ 与本项目现有环境的衔接

| 项 | 现状 | 说明 |
| --- | --- | --- |
| 现有 Ubuntu VM | **24.04** | 日常学习够用；**但编译 RK SDK 可能不兼容**（官方多为 20.04/22.04） |
| 建议 | 到时**另开一个 22.04 虚拟机**专门做 SDK 编译 | 别把学习用的 24.04 环境搞乱 |
| 可复用 | Shell 编程、权限、磁盘挂载、网络、`apt`、Python | 这些技能直接迁移 |

**教学时的约定（新阶段补充）**：

1. **每一步都给"验证方法"**（怎么确认这步成功了）
2. **每步都给"回退方法"**（刷坏了怎么办 —— 香橙派有 Maskrom 模式可以救砖，要早说）
3. 涉及硬件操作先确认**断电/接线顺序**（烧板子比删文件贵）
4. 优先用**官方镜像 + 官方工具**跑通，再折腾源码编译
