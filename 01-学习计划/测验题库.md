### A 类：场景排障（每题 1 分）

**A1**　`crontab -l` 里有任务、时间也对，但到点没执行。列出你的排查顺序（至少 4 步）。

<details><summary>答案</summary>

1. **cron 服务在跑吗** → `systemctl status cron`
2. **当前用户对不对** → crontab 是**按用户**的，`sudo crontab -l` 和 `crontab -l` 是两个
3. **脚本执行权限** → `ls -l` 有没有 `x`；或 `bash 脚本` 显式调用
4. **看日志找真实原因** → `journalctl -u cron` 或 `/var/log/syslog | grep CRON`（CentOS 是 `/var/log/cron`）
5. **环境变量差异** → cron 的 PATH 极简，脚本里要用绝对路径
6. **换行符** → 从 Windows 传进来的 `.sh` 带 `\r`，报 `bad interpreter` → `dos2unix`

</details>

**A2**　Windows 上 `ssh cxh@192.168.139.100` 连不上，报 `Connection refused`。怎么查？

<details><summary>答案</summary>

**先分清"拒绝"和"超时"**：
- `Connection refused` = 网络通了，但**22 端口没人听** → 服务侧问题
- `Connection timed out` = 根本不通 → 网络/防火墙问题

`refused` 的排查顺序：
1. `systemctl status ssh.socket`（Ubuntu 用 socket 激活，**没有常驻 sshd 进程是正常的**）
2. `sudo ss -tlnp | grep :22` —— 端口真的在听吗
3. `sudo systemctl start ssh` 或 `sudo systemctl enable --now ssh`
4. 服务没装 → `sudo apt install openssh-server`

`timeout` 的话：`ip a` 看 IP 对不对、`ping 192.168.139.2` 看网关、`sudo ufw status` 看防火墙（若 active 要 `sudo ufw allow 22`）。

</details>

**A3**　`df -h` 显示 `/` 用了 100%，但 `du -sh /*` 加起来远不到。可能是什么？

<details><summary>答案</summary>

**文件被删除但进程还占着** —— `du` 看不到，`df` 算在内。
```bash
sudo lsof +L1          # 列出被删但仍被打开的文件
sudo lsof | grep deleted
```
处理：重启对应进程（`systemctl restart xxx`）就释放。

其他可能：挂载点被覆盖（另一个分区挂到了非空目录上，原生文件被"藏"起来）、`/` 内的 inode 用尽（`df -i`）。

</details>

**A4**　`cat /etc/shadow` 报"权限不够"，但你已经是文件所有者。为什么？该怎么读？

<details><summary>答案</summary>

`/etc/shadow` 是 `640 root:shadow` 或 `600 root:root` —— **所有者是 root，不是你**。普通用户连 `r` 都没有。
- 正确读法：`sudo cat /etc/shadow`
- 只查自己的密码状态：`passwd -S` 或 `sudo passwd -S 用户名`
- `chmod` 自己改不动（不是 owner），硬改要先 `sudo chown`

</details>

**A5**　某服务被 `kill -9` 掉了，过一会儿又自己回来了。解释原因并说明怎么让它**别**回来。

<details><summary>答案</summary>

**systemd 自动重启**。单元文件里有 `Restart=always` 或 `Restart=on-failure`（我实测过 `on-failure` 版本）。
- 查：`systemctl cat 服务名 | grep Restart`
- 让它别回来：`sudo systemctl stop 服务名`（stop 后 systemd 不会再拉起），再 `disable` 防止开机自启
- ⚠️ 只用 `kill` 杀进程**不够**——systemd 会当它异常退出而重启

</details>

**A6**　`mount /dev/sdb1 /newdisk` 报 `mount: /newdisk: mount point does not exist`。为什么？课件里没这一步。

<details><summary>答案</summary>

**课件省略了建目录这一步**。`/newdisk` 目录本身必须先存在 —— 挂载是"把一个文件系统盖到一个已存在的空目录上"，不是自动创建目录。
```bash
sudo mkdir -p /newdisk
sudo mount /dev/sdb1 /newdisk
```
⚠️ 建出来的目录属主是 `root:root`，`cxh` 写不进去 → `sudo chown cxh:cxh /newdisk`。

</details>

### B 类：找错（每题 1 分）

**B1**　下面为什么每次都会创建一个叫 `1` 的空文件？
```bash
if [ 2 > 1 ]; then echo yes; fi
```

<details><summary>答案</summary>

`>` 被 shell 当成**重定向**，不是比较。实际执行的是 `[ 2 ]` 并把输出写到文件 `1`。
- 字符串比较用 `\>` 转义，或 `[[ 2 > 1 ]]`
- **数字比较用 `-gt`**：`[ 2 -gt 1 ]`

</details>

**B2**　这个循环跑完，`count` 还是 0，为什么？
```bash
cat list.txt | while read n; do count=$((count+1)); done
echo $count
```

<details><summary>答案</summary>

**管道右侧在子 shell 里执行**，变量改动出不来。
```bash
while read n; do count=$((count+1)); done < list.txt
```
或用进程替换 `done < <(cat list.txt)`。

</details>

**B3**　脚本第 14 行报错，但 14 行看着没问题，错在第 9 行。什么情况？

<details><summary>答案</summary>

**`if` / `elif` 漏了 `then`**。漏了之后 bash 把后面的 `echo` 吞进 `elif` 的条件列表里当命令，直到遇到 `else` 才报错。
**教训：报错行 ≠ 出错行**，往上翻。
工具：`bash -n 脚本`（只查语法）、`shellcheck 脚本`。

</details>

**B4**　`cp a.txt b.txt /tmp/newdir` 报错，但文件都在。为什么？

<details><summary>答案</summary>

**目标目录不存在**。`cp 多个源 目标` 时，目标**必须已经是目录**，`cp` 不会自动创建。
```bash
mkdir -p /tmp/newdir && cp a.txt b.txt /tmp/newdir
```
（`cp -r 目录 新名字` 可以创建立目的，但那是"重命名"语义，和多个源情况不同。）

</details>

**B5**　`for f in *.txt; do echo $f; done`，目录里没有 txt 时打出了 `*.txt`。为什么？

<details><summary>答案</summary>

**通配符没匹配到时，bash 原样保留**（默认不开 `nullglob`）。
```bash
for f in *.txt; do [ -e "$f" ] || continue; echo "$f"; done
# 或
shopt -s nullglob
```

</details>

### C 类：概念（每题 1 分）

**C1**　`rwx` 三组权限位，判断顺序是什么？为什么 `other` 有 `r` 也可能读不了文件？

<details><summary>答案</summary>

**三栏互斥，从左到右第一个匹配就停**：owner → group → other。
所以如果文件属主是你、属主位是 `---`，就算 `other` 是 `rwx`，**你也被判成 owner 而拒绝**。
读文件还要求**路径上每一层目录都有 `x`**，缺一层就是"权限不够"。

</details>

**C2**　删掉一个文件，需要的是文件本身的 `w` 还是目录的 `w`？

<details><summary>答案</summary>

**目录的 `w`**。文件名是目录里的一条记录，删文件 = 删目录项。
- 目录 `w` → 能增删目录里的条目（不管文件属主是谁）
- 文件 `w` → 只能改**内容**
配合目录的 `x` 才能进去操作。

</details>

**C3**　`umask` 是什么？你的 Ubuntu 新建文件为什么是 `664` 而课件是 `644`？

<details><summary>答案</summary>

`umask` 是"要**减掉**的权限位"，**默认权限 = 满权限 − umask**（文件满 `666`，目录满 `777`，文件天生没有 `x`）。
- Ubuntu 桌面默认 `0002` → 文件 `664`、目录 `775`
- CentOS 默认 `0022` → 文件 `644`、目录 `755`
- 实测：`source /etc/profile` 之后 umask 会变成 `0022`，文件也就变 `644` 了。

</details>

**C4**　`systemctl enable` 和 `systemctl start` 分别做了什么？`enable` 会立刻启动吗？

<details><summary>答案</summary>

- `start` = **现在**启动（立即生效，重启就没了）
- `enable` = **开机**自启（只是建软链接，**不启动**）
- 两个都要 → `systemctl enable --now 服务名`
- 查：`is-enabled`、`is-active`

</details>

**C5**　Ubuntu 上 `ps aux | grep sshd` 什么都没有，但 SSH 明明能用。解释。

<details><summary>答案</summary>

**`ssh.socket` 按需激活** —— 平时没有常驻 sshd 进程，有连接进来时 systemd 才拉起。
所以：**"服务正常"≠"有进程在跑"**。
- 服务名是 **`ssh`**，不是 `sshd`
- `systemctl status ssh.socket` 是 active 就对了
- 这个坑在课件第 14 章出现了三次（`ps`、`pstree`、`netstat` 各一次）。

</details>

**C6**　`load average: 8.00` 在 4 核机器上意味着什么？高 load 一定说明 CPU 忙吗？

<details><summary>答案</summary>

**满载且已排队**：8 ÷ 4 = 每个核上排 2 个任务。
**不一定** —— load 统计的是"运行 + 不可中断等待（D 状态）"的进程数。IO 卡住一样把 load 拉高。
区分方法：看 `top` 的 `%wa`（等 IO）和 `%id`（空闲）→ 高 `wa` 是 IO 瓶颈，高 `us` 才是 CPU 忙。

</details>

### D 类：写命令（每题 1 分）—— 五个模板，这是主攻方向

**D1**　每天 **凌晨 2:30** 执行 `/home/cxh/shcode/backup.sh`。

<details><summary>答案</summary>
```bash
30 2 * * * /home/cxh/shcode/backup.sh
```
五段顺序：**分 时 日 月 周**。日、月**没有 0**（1 开始），周 `0` 和 `7` 都是周日。
</details>

**D2**　每周一、周四 **下午 6 点**执行 `my.sh`。

<details><summary>答案</summary>
```bash
0 18 * * 1,4 /home/cxh/shcode/my.sh
```
</details>

**D3**　在 `/etc` 下找 **最近 3 天内修改过**的、名字以 `.conf` 结尾的普通文件。

<details><summary>答案</summary>
```bash
find /etc -type f -name "*.conf" -mtime -3
```
- `-mtime -3` = **3 天内**（负号）；`+3` = 3 天前；`3` = 正好第 3 天
- 顺序无所谓，但 `-name` 的模式**必须加引号**，否则被 shell 先展开
</details>

**D4**　把 `~/shcode` 目录打包成 `~/backup/code-20261112.tar.gz`，要求包内**不带**绝对路径。

<details><summary>答案</summary>
```bash
tar -zcf ~/backup/code-20261112.tar.gz -C ~ shcode
```
`-C 父目录 相对名` 是关键：进到 `~` 再打包 `shcode`，解出来就是 `shcode/`，不会带 `/home/cxh/`。
先确认 `~/backup` 存在，`tar` 不会替你建目标目录。
</details>

**D5**　给 `/newdisk` 写一条 fstab 记录（用 UUID，ext4，能 dump 检查，开机 fsck）。

<details><summary>答案</summary>
```
UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx  /newdisk  ext4  defaults  0  2
```
六列：**设备 / 挂载点 / 类型 / 选项 / dump / fsck 顺序**。
- 第 5 列 dump：一般 `0`
- 第 6 列：根分区 `1`，其它 `2`，**swap 和光驱写 `0`**
- UUID 用 `blkid` 或 `lsblk -f` 查
- 写完 `sudo mount -a` 验证，**不报错才算对**（写错会导致开不了机）
</details>

**D6**　重启 `ssh` 服务并设为开机自启（一条命令）。

<details><summary>答案</summary>
```bash
sudo systemctl enable --now ssh && sudo systemctl restart ssh
```
语序永远是 `systemctl <动作> <服务名>`。Ubuntu 服务名是 **`ssh`**（不是 `sshd`）。
只想重启：`sudo systemctl restart ssh`。
</details>

**D7**　把 `/home/cxh/data` 及其**所有内容**的属主改成 `tom`、属组改成 `wudang`。

<details><summary>答案</summary>
```bash
sudo chown -R tom:wudang /home/cxh/data
```
`-R` **必须大写**（lowercase `-r` 在 chown 里不是递归）。
只改属组可以用 `chgrp -R wudang 目录`，但**非 root 只能改到自己所属的组**（我踩过：cxh 不在 fruit 组就 `chgrp fruit` 失败）。
</details>

**D8**　让 `/home/cxh/report.txt` 只有属主能读写，其他人完全无权限（用数字表示）。

<details><summary>答案</summary>
```bash
chmod 600 /home/cxh/report.txt
```
`6` = `rw-`（4+2），`00` = 两组 `---`。对照：`644` 公开可读、`755` 目录/脚本、`777` 危险。

</details>

**D9**　列出当前系统所有**监听中的 TCP 端口**及对应进程（现代写法）。

<details><summary>答案</summary>
```bash
sudo ss -tlnp
```
- `-t` TCP、`-l` listening、`-n` 不解析名字、`-p` 显示进程
- `netstat -tlnp` 是老写法，需装 `net-tools`，现代 Ubuntu 用 `ss`

</details>

**D10**　找出 `~/shcode` 下所有 `.sh` 文件并**一次性**加上执行权限。

<details><summary>答案</summary>
```bash
find ~/shcode -name "*.sh" -type f -exec chmod +x {} \;
```
**不能用 `| xargs rm` / `| xargs chmod` 里的管道喂 `rm`** —— 文件名带空格会拆错。`-exec ... {} \;` 安全。
（`-delete` 只能删文件，删不了非空目录。）
</details>

### E 类：预测输出（每题 1 分）

**E1**
```bash
x=1; y=2; echo $((x+y)); echo $x+$y
```
两行分别输出什么？

<details><summary>答案</summary>

```
3
1+2
```
`$(( ))` 才做算术；没包起来的 `$x+$y` 只是**字符串拼接**。
</details>

**E2**
```bash
f() { echo "start"; return 300; }
f; echo "退出码：$?"
```

<details><summary>答案</summary>

```
start
退出码：44
```
**退出码只有 0–255**，`300 − 256 = 44`。
要返回数据（比如大于 255 的数、字符串）必须用 `echo` 输出 + `$( )` 接收，别用 `return`。
</details>

**E3**
```bash
ls -l /etc | grep "^-" | wc -l        # 普通用户
sudo ls -l /etc | grep "^-" | wc -l   # root
```
两个数字为什么不一样？（我实测 1682 vs 1683）

<details><summary>答案</summary>

普通用户**读不到的目录被静默跳过**（那些是 `700` 的目录，里面的文件 `ls` 列不出来，但也不报错）。
所以数字小 1。**不要用 `2>/dev/null` 把这类差异藏起来** —— 差一个就说明有东西没看见。
</details>

**E4**
```bash
echo 1 > f; echo 2 >> f; echo 3 > f; cat f
```

<details><summary>答案</summary>

```
3
```
`>` **覆盖**（每次截断重写），`>>` **追加**。
执行顺序：写 `1` → 追加 `2`（内容 `1\n2`）→ 覆盖成 `3`。
</details>

**E5**
```bash
case "abc" in
  a*) echo A ;;
  *)  echo other ;;
esac
```

<details><summary>答案</summary>

```
A
```
`case` **从上往下第一个匹配就执行**，不像 C 语言要 `break`。`a*` 匹配了就不再看 `*`。
</details>

### F 类：Ubuntu 与 CentOS 差异（每题 1 分）

**F1**　课件的 `/etc/sysconfig/network-scripts/ifcfg-ens33` 在哪？Ubuntu 怎么写网络配置？

<details><summary>答案</summary>

**`/etc/sysconfig/` 整个目录不存在**（那是 RedHat 系）。Ubuntu 用 **netplan**（`/etc/netplan/*.yaml`，YAML 格式）+ NetworkManager。
- 网卡名按 PCI 位置生成，本机是 **`ens160`** 不是 `ens33`
- 改完 `sudo netplan apply`；试错用 `sudo netplan try`（60 秒不确认自动回滚）
- ⚠️ **本机特殊情况**：IP 是在桌面 GUI 里设的，`50-cloud-init.yaml` 还写着 `dhcp4: true` —— **别跑 `netplan apply`**，会把 IP 打回 DHCP

</details>

**F2**　`yum` / `rpm` 在 Ubuntu 上对应什么？`--permanent` + `--reload` 呢？

<details><summary>答案</summary>

| CentOS | Ubuntu |
| --- | --- |
| `yum install` | `apt install` |
| `yum remove` | `apt remove`（`purge` 连配置一起删） |
| `rpm -qa` | `dpkg -l` |
| `rpm -ql 包` | `dpkg -L 包` |
| `rpm -qf 文件` | `dpkg -S 文件` |

防火墙：`firewalld --permanent` + `--reload` → Ubuntu 用 **`ufw`**，**`sudo ufw allow 22` 立刻生效，没有 `--permanent`，没有 `reload`**。
</details>

**F3**　`service 服务名 restart` 还能用吗？`chkconfig` 呢？

<details><summary>答案</summary>

- `service` 命令**还在**（兼容层，实际转发给 systemd），但推荐直接用 `systemctl`
- **`chkconfig` 不存在** → `systemctl enable/disable`
- `runlevel` → `systemctl get-default`
- `setup` → 没有
- ⚠️ Ubuntu **没有 `network` 这个服务**（网络归 NetworkManager + netplan），`service network restart` 一定失败

</details>

**F4**　课件让你用 `python`，你的机器上出不来。为什么？怎么修？

<details><summary>答案</summary>

Ubuntu 24.04 **只有 `python3`**，没有 `python`。
- 临时：`python3 脚本.py`
- 一劳永逸：`sudo apt install python-is-python3`（建个 `python → python3` 的软链）
- ⚠️ **PEP 668**：`pip install` 到系统环境会被拦 → 用 `python3 -m venv 环境名` 建虚拟环境
</details>
