# C 语言急速复习（面向香橙派 5 嵌入式）

> 建立于 **2026-11-12**。学习者背景：**大学学过 C，已遗忘**；**敲代码不熟练**（能看懂，写不出）。
> 目标不是"重新学一遍 C"，而是**用最短时间恢复到"能写、能编译、能调试"**，直接为香橙派项目供能。

## 一、为什么"急速"是可行的

C 语言本身**语法很小**（关键字 32 个，常用不到 20 个）。真正难的是**指针和内存** —— 而这恰好也是嵌入式唯一绕不开的部分。

所以路线是：**语法部分快速过（2 小时），把 80% 时间砸在指针 / 结构体 / 内存 / 位操作上。**

---

## 二、教学法：抄 → 改 → 造

| 阶段 | 做什么 | 治什么病 |
| --- | --- | --- |
| **抄** | 我给一段能跑的代码，你**一个字一个字敲一遍**（不许复制粘贴） | **敲代码不熟** —— 手感只能靠敲出来 |
| **改** | 我给 3 个"改造任务"，你改完编译看效果 | 建立"改动 → 编译 → 结果"的因果感 |
| **造** | 自己写一个小功能（不给代码） | 从"看懂"到"写出" |

> **为什么强调手敲**：和 Linux 那次测验的结论一样 —— **理解 88%，提取不出来**。C 也是一样，读过一万行不如敲过一百行。

## 三、环境（Ubuntu 虚拟机）

```bash
gcc --version          # 编译器
make --version         # 构建工具
gdb --version          # 调试器
```

缺了就装：

```bash
sudo apt install build-essential gdb
```

**为什么在虚拟机而不是 Windows**：
- 香橙派的开发**全在 Linux 下**（交叉编译、make、脚本）
- 你 Linux 命令行已经熟了（vim / 管道 / 权限），**写 C 会顺手**
- Windows 装编译器是额外成本，且和最终环境不一致

## 四、模块表（6 次课，每次 60–90 分钟）

| # | 模块 | 内容 | 为什么嵌入式需要 | 状态 |
| --- | --- | --- | --- | --- |
| **0** | 工具链与"能编译" | 编译四个步骤（预处理/编译/汇编/链接）、**怎么读 gcc 报错**、`-Wall` | 报错读不懂 = 后面全卡 | ⬜ |
| **1** | 数据类型与位运算 | `int` 几字节、有符号/无符号、`&` `\|` `^` `~` `<<` `>>`、`0x` 十六进制 | **寄存器操作全靠位运算**（你 131 集见过 `BCD_TO_BIN` 就是这个） | ⬜ |
| **2** | **指针（一）** | 地址、`&` `*`、指针作函数参数（**值传递 vs 地址传递**） | 所有 C API 都用指针传参 | ⬜ |
| **3** | **指针（二）+ 字符串** | 指针与数组的关系、`char*` 与字符串、**缓冲区边界**（`strcpy` 的坑） | 嵌入式最经典的崩溃原因 | ⬜ |
| **4** | 结构体 | `struct`、`typedef`、**结构体指针 `->`**、结构体数组 | **驱动/内核里到处是结构体**（设备树、file_operations） | ⬜ |
| **5** | 文件 IO + 命令行参数 | `fopen/fread/fwrite`、`argc/argv`、**写一个真实小工具**（统计文件行数 / 十六进制 dump） | 板子上跑程序必须读设备文件、接参数 | ⬜ |
| **6** | 动态内存 + 多文件 + make | `malloc/free`、头文件、`make` 多文件编译、`gdb` 基本用法 | 香橙派 SDK 全是 make 多文件 | ⬜ |

> **总时长约 8–10 小时。** 每天 1 次，一周多能恢复"能写"的状态。

## 五、和香橙派的关系

**C 不是第四条并行的线 —— 它是香橙派的燃料。**

```
香橙派刷机         → 不需要 C（用现成工具 + 镜像）
香橙派跑通系统     → 不需要 C（shell 就够，你 Linux 底子在）
香橙派做项目       → ⭐ 正式开始需要 C：
                     · 操作 GPIO / I2C / SPI（ioctl + 结构体）
                     · 写字符设备驱动（file_operations 结构体）
                     · 读传感器（位运算 + 类型宽度）
                     · 改设备树、编内核（make + 多文件）
```

所以顺序是：**先刷机跑通（1–2 天）→ 同时开始 C 复习 → 两者在"写第一个板子程序"处汇合。**
