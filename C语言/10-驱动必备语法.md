# C 语言 第 9 课：驱动必备语法（volatile / union / 位域 / 函数指针 / static）

> 2026-11-18。**这一课的 5 个东西，是"看懂驱动代码"的最后一块语法拼图。**

---

## 一、⭐ `volatile` —— 禁止编译器缓存内存读取

```c
while (*flag == 0) { }        /* 等硬件把 flag 改成 1 */
```

**问题**：编译器想"`flag` 循环里没被改 → 只读一次就够了" → 优化成死循环，**永远等不到硬件**。

**解法**：
```c
volatile int *flag;            /* 每次都必须真读 */
```

### 亲手验证（`gcc -O2 -S` 看汇编）

```c
void wait_no_volatile(int *flag)          { while (*flag == 0) { } }
void wait_volatile(volatile int *flag)    { while (*flag == 0) { } }
```

**汇编差异**：
- `wait_no_volatile`：循环体里**没有读内存的指令**（只 `jmp` 自己）
- `wait_volatile`：**每轮都有 `mov eax, [rdi]`**

> 🔑 **`volatile` 不是"让变量可变"，是"禁止编译器缓存这个内存的读取"。**
> 凡是硬件会改的、中断会改的变量，必须加 `volatile`。

## 二、`union` —— 同一块内存的多种解释

```c
struct S { int a; char b; };    /* 两个不同位置，共 8 字节 */
union  U { int a; char b; };    /* 共用同一块内存，共 4 字节 */
```

### 用途 1：同一块内存的多种视图

```c
union Data { unsigned int u32; unsigned char bytes[4]; };

d.u32 = 0x12345678;
/* 实测：bytes = 78 56 34 12 */
```

### 用途 2：⭐ 判断大小端（嵌入式必知）

```c
union { unsigned int i; unsigned char c[4]; } e;
e.i = 1;
if (e.c[0] == 1) → 小端（x86/ARM 默认）；否则大端
```

**实测输出**：`小端（Little-Endian）：低位字节在低地址`

> 📌 **为什么必须懂**：网络协议规定用大端（网络字节序），x86/ARM 是小端 →
> 收发数据必须 `htons()` / `ntohl()` 转换。

## 三、位域（bit-field）

```c
struct Flags {
    unsigned int a : 1;     /* 1 位：0~1 */
    unsigned int b : 3;     /* 3 位：0~7 */
    unsigned int c : 4;     /* 4 位：0~15 */
};
```

### ⚠️ 实测发现 1：**`sizeof` 不等于"位数之和"**

```
a(1位) + b(3位) + c(4位) = 8 位 = 1 字节
但实测 sizeof(struct Flags) = 4 字节！
```

**原因**：位域的**底层类型是 `unsigned int`（4 字节）**，GCC 按这个存储单元分配。
想省空间要用 `unsigned char a : 1;`（但那样对齐会变）。

### ⚠️ 实测发现 2：**溢出被 `-Wall` 抓到**

```c
f.b = 9;     /* 3 位最大 7 */
```
```
warning: unsigned conversion from 'int' to 'unsigned char:3'
         changes value from '9' to '1' [-Woverflow]
```
**运行结果：`b = 1`**（9 的低 3 位 = 001，即 1）—— **静默截断**。

> 📌 **位域适合"自己程序内部用"，不适合定义通信协议格式** ——
> 协议要用**移位 + 掩码**手动处理（`(x >> 3) & 0x7`），才跨平台。

## 四、⭐ 函数指针 —— 驱动架构的核心

### 语法

```c
int (*fp)(int, int);      /* 指向"返回 int、接受两个 int"的函数的指针 */
```
**外层括号不能去** —— 去掉就变成"返回指针的函数"。

### 实测

```
fp(3,5) = 8           ← 函数名直接赋值：fp = add;
(*fp)(3,5) = 8        ← 等价写法
fp(3,5) = -2          ← fp = sub; 之后

函数指针数组：
add(6,2) = 8
sub(6,2) = 4
mul(6,2) = 12

apply(add,4,7) = 11   ← 回调
```

### ⭐⭐ 这就是 Linux 驱动

```c
/* 内核里的 struct file_operations（简化） */
struct file_operations {
    ssize_t (*read)(...);
    ssize_t (*write)(...);
    int     (*open)(...);
    int     (*release)(...);
};

/* 驱动做的事就是"填空" */
static struct file_operations my_fops = {
    .read    = my_read,
    .write   = my_write,
    .open    = my_open,
    .release = my_release,
};
```

**内核拿着这个结构体，通过函数指针调用你的代码** —— 驱动的全部秘密。

## 五、`static` / `const`

| 用法 | 作用 | 驱动里 |
| --- | --- | --- |
| `static int f(void)`（文件级） | 函数**只在本文件可见** | ⭐ 驱动内部函数全是 `static` |
| `static int x = 0;`（函数内） | **只初始化一次，跨调用保留** | 计数器、状态缓存 |
| `const` | 只读 | `const char *name` |

**实测**：
```
第 1 次调用
第 2 次调用      ← static int calls 没被重置
第 3 次调用
```

## 六、⭐ 完整示例：`led_ops`（驱动架构缩小版）

```c
#include <stdio.h>

/* 模拟硬件寄存器：硬件会改 → 必须 volatile；只在本文件 → static */
static volatile int led_state = 0;

/* 三个实现函数，都是 static（不污染全局符号） */
static int led_on_impl(void)
{
    led_state = 1;
    printf("LED 已点亮（state = %d）\n", led_state);
    return 0;                          /* 0 = 成功（内核风格） */
}

static int led_off_impl(void)
{
    led_state = 0;
    printf("LED 已熄灭（state = %d）\n", led_state);
    return 0;
}

static int led_status_impl(void)
{
    return led_state;
}

/* ⭐ ops 结构体：只装函数指针 */
struct LedOps {
    int (*on)(void);
    int (*off)(void);
    int (*status)(void);
};

/* 定义并初始化（C99 指定初始化器） */
static struct LedOps led_ops = {
    .on     = led_on_impl,
    .off    = led_off_impl,
    .status = led_status_impl,
};

int main(void)
{
    led_ops.on();
    printf("状态查询：%s\n", led_ops.status() ? "亮" : "灭");

    led_ops.off();
    printf("状态查询：%s\n", led_ops.status() ? "亮" : "灭");

    return 0;
}
```

**实测输出**：
```
LED 已点亮（state = 1）
状态查询：亮
LED 已熄灭（state = 0）
状态查询：灭
```

### 这段代码为什么是"驱动架构缩小版"

| 元素 | 驱动里对应 |
| --- | --- |
| `static volatile int led_state` | 寄存器变量 |
| `static int led_on_impl(void)` | 驱动内部函数 |
| `struct LedOps { int (*on)(void); ... }` | `struct file_operations` |
| `static struct LedOps led_ops = { .on = ... }` | 驱动的 ops 初始化 |
| `led_ops.on()` | 内核通过指针回调驱动 |

## 七、本课记住的 5 条

1. **`volatile` = 禁止编译器缓存读取**（硬件变量必加）
2. **`union` = 同一块内存多种视图**（大小端检测、协议解析）
3. **位域的 `sizeof` ≠ 位数之和**（底层类型决定存储单元）；**溢出不报错**
4. ⭐ **`struct` + 函数指针 = `file_operations`**（驱动的架构）
5. **`static` 函数 = 文件内私有**（驱动代码的默认写法）
