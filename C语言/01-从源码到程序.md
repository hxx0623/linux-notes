# C 语言 第 1 课：从源码到可执行文件

> 2026-11-14。教材 = 亲手踩的 5 个报错。**这一课的产出不是"会写 hello world"，是"能看懂 gcc 在骂什么"。**

---

## 一、一个程序要经过 4 个阶段

```bash
gcc -E hello.c -o hello.i    # ① 预处理：展开 #include / #define
gcc -S hello.i -o hello.s    # ② 编译：C → 汇编
gcc -c hello.s -o hello.o    # ③ 汇编：汇编 → 机器码（目标文件）
gcc hello.o   -o hello       # ④ 链接：目标文件 + 库 → 可执行文件
```

**记忆**：`-E`（end，预处理完就停）→ `-S`（stop，编到汇编就停）→ `-c`（compile only，不链接）。

| 产物 | `file` 显示 | 能运行吗 |
| --- | --- | --- |
| `hello.i` | C source, ASCII text | ❌ |
| `hello.s` | assembler source, ASCII text | ❌ |
| `hello.o` | ELF 64-bit **relocatable** | ❌（**没执行权限**，加了也报"格式错误"） |
| `hello` | ELF 64-bit **executable** | ✅ |

**实测数据**：`hello.c` 8 行 → `hello.i` **821 行**（`#include <stdio.h>` 把 800 多行头文件贴了进来）。

## 二、⭐ 五个报错全记录（实测）

### ① 漏分号 → **编译期 error**，还告诉你该加什么

```
hello.c:6:29: error: expected ';' before 'return'
    6 |     printf("hello,C\n" )
      |                          ^
      |                          ;
                                  ↑ gcc 直接补给你看
```

### ② `printf` 拼成 `print` → **编译 warning 通过，链接 error 失败**

```
hello.c:6:9: warning: implicit declaration of function 'print'; did you mean 'printf'?
    6 |     print("hello,C\n" );
      |     ^~~~~
      |     printf                          ← gcc 猜出你想写什么
/usr/bin/ld: hello.c:(.text+0x18): undefined reference to `print'
collect2: error: ld returned 1 exit status
```

⭐ **两个阶段的报错**：编译通过（只是警告"没见过 print"），**链接时找不到 `print` 的实现** → 最终失败。

### ③ 变量没声明 → **编译期 error**

```
hello.c:7:24: error: 'count' undeclared (first use in this function)
    7 |     printf("%d\n", count);
      |                     ^~~~~
hello.c:7:24: note: each undeclared identifier is reported only once for each function
```

### ④ 注释掉 `#include <stdio.h>` → **只有 warning，而且照样生成可执行文件**

```
hello.c:6:9: warning: implicit declaration of function 'printf'
hello.c:6:9: warning: incompatible implicit declaration of built-in function 'printf'
hello.c:6:9: note: include '<stdio.h>' or provide a declaration of 'printf'
+++ |+#include <stdio.h>
 1 | //#include <stdio.h>            ← gcc 直接给你改法（diff 形式）
```

**为什么能生成**：`printf` 在 libc 里**有实体**，链接找得到；缺的只是"声明"（编译器无法检查参数）。**这就是 C 最坑的地方 —— 所以永远加 `-Wall`。**

### ⑤ `main` 拼成 `mian` → **链接期 error，并暴露了程序的真正入口**

```
/usr/bin/ld: .../Scrt1.o: in function `_start':
(.text+0x1b): undefined reference to `main'
collect2: error: ld returned 1 exit status
```

⭐ **真正被执行的第一个函数不是 `main`，是 `_start`**（C 运行时启动代码）：
`_start` → 准备栈/参数 → **调用 `main`** → 拿到返回值 → 调用 `exit`。

## 三、⭐ 报错分类表（这张表最有用）

| 错误 | 报错前缀 | 阶段 | 类型 | 能生成程序吗 |
| --- | --- | --- | --- | --- |
| ① 漏 `;` | `hello.c:6:29: error:` | 编译 | error | ❌ |
| ② `print` 拼错 | **先** `warning:` **再** `/usr/bin/ld: ... error:` | 编译 → **链接** | warning + error | ❌ |
| ③ `count` 未声明 | `error: 'count' undeclared` | 编译 | error | ❌ |
| ④ 没 include | `warning: implicit declaration` | 编译 | **只有 warning** | ✅ **能！** |
| ⑤ `mian` 拼错 | `/usr/bin/ld: undefined reference to 'main'` | **链接** | error | ❌ |

**判读口诀**：
- **`hello.c:行:列: error:`** → **编译**阶段（源码写错了）
- **`/usr/bin/ld: ... undefined reference to 'xxx'`** → **链接**阶段（找不到实现/拼错了函数名）
- **`warning:`** → 只是提醒，**可能照样生成程序**

## 四、🌱 踩到的细节：`./hello.o` 报"权限不够"

```
bash: ./hello.o: 权限不够        ← 不是"格式错误"！
```

**两道门，按顺序拦**：

| 门 | 报错 | 原因 |
| --- | --- | --- |
| **① 执行权限** | `权限不够` | `gcc -c` 产出的 `.o` 是 `644`（没有 `x`） |
| **② 文件格式** | `无法执行二进制文件: 可执行文件格式错误` | 就算 `chmod +x`，它还是"可重定位目标文件"，不是可执行程序 |

```bash
ls -l hello.o          # -rw-r--r--  没有 x
chmod +x hello.o
./hello.o              # 这才会报"格式错误"
```

## 五、观察到的现象

- **去掉 `\n`** → 输出 `hello,Ccxh@cxh-...` —— **shell 提示符直接接在输出后面**（`\n` 就是"回车换行"）
- `printf` 的顺序 = 执行顺序
- **中文字符串能正常打印**（终端是 UTF-8）

## 六、记住这几条（以后天天用）

1. **`gcc xxx.c -o xxx`** 一条命令能跑，但内部是四步
2. **永远加 `-Wall`**（否则 warning 默默放过）
3. **两个报错阶段要分清**：`hello.c:行:列` = 编译；`ld: undefined reference` = 链接
4. **`.o` 不能直接运行** —— 它没有执行权限，也没有入口
5. **程序的真正入口是 `_start`**，它负责调用 `main`
6. **`#include` 是"文本替换"** —— 一个 8 行的文件能变成 821 行
