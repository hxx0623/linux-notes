## 一、语法速查

### 条件

```c
if (score >= 90) {
    ...
} else if (score >= 60) {
    ...
} else {
    ...
}
```

| 运算符 | 含义 |
| --- | --- |
| `==` `!=` | 等于 / 不等于（**注意是两个等号**） |
| `>` `>=` `<` `<=` | 大小比较 |
| `&&` `\|\|` `!` | 与 / 或 / 非（**C 里没有 and/or/not**） |

### 循环

```c
for (int i = 0; i < n; i++) { ... }     /* 知道次数 */
while (cond) { ...; }                    /* 知道条件 */
do { ... } while (cond);                 /* 至少执行一次 */
```
- `break`：**整个循环结束**
- `continue`：**跳过本次剩余部分**，进入下一轮

### 函数

```c
int add(int a, int b);      /* ① 声明（原型）：必须先有，否则调用处报隐式声明 */

int main(void) { int r = add(3, 5); ... }   /* ② 调用：实参复制给形参 */

int add(int a, int b) { return a + b; }     /* ③ 定义：return 交回值 + 立刻结束函数 */
```

## 二、⛔ 四个陷阱（全部实测）

### 陷阱 1：`=` 写成了 `==`（C 最经典 bug）

```c
int y = n % 2;
if (y = 0)       /* ⚠️ 赋值！把 0 赋给 y，然后判断"赋值结果"（= 0 → 假） */
```

**实测后果**：`is_even()` 对**任何数**都返回 0（4 被判成奇数），且 `y` 被改成 0。
**gcc 报**（仅开 `-Wall` 才有）：
```
warning: suggest parentheses around assignment used as truth value [-Wparentheses]
```

**修法**：`if (y == 0)`；更简洁：`return (n % 2 == 0);`（**比较结果本身就是 int 0/1**）

**防错手段**：`-Wall -Wextra`；**更狠：`-Werror`**（警告变错误，一个都不许过 —— 内核就这么干）；老派"尤达表达式" `if (0 == y)`（漏等号会编译报错）。

### 陷阱 2：`<=` 越界（数组越界第一来源）

```c
int arr[5] = {10,20,30,40,50};
for (int i = 0; i <= 5; i++) printf("%d\n", arr[i]);
```

**实测**：`arr[5]` 打印出 **`32764`**，**程序没崩**。
`32764` = `0x7FFC` —— **栈地址的低位**，说明它读到了栈上相邻的内存（保存的寄存器/返回地址之类）。

⭐ **最恐怖的地方**：**它没崩，还打印出一个"看起来正常"的数字** —— 你会以为程序是对的。
**越界读只是"看到别人的内存"，越界写才是灾难**（破坏栈 → 崩溃或更隐蔽的 bug）。

**抓它的工具：AddressSanitizer（ASan）**
```bash
gcc -fsanitize=address -g arr.c -o arr
./arr
```

**实测输出（2026-11-16，`arr.c:15` 是 `arr[5]` 那一行）**：

```
ERROR: AddressSanitizer: stack-buffer-overflow on address 0x7f2b8b000034
READ of size 4 at 0x7f2b8b000034 thread T0
    #0 0x... in main /home/cxh/c-lab/02-flow/arr.c:15     ← 精确到行
    #1 0x... in __libc_start_call_main
    #2 0x... in __libc_start_main_impl
    #3 0x... in _start                                    ← 又是 _start（程序真入口）
Address 0x... is located in stack of thread T0 at offset 52 in frame
    #0 ... in main arr.c:4
This frame has 1 object(s):
    [32, 52) 'arr' (line 5) <== Memory access at offset 52 overflows this variable
```

**怎么读**：
- `arr` 占 **`[32, 52)` = 20 字节** = 5 个 int ✅
- 访问 **`offset 52`** = `arr[5]` 的地址（32 + 5×4）→ **刚好越过右边界**
- `READ of size 4` = 这次读 4 字节；如果换成**写**，会直接崩

**影子内存（Shadow bytes）**：每 8 个应用字节对应 1 个影子字节。
```
=>0x...: f1 f1 f1 f1 f1 00[04]f3 f3 f3 f3 f3
                         ↑  ↑
                    00=可用  04=部分可用(4字节)   f3=右侧红区
```
`f1` = 栈左红区、`f2` = 栈中间红区、`f3` = 栈右红区 —— **ASan 在变量周围塞"毒地"（Redzone），越界一碰就报警**。

**代价**：内存占用增加、速度约慢 2 倍 → **只在调试时开**。

### 陷阱 3：`unsigned` 倒序循环 = 死循环

```c
for (unsigned int i = 5; i >= 0; i--)   /* ⚠️ 永远停不下来 */
```
**原因**：`unsigned` **永远 ≥ 0**，`i >= 0` 恒真；`0--` 会变成 `4294967295`（`UINT_MAX`）继续往下减。
**实测**：疯狂刷屏，数字在 `4294967295` 附近。

**正确写法**：
```c
for (unsigned int i = 5; i-- > 0; ) { ... }   /* i 在判断里减 */
/* 或者直接用有符号 int（如果不需要 unsigned 的大范围） */
```

### 陷阱 4：函数漏 `return`

```c
int f(int x) { if (x > 0) return 1; }   /* x <= 0 时没有返回值 */
```
**后果**：**UB**，返回的是寄存器里的垃圾值。**`-Wall` 会给 `control reaches end of non-void function`。**

---

## 三、嵌入式三条铁律

1. **数组循环用 `i < N`，永远不用 `i <= N`**
2. **倒序循环不要用 `unsigned`**
3. **函数必须 return（除非声明 `void`）**

---

## 四、错误码约定（从这一课开始见）

```c
int do_something(void)
{
    if (失败) return -1;    /* 负数 = 错误码 */
    return 0;               /* 0 = 成功 */
}
```

**Linux 内核风格**：`0` 永远是成功，负数是错误（`-EINVAL` 参数错、`-ENOMEM` 内存不足…）。
你现在 `main` 里的 `return 0;` 就是同一套约定。
