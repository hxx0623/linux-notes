## 一、`argc` / `argv`（实测）

```
$ ./args
argc = 1                  ← 最少是 1（argv[0] 是程序名）
argv[argc] = (nil)        ← 标准保证是 NULL
argv[0] = "./args"

$ ./args hello world 123
argc = 4
argv[0] = "./args"
argv[1] = "hello"
argv[2] = "world"
argv[3] = "123"
```

### ⭐ `(nil)` 和 `argv[argc] == NULL` 的意义

`(nil)` 是 glibc 打印 NULL 指针的方式。

**标准保证 `argv[argc] == NULL`**，所以可以不用 `argc` 遍历：

```c
for (char **p = argv; *p != NULL; p++) printf("%s\n", *p);
```

> 这是 C 的经典手法：**用 NULL 做结束标记**。
> 字符串用 `'\0'` 收尾、指针数组用 `NULL` 收尾 —— 同一个思路。
> Linux 源码里大量 `while (*p)`、`for (; *s; s++)` 全靠这个约定。

## 二、错误处理（`perror` 实测）

```bash
$ mv a.txt a.txt.bak
$ ./r1
a.txt: No such file or directory     ← perror("a.txt") 的输出
```

**`perror(前缀)`** 把全局 `errno` 翻译成人话，前面加上你给的前缀。

**为什么必须做**：`fopen` 失败不检查 → 后面 `fprintf(NULL, ...)` → **段错误**。
**检查 + `perror` = 优雅地报错，而不是崩溃。**

## 三、⚠️ 从 `r1.c` 到 `mycat`：踩的坑

**做法**：把 `r1.c` 改成"文件名从命令行来"。**复用是对的**，但——

### 坑：抄完没删干净

`r1.c` 里有一行统计输出：

```c
printf("\n共 %d 行\n", n);
```

**照抄到 `mycat` 里就错了**：

```
$ ./mycat a.txt
第一行
数字: 42
第三行（fputs）

共 3 行              ← ⚠️ cat 不会打印这个！

$ cat a.txt
第一行
数字: 42
第三行（fputs）
```

### 🔑 设计原则：**工具的语义要"纯粹"**

| 工具 | 契约（只做这一件事） |
| --- | --- |
| `cat` | **原样输出文件内容**，一个字节都不多不少 |
| `wc -l` | 只输出行数 |
| `grep` | 只输出匹配的行 |

**`mycat` 输出了额外的"共 3 行" → 它就不再是 `cat` 了**，而是 `cat`+`wc` 的混合体。
**Unix 哲学：一个工具只做一件事，做好** —— 组合用管道（`cat a.txt | wc -l`），而不是让工具自己越界。

**推广**：**抄代码时要问"这部分属于我现在做的工具吗？"** 不属于就删掉。

## 四、正确版 `mycat`

```c
#include <stdio.h>

int main(int argc, char *argv[])
{
    /* ① 参数检查 —— 用法提示走 stderr，并用 argv[0] 显示真实程序名 */
    if (argc != 2) {
        fprintf(stderr, "用法: %s <文件>\n", argv[0]);
        return 1;
    }

    /* ② 打开 + 检查 */
    FILE *fp = fopen(argv[1], "r");
    if (fp == NULL) {
        perror(argv[1]);
        return 1;
    }

    /* ③ 逐行读 + 原样输出（不计数、不加修饰） */
    char buf[256];
    while (fgets(buf, sizeof(buf), fp) != NULL) {
        printf("%s", buf);          /* buf 已含 '\n'，不要再加 */
    }

    /* ④ 关闭 */
    fclose(fp);
    return 0;
}
```

### 两个细节为什么这样写

| 细节 | 为什么 |
| --- | --- |
| **用法提示用 `fprintf(stderr, ...)`** | 如果用户 `./mycat > out.txt`，用法提示**不该写进 out.txt**。错误走 stderr、结果走 stdout |
| **用 `argv[0]` 而不是写死 `"mycat"`** | 程序改名后提示自动跟着变，且能显示调用路径 |

## 五、测试清单（一个工具写完必须跑这四条）

```bash
./mycat a.txt            # ① 正常：和 cat 输出完全一致
./mycat r1.c             # ② 拿源码测（多行、含空行）
./mycat 不存在.txt       # ③ 文件不存在 → perror 报错，不崩溃
./mycat                  # ④ 不给参数 → 打印用法，不崩溃
```

**③④ 是最要紧的**：**程序出问题时"不崩溃、能报错"，才是成熟程序。**

## 六、五条铁律（本课总结）

1. **`argc` 最少是 1**，`argv[0]` 是程序名，`argv` 里全是字符串
2. **`fopen` 后必须检查 `NULL`** + `perror`
3. **`fclose` 必须调用**（缓冲数据要刷盘）
4. **错误走 `stderr`，正常结果走 `stdout`**
5. ⭐ **工具的语义要纯粹** —— 抄代码时删掉"不属于这个工具"的部分
