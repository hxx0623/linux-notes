# C 语言 第 2 课：变量、数据类型、sizeof、printf

> 2026-11-16。核心认知：**类型宽度是"硬件约定"，不是抽象概念。**

---

## 一、实测的类型宽度（64 位 Linux）

| 类型 | 字节 | 说明 |
| --- | --- | --- |
| `char` | 1 | 本质是小整数（`'A'` = 65） |
| `short` | 2 | |
| `int` | 4 | 最常见，但**平台相关** |
| `long` | ⚠️ **8**（Linux）/ **4**（Windows 64 位） | **这就是必须用定宽类型的原因** |
| `long long` | 8 | |
| `float` | 4 | 结尾加 `f`：`3.14f` |
| `double` | 8 | 默认浮点类型 |
| `unsigned int` | 4 | |

### ⭐ 为什么嵌入式一律用 `stdint.h` 的定宽类型

| | `int` | `uint32_t` |
| --- | --- | --- |
| 宽度 | **随平台变**（2/4/8 都可能） | **永远 4 字节** |
| 后果 | 同一份代码在不同板子上行为不同 | 代码可移植且**位级精确** |
| 用于 | 普通计数值 | **寄存器、协议字段、内存布局、位操作** |

**准确表述**：不是为了"适配平台"，而是**"锁定宽度，让位级操作在任何平台都一样"**。

`uint8_t`=1、`int8_t`=1、`uint16_t`=2、`int16_t`=2、`uint32_t`=4、`int32_t`=4（实测）

`stdint.h` 还给了极值宏：`UINT8_MAX`(255)、`INT8_MIN`(-128)、`UINT32_MAX` 等 —— **比手写数字更安全**。

## 二、⭐ 溢出的两种命运（极重要）

### 无符号溢出 = **良定义**（标准保证）

```c
unsigned char uc = 255;
uc = uc + 1;        /* 实测 → 0 */
```
**规则**：无符号运算按模 2^n 回绕。**这是标准明确规定的行为**，可以依赖。

### 有符号溢出 = **未定义行为（UB）**

```c
int i = 2147483647;
i = i + 1;          /* 实测 → -2147483648 */
```
**但在 C 标准里这是 UB**。GCC 用补码给出了 `-2147483648`，**但标准不保证**；开优化时编译器可能假设"有符号不会溢出"，从而**删掉整段判断** —— **这是大量安全漏洞的源头**。

> 📌 **写代码原则**：无符号溢出可以算；**有符号溢出必须自己防**（先判断再运算）。

## 三、⭐ `printf` 格式化符必须和参数类型匹配

| 格式符 | 期望类型 |
| --- | --- |
| `%d` | `int` |
| `%u` | `unsigned int` |
| `%ld` / `%lu` | `long` / `unsigned long` |
| `%lld` / `%llu` | `long long` / `unsigned long long` |
| `%c` | 字符（`char`） |
| `%s` | `char *`（字符串） |
| `%f` | `double` / `float` |
| `%zu` | `size_t`（`sizeof` 的返回类型） |
| `%x` | 十六进制（`int`） |
| `%p` | 指针地址 |

### 实测：`printf("%d", 2.71828)` → 输出 **`-1259769184`**（垃圾）

**原因不是"截断"，是"读错了地方"**：

```
x86-64 传参规则：
   double  → 浮点寄存器 XMM0
   int     → 通用寄存器（RSI 等）

printf 看到 %d → 去通用寄存器取 int
        ↓
但你的 double 在 XMM0 里
        ↓
通用寄存器里是【别人的残留值】→ 打印出垃圾
```

⭐ **最危险的地方**：**它不崩溃、不报错，只是静默输出垃圾。** 而 `%s` 传整数则会直接段错误（把整数当地址去读）。

**所以：`-Wall -Wextra` 必加，格式化符对应关系必须自己记住。**

## 四、另一个坑：未初始化变量

```c
uint16_t c;              /* 没赋值 */
printf("%u\n", c);       /* → 垃圾值（UB） */
```

**局部变量不初始化时值是"不确定的"**（不是 0！）。GCC 的 `-Wall` 对"声明了但没用"不会警告 —— **靠自觉：声明时就初始化**。

---

## 五、本课记住的 5 条

1. `long` 在 Linux 64 位是 **8 字节**，Windows 64 位是 **4 字节** → 必须用 `stdint.h`
2. `char` 是小整数（`'A'` = 65）
3. **无符号溢出良定义**（回绕），**有符号溢出是 UB**
4. `printf` 格式符不匹配 → **静默输出垃圾**（最危险）
5. `sizeof` 在**编译期**求值；`size_t` 用 `%zu`
