# C 语言 第 4 课：数组与字符串

> 2026-11-16。核心认知：**字符串不是一种类型，是"以 `\0` 结尾的 char 数组"。**

---

## 一、数组基础（实测）

```c
int a[5] = {10,20,30,40,50};
sizeof(a)      = 20      /* 整组字节 */
sizeof(a[0])   = 4       /* 单元素 */
元素个数        = 20/4 = 5

int b[5] = {1, 2};       /* 部分初始化 → 剩下的【补 0】 */
b = {1, 2, 0, 0, 0}
```

> ⚠️ **注意特例**：局部数组**部分初始化时会补 0**；但**完全不初始化**（`int c[5];`）时是**垃圾值**。

## 二、⭐ 字符串的本质

```c
char s1[] = "hello";     /* 数组：6 字节（5 字符 + '\0'），内容可改 */
char *s2   = "hello";    /* 指针：指向【只读段】，改了就段错误 */
```

逐字节（实测）：

| i | 0 | 1 | 2 | 3 | 4 | **5** |
| --- | --- | --- | --- | --- | --- | --- |
| 字符 | h | e | l | l | o | **`\0`** |
| ASCII | 104 | 101 | 108 | 108 | 111 | **0** |

```c
sizeof(s1) = 6    /* 含 '\0' */
strlen(s1) = 5    /* 到 '\0' 之前 */
```

**所有字符串函数（`strlen`、`printf("%s")`、`strcpy`）都靠找 `\0` 判断结尾。** 没有它 → 一路读到越界。

## 三、⛔ 四个真实 bug（全部实测）

### bug 1：数组作参数会"退化"成指针

```c
void show(int arr[]) { printf("%zu\n", sizeof(arr)); }   /* → 8，不是 20！ */
int main(void) { int a[5]; show(a); }                    /* main 里是 20 */
```
**原因**：数组名传参时退化成指针（8 字节）。
**结论**：**数组作函数参数，必须额外传一个长度参数。** 这是 C 的硬规则。

### bug 2：字符串漏 `\0` → ASan 抓 `[32, 37)` 越界

```c
char s[5] = {'h','e','l','l','o'};   /* 5 字节，没有 '\0' */
printf("%s\n", s);
```
ASan 实测：
```
This frame has 1 object(s):
    [32, 37) 's' (line 5) <== Memory access at offset 37 overflows this variable
Shadow: =>f1 f1 f1 f1 f1[05]f3 f3 f3     ← 05 = 5 字节可用
```
⭐ **关键对比**：
- **加 ASan** → 直接崩溃报警
- **不加 ASan** → **照样打印出 `hello`（看起来完全正常！）**

**这就是 UB 的本质：不崩溃、看起来对，但你已经在读别人的内存。**

### bug 3：⭐ `strcpy` 溢出 → **两道防线都抓到了**

```c
char dst[5];
strcpy(dst, "hello world");      /* 12 字节塞进 5 字节 */
```

**防线 ①（编译期，`-Wall` 静态检查）**：
```
dst.c:7:5: warning: '__builtin_memcpy' writing 12 bytes into a region of size 5
           overflows the destination [-Wstringop-overflow=]
dst.c:6:10: note: destination object 'dst' of size 5
```

**防线 ②（运行期，Stack Protector）**：
```
dst = hello world
*** stack smashing detected ***: terminated
已中止（核心已转储）
```

⭐ **`stack smashing detected` 是 GCC 的 `-fstack-protector`（Ubuntu 默认开启）在起作用**：
编译器在每个函数的栈帧里放一个"金丝雀值（canary）"，函数返回前检查它有没有被改；
被改 → **立刻 abort**，而不是带着被破坏的栈返回。

> 📌 **所以"越界写"往往能被抓住（编译器 + canary），"越界读"只能靠 ASan 或你自己。**

### bug 4：改字符串常量 → 段错误

```c
char *s2 = "hello";
s2[0] = 'H';         /* 段错误（核心已转储） */
```
**原因**：字符串常量放在**只读段（`.rodata`）**，运行时改它 → 内核拒绝 → SIGSEGV。

## 四、⭐ 一个自己写 `to_upper` 时踩的坑

```c
void to_upper(char s[])
{
    for (int x = 0; x != '\0'; x++)     /* ⚠️ 错：条件应该是 s[x] != '\0' */
    {
        s[x] -= 32;
    }
}
```

**两个错误叠在一起**：

| # | 错误 | 后果 |
| --- | --- | --- |
| 1 | `x != '\0'` 写成了"索引 x 不等于 0" | `x` 初值 0 → `0 != 0` 假 → **循环一次都不跑**，函数什么都没干 |
| 2 | `s[x] -= 32` 无脑减 32 | 即使修好上一条，**非小写字母也会被破坏**：空格(32)−32 = **0 = `\0`** → **字符串被提前截断**！`,`(44)−32=12、`C`(67)−32=35='#' |

**正确写法**：

```c
void to_upper(char s[])
{
    for (int i = 0; s[i] != '\0'; i++) {
        if (s[i] >= 'a' && s[i] <= 'z') {   /* ⭐ 只处理小写字母 */
            s[i] -= 32;
        }
    }
}
```

## 五、安全字符串函数（必须记住）

```c
/* ❌ 永远不要用 */
strcpy(dst, src);            /* 不检查目标大小 */
strcat(dst, src);            /* 同上 */

/* ✅ 用这个（自动截断 + 补 '\0'） */
snprintf(dst, sizeof(dst), "%s", src);

/* ✅ 或者（注意 strncpy 自己【不保证】补 '\0'） */
strncpy(dst, src, sizeof(dst) - 1);
dst[sizeof(dst) - 1] = '\0';
```

---

## 六、本课记住的 5 条

1. **字符串 = char 数组 + 结尾的 `\0`**（`sizeof` 比 `strlen` 多 1）
2. **数组作参数退化成指针** → 必须额外传长度
3. **`strcpy` 禁用**，用 `snprintf`
4. **越界写会被 canary 抓住**（`stack smashing detected`），**越界读不会** → 靠 ASan
5. **改字符串常量 → 段错误**（在只读段）
