## 一、【课件】13.1 网络配置原理图

### 本机真实拓扑（10-29 实测）

```
Ubuntu 虚拟机  ens160   192.168.139.100（已改静态）
        ↓ 默认路由 default via 192.168.139.2
NAT 网关（VMware 内部）  192.168.139.2   ← 在这里做地址转换
        ↓
宿主机 真实网卡 WLAN     192.168.28.99
        ↓
家用路由器（局域网网关）  192.168.28.1
        ↓
      互联网
```

| 角色 | 值 | 在哪查 |
| --- | --- | --- |
| 虚拟机网卡 | `ens160` / `192.168.139.100` | `ip a`、`hostname -I` |
| NAT 网关 | `192.168.139.2` | `ip route` |
| 宿主机 VMnet8（NAT） | `192.168.139.1` | `ipconfig` |
| 宿主机 VMnet1（**仅主机**） | `192.168.160.1` | `ipconfig`（未使用，空转） |
| 宿主机真实网卡 | WLAN `192.168.28.99` | `ipconfig` |
| 家用路由器 | `192.168.28.1` | `ipconfig` 的默认网关 |

> **课件图比我讲的多/少一站**：课件把「虚拟交换机 + NAT 转换」合并成一个 `vmnet8` 框，
> 我的版本把 `192.168.139.2`（NAT 网关）单独拆出来。两者是同一条路，粒度不同。
> 证据：`ip route` 显示 `default via 192.168.139.2` —— 虚拟机的下一跳确实是 `.2`。

### 同一网段的判断

掩码 `255.255.255.0` → **前三段相同才是同一网段**。
`192.168.139.129` 与 `192.168.140.129` **不在**同一网段。

### ⚠️ 网段 vs 主机地址（易混）

| 写法 | 含义 |
| --- | --- |
| `192.168.28.0/24` | **一整个网段**（地址范围），不能作为“目的地” |
| `192.168.28.1` | 网段中的**一台机器**（路由器） |
| `192.168.28.255` | 广播地址 |

## 三、【课件】13.4 `ifconfig` 与 `ip a`

`ifconfig` 输出逐段：

| 段 | 含义 |
| --- | --- |
| `flags=<UP,BROADCAST,RUNNING,MULTICAST>` | 状态标志（`UP` 启用、`RUNNING` 链路就绪） |
| `mtu 1500` | 最大传输单元 |
| `inet 192.168.139.100 netmask 255.255.255.0 broadcast ...` | IPv4 / 掩码 / 广播 |
| `inet6 fe80::...` | IPv6 链路本地（无视） |
| `ether 00:0c:29:59:f8:ae` | MAC 地址 |
| `RX packets / TX packets` | 收 / 发统计（RX 远少于 TX = 发出去了没人回） |

### 新老命令对照（Ubuntu 默认不装 net-tools）

| 老（net-tools） | 新（iproute2） |
| --- | --- |
| `ifconfig` | `ip a` |
| `ifconfig ens160` | `ip a show ens160` |
| `ifconfig ens160 up` | `ip link set ens160 up` |
| `route -n` / `netstat -rn` | `ip route` |
| `arp -a` | `ip neigh` |
| — | `ip -s link show ens160`（收发包统计） |

## 四、【课件】13.5 `ping`

| | Windows | Ubuntu |
| --- | --- | --- |
| 默认次数 | 4 次自动停 | **一直 ping，`Ctrl+C` 停** |

常用参数：`-c 4`（次数）、`-i`（间隔）、`-s`（包大小）、`-W`（超时）、`-I ens160`（指定网卡）

### 🔑 网络排障黄金四步

```bash
ping -c 2 127.0.0.1        # ① 本机协议栈
ping -c 2 192.168.139.2    # ② 到网关（局域网）
ping -c 2 8.8.8.8          # ③ 到外网（绕过 DNS）
ping -c 2 www.baidu.com    # ④ 域名解析（只测 DNS）
```

| ① | ② | ③ | ④ | 问题在哪 |
| --- | --- | --- | --- | --- |
| ❌ | | | | 本机 TCP/IP 栈 |
| ✅ | ❌ | | | IP/掩码/网关配错 |
| ✅ | ✅ | ❌ | | 网关之后断了（宿主机网络 / VMware NAT 服务） |
| ✅ | ✅ | ✅ | ❌ | **DNS 问题** |

`ping` 输出细节：`time=xx ms` 延迟；`ttl` 每过一跳减 1；百度会显示真实别名 `www.a.shifen.com`（CNAME）。

## 五、【课件】13.6 网络环境配置（本机最重要的一集）

### 课件两种方法

| 方法 | 说明 |
| --- | --- |
| 自动获取（DHCP） | 简单，但**每次 IP 可能变** |
| **指定静态 IP**（课件推荐） | 改配置文件，IP 固定 |

课件做法：`vi /etc/sysconfig/network-scripts/ifcfg-ens33`
字段：`DEVICE` `HWADDR` `TYPE` `UUID` `ONBOOT` `BOOTPROTO` `IPADDR` `GATEWAY` `DNS1`，生效用 `service network restart`。

### ⚠️ Ubuntu 完全没有这条路

**`/etc/sysconfig/` 不存在**（那是 RedHat 系）。Ubuntu 用 **netplan**：

| 课件 | Ubuntu（netplan YAML） |
| --- | --- |
| `ifcfg-ens33` | `/etc/netplan/*.yaml` |
| `DEVICE=ens33` | `ethernets:` 下写 **`ens160:`** |
| `BOOTPROTO=static` / `dhcp` | `dhcp4: false` / `true` |
| `IPADDR=x.x.x.x` | `addresses: [x.x.x.x/24]` |
| `GATEWAY=x.x.x.x` | `routes: - to: default` + `via: x.x.x.x` |
| `DNS1=` | `nameservers: addresses: [...]` |
| `service network restart` | `sudo netplan apply` |

### 本机适用做法：GUI（NetworkManager）

桌面版 `renderer: NetworkManager`，**网络由 NetworkManager 管**，所以直接：

```
右上角网络图标 → 设置 → 网络 → 有线 (ens160) → ⚙ → IPv4 → 方法：手动
地址 192.168.139.100 / 255.255.255.0，网关 192.168.139.2，DNS 192.168.139.2, 223.5.5.5
```

### 实测结果（10-29）

| 检查点 | 改之前（DHCP） | 改之后（静态） |
| --- | --- | --- |
| `ip a` | `scope global **dynamic** noprefixroute` | `scope global noprefixroute` |
| `ip route` | `proto **dhcp**` | `proto **static**` |
| IP | `192.168.139.129` | **`192.168.139.100`** |

**判断静态成功的两个标志：`dynamic` 消失 + `proto static`。**

### 🚨 改网络前的保命四条

| # | 措施 |
| --- | --- |
| 1 | 先拍快照 |
| 2 | **用 VMware 控制台操作，别用 SSH**（否则自己把自己踢下线） |
| 3 | 抄下原 IP 和网关 |
| 4 | 走 netplan 时先 `sudo netplan try`（**60 秒不确认自动回滚**） |

**静态 IP 要选 DHCP 池外的地址**（VMware 池一般 `.128`–`.254`，所以选 `.100`）。

### ⚠️ 本机遗留隐患：netplan 与 NetworkManager 不一致

```
/etc/netplan/50-cloud-init.yaml  →  dhcp4: true   （600 root，没改）
实际生效                          →  静态 IP（NetworkManager 里的配置）
```

**这意味着：在这台机器上执行 `sudo netplan apply` 有可能把静态 IP 打回 DHCP。**
→ 要改网络就统一走 GUI；想改回 DHCP 也在 GUI 里改。

## 六、【课件】13.7 主机名与 hosts

| 操作 | 课件（CentOS） | Ubuntu |
| --- | --- | --- |
| 查看 | `hostname` | `hostname` / `hostnamectl` |
| 修改 | 改 `/etc/hostname` + **重启** | **`sudo hostnamectl set-hostname 名字`**，立即生效 |

**提示符不会立刻变** —— 退出重开终端。

### ⚠️ Ubuntu 独有的 `127.0.1.1` 行

```
127.0.1.1   cxh-VMware20-1
```

作用是**让主机名能在本地解析**，否则每次解析自己的名字都要去问 DNS，问不到就卡几秒（旧版 `sudo` 卡顿的根源）。
**手动改 `/etc/hostname` 时必须同步改这一行**（用 `hostnamectl` 会自动改）。

### hosts 文件

| 系统 | 位置 |
| --- | --- |
| Linux | `/etc/hosts` |
| Windows | `C:\Windows\System32\drivers\etc\hosts` |

**格式**：`IP地址  主机名  [别名...]  # 注释`，一行一条。

## 七、【课件】13.8 主机名解析过程

课件四步（**由近到远**）：

```
① 浏览器自己的缓存        有 → 用
② 操作系统 DNS 解析器缓存  有 → 用
③ /etc/hosts              有 → 用
④ 问 DNS 服务器（分布式查询）
```

Windows 下的查/清缓存：`ipconfig /displaydns`、`ipconfig /flushdns`

### 【Ubuntu】顺序由 `/etc/nsswitch.conf` 决定

```bash
grep hosts /etc/nsswitch.conf
# hosts: files mdns4_minimal [NOTFOUND=return] dns
#        ↑files（/etc/hosts）排在 ↑dns 前面 → hosts 优先
```

```bash
resolvectl query www.baidu.com    # 看解析结果
sudo resolvectl flush-caches      # 清 DNS 缓存（改 hosts 不生效时用）
```

### 实测实验（证明 hosts 优先于 DNS）

```bash
sudo sh -c 'echo "127.0.0.1   www.baidu.com" >> /etc/hosts'
sudo resolvectl flush-caches
ping -c 2 www.baidu.com        # → 变成 127.0.0.1，DNS 完全没被问
sudo vim /etc/hosts            # 删掉那行恢复
```

## 八、今日踩的坑（10-29）

1. **`ls -l: 未找到命令`** —— 命令里夹了**全角空格**（U+3000），bash 只认半角空格，整串被当成一个命令名。
   → 切英文输入法重打；自检 `echo "ls -l" | od -c`（半角是 `040`，全角是 `342 200 200`）。
2. **`cp 多个文件 目标` 报“没有那个文件或目录”** —— 多个源文件时**目标是目录**，不能是新文件名。
   → `sudo cp -r /etc/netplan ~/netplan-bak-$(date +%F)` 或一个一个拷。
3. **`cat /etc/netplan/50-cloud-init.yaml` 权限不够** —— 该文件是 `600 root`，必须 `sudo cat`。
4. **`ens33` 不存在，实际是 `ens160`** —— 网卡名按 PCI 位置生成，**课件里所有 `ens33` 都要换成 `ens160`**。
5. **GUI 改了静态 IP，netplan 文件仍是 `dhcp4: true`** —— 两套配置并存，别在这台机器上跑 `netplan apply`。
6. **Ubuntu 24.04 没有 `/var/log/syslog`**（10-28 记）—— 日志统一进 `journalctl`。

## 九、第 13 章三条铁律

**① hosts 优先于 DNS** —— 本地小抄赢过打客服电话。

**② 排障由近到远** —— `127.0.0.1` → 网关 → `8.8.8.8` → 域名，哪一步断就是哪一层的问题。

**③ Ubuntu 没有 `/etc/sysconfig/`** —— 网络配置走 **netplan + NetworkManager**；桌面版 GUI 最稳。

## 十、自测题

1. 浏览输入 `www.baidu.com`，解析按什么顺序进行？
2. `ping 8.8.8.8` 通、`ping www.baidu.com` 不通，问题在哪一层？
3. 课件的 `/etc/sysconfig/network-scripts/ifcfg-ens33` 在 Ubuntu 上对应什么文件？
4. 判断“静态 IP 已经生效”，看哪两个标志？
5. Ubuntu 的 `/etc/hosts` 里 `127.0.1.1` 那行是干什么的？删了会怎样？
6. 改网络前为什么“不能用 SSH 操作”？

<details>
<summary>答案</summary>

1. 浏览器缓存 → 操作系统 DNS 缓存 → `/etc/hosts` → DNS 服务器
2. **DNS 解析**（能到 IP，说明网络通；域名解析不出来）
3. `/etc/netplan/*.yaml`（本机是 `50-cloud-init.yaml`），生效命令 `sudo netplan apply`
4. `ip a` 里没有 `dynamic`；`ip route` 里是 `proto static`
5. 让本机主机名能在本地解析；删了会去问 DNS，问不到就卡几秒（`sudo` 变慢）
6. 改网络会断开连接，用 SSH 等于砍断自己坐的树枝；要用 VMware 控制台
