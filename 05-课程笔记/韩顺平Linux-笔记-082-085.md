## 一、【课件】15.1.1 `rpm` 是什么

> `rpm` 用于互联网下载包的打包及安装工具，生成 **`.RPM`** 扩展名的文件。
> **RPM = RedHat Package Manager**，类似 Windows 的 `setup.exe`。
> Linux 各发行版（suse、redhat、centos…）都有采用，**可算是公认的行业标准**。

| 系统 | 包格式 | 工具 |
| --- | --- | --- |
| Windows | `.exe` / `.msi` | 安装向导 |
| CentOS / RHEL | **`.rpm`** | `rpm`（底层）/ `yum`（高层） |
| **Ubuntu** | **`.deb`** | **`dpkg`（底层）/ `apt`（高层）** |

## 三、【课件】15.1.3 包名格式（能读出很多信息）

```
firefox-60.2.2-1.el7.centos.x86_64
   ↑        ↑          ↑       ↑
 名称    版本号    适用操作系统  架构
```

| 架构 | 含义 |
| --- | --- |
| `x86_64` | 64 位 |
| `i686` / `i386` | **32 位** |
| **`noarch`** | **通用**，不依赖 CPU 架构（字体、Java 库、纯脚本） |

**`el7` = RHEL/CentOS 7 专用 → 拿到 Ubuntu 上装不了。**

Ubuntu 的 deb 是同一个结构：`<包名>_<版本>_<架构>.deb`，比如 `hello_2.10-3build1_amd64.deb`。

## 四、【课件】15.1.4 五个查询指令

| 命令 | 作用 |
| --- | --- |
| `rpm -qa` | 所有已安装的包（配 `\| more` / `\| grep`） |
| `rpm -q 包名` | 某个包**装了没** |
| `rpm -qi 包名` | 包的**详细信息**（版本、厂商、日期） |
| `rpm -ql 包名` | 这个包**装了哪些文件** |
| **`rpm -qf 文件全路径`** | **这个文件属于哪个包** ⭐ 最实用 |

```bash
rpm -qf /etc/passwd
rpm -qf /usr/bin/ssh
```

## 五、【课件】15.1.5 卸载 `rpm -e`

```bash
rpm -e 包名            # erase
```

### ⚠️ 卸载用「包名」，安装用「文件名」

| 动作 | 用什么 | 例子 |
| --- | --- | --- |
| **卸载** | **包名**（无版本、无后缀） | `rpm -e firefox` |
| **安装** | **文件名 + 全路径** | `rpm -ivh /tmp/firefox-60.2.2-1.el7.centos.x86_64.rpm` |

卸载时带版本号 → `error: package ... is not installed`

### 依赖错误与 `--nodeps`

```
$ rpm -e foo
error: Failed dependencies:
        foo is needed by bar-1.0-1
```

强行删：

```bash
rpm -e --nodeps foo
```

> 课件：**“一般不推荐这样做，因为依赖于该软件包的程序可能无法运行。”**

**真正的原因**：`--nodeps` 跳过检查 → **删除会成功**，但依赖它的程序**之后运行时才崩**（找不到库）。**错误被推迟到未来。**

## 七、【课件】15.2 `yum`

> **Yum 是一个 Shell 前端软件包管理器。基于 RPM 包管理**，能从指定服务器自动下载 RPM 包并安装，**可以自动处理依赖性关系，并且一次安装所有依赖的软件包**。

### 三个关键词

| 关键词 | 含义 |
| --- | --- |
| **Shell 前端** | 它是 rpm 的**上层包装**（底层还是调 rpm） |
| 基于 RPM | 装的还是 `.rpm` |
| **自动处理依赖** | ⭐ 存在理由 |

### 指令

```bash
yum list | grep xx      # 仓库里有没有
yum install xxx         # 下载并安装（带依赖）
```

### ⚠️ 前端/后端关系（易错）

```
yum    ← 前端（你敲的，负责找包/算依赖/下载）
 ↓ 调用
rpm    ← 后端（负责真正装进系统）
```

**判断方法：你直接敲的那个就是前端。**

## 八、🔑 Ubuntu 完整对照表（本章核心产出）

| 想干什么 | CentOS 高层 | **Ubuntu 高层** | CentOS 底层 | **Ubuntu 底层** |
| --- | --- | --- | --- | --- |
| 装 | `yum install` | **`apt install`** | `rpm -ivh` | **`dpkg -i`** |
| 删 | `yum remove` | `apt remove` / `purge` | `rpm -e` | `dpkg -r` / `-P` |
| 列出已装 | `yum list` | `apt list --installed` | `rpm -qa` | **`dpkg -l`** |
| 包信息 | `yum info` | `apt show` | `rpm -qi` | `dpkg -s` |
| 包内文件 | — | — | `rpm -ql` | **`dpkg -L`** |
| **文件属哪个包** | — | — | `rpm -qf` | **`dpkg -S`** |
| 搜索 | `yum search` | `apt search` | — | — |
| **更新索引** | `yum makecache` | **`apt update`** | — | — |
| 升级 | `yum update` | **`apt upgrade`** | — | — |
| 修依赖 | — | **`apt install -f`** ⭐ | — | — |

```
dpkg ←→ rpm     （底层：只管单个包文件，不管依赖）
apt  ←→ yum     （高层：连仓库，自动解决依赖）
```

## 九、`apt` 的四层结构（比课件更值得理解）

```
① 源（仓库）   /etc/apt/sources.list.d/ubuntu.sources   ← 软件从哪来
        ↓ apt update
② 索引         /var/lib/apt/lists/                       ← 有哪些包、什么版本
        ↓ apt install
③ 包缓存       /var/cache/apt/archives/                  ← 下载的 .deb
        ↓ dpkg -i
④ 已安装       /var/lib/dpkg/status                      ← 装了什么
```

| 报错 | 卡在哪层 | 解决 |
| --- | --- | --- |
| `E: 无法定位软件包` | ②索引里没有 | `apt update`；还不行就是源里真没这个包 |
| `E: 无法获得锁 /var/lib/dpkg/lock-frontend` | 有别的 apt 在跑 | `ps aux \| grep apt` |
| `E: 无法下载` / 解析失败 | **网络** | 查网络，不是 apt 的错（今天遇到了） |
| `dpkg: dependency problems` | ④装了一半 | `apt install -f` |

## 十、Ubuntu 的第三套体系：snap

| 体系 | 命令 | 包在哪 | 例子 |
| --- | --- | --- | --- |
| **deb** | `apt` / `dpkg` | `/var/lib/dpkg` | `curl`、`vim` |

| flatpak | 未装 | — | — |

**所以 `dpkg -l | grep firefox` 什么都没有，但火狐能正常用** —— 它是 snap 装的。

## 十一、实操：`hello.deb` 完整走一遍

```bash
cd /tmp
apt download hello                 # 只下载，不装
sudo dpkg -i hello_*.deb           # 手动安装（不管依赖）
hello                              # 运行
dpkg -l hello                      # 装了没
dpkg -L hello                      # 装了哪些文件
dpkg -S /usr/bin/hello             # 文件属于哪个包（对应 rpm -qf）
sudo dpkg -r hello                 # 卸载
rm -f /tmp/hello_*.deb
```

**这条链路把 082–084 三集的命令在 Ubuntu 上全部演练了一遍。**

## 十二、🔴 当天的大故障：虚拟机突然断网

**症状**：`apt download` 报

```
E: 无法下载 ... 暂时不能解析域名"mirrors.tuna.tsinghua.edu.cn"
```

**排查过程（用了 064 集的方法，但病根在宿主机）**：

| 层次 | 检查 | 结果 |
| --- | --- | --- |
| 虚拟机内 | 静态 IP / 网关 / DNS 配置 | **完全正常（一个字节都没错）** |
| 宿主机 | `ipconfig` → VMnet8 | **`169.254.36.82`（APIPA，拿不到 IP）** |
| 宿主机 | `netsh interface ipv4 show config` | **`DHCP enabled: Yes`**（本该是固定 `192.168.139.1`） |
| 宿主机 | `Get-Service *vmware*` | **`VMware NAT Service` = Stopped** |
| 宿主机 | 事件日志 | **`2026/10/31 19:50:39 服务 VMware Authorization Service 意外停止`** |

**修复两步：**

1. 启动 `VMware NAT Service`
2. 把 `VMware Network Adapter VMnet8` 从「自动获取 IP」改回固定 **`192.168.139.1 / 255.255.255.0`（网关留空）**

**修复后的黄金四步结果：**

| 测试 | 结果 |
| --- | --- |
| `ping 192.168.139.2`（NAT 网关） | ✅ 0.26 ms |
| `ping 192.168.139.1`（宿主机） | ❌ 100% 丢包 ← **Windows 防火墙默认禁 ICMP，正常** |
| `ping 8.8.8.8` | ✅ 171 ms |
| `ping mirrors.tuna...` | ✅ 0% 丢包，DNS 恢复 |

**教训（划重点）**：

> **虚拟机里出网络问题，先回头看宿主机。**
> Ubuntu 里的静态 IP / 网关 / DNS 配置全程正确，病根在 Windows 侧的 VMware 服务与虚拟网卡。

**下次 10 秒排查：**


## 十三、自测题

1. `rpm` 和 `dpkg` 属于哪一层？`yum` 和 `apt` 属于哪一层？
2. `rpm -e` 后面跟包名还是文件名？
3. `apt update` 和 `apt upgrade` 有什么区别？
4. Ubuntu 上 `dpkg -i` 装完报依赖错误，怎么修？
5. 你的火狐为什么 `dpkg` 里查不到？
6. 虚拟机突然断网，第一步应该查什么？

<details>
<summary>答案</summary>

1. `rpm`/`dpkg` 是**底层**（只管单个包文件）；`yum`/`apt` 是**高层**（连仓库、自动解决依赖）
2. **包名**（不带版本号、不带 `.rpm`）
3. `apt update` 只更新**索引清单**，不动已装软件；`apt upgrade` 按新索引**下载并安装**新版本
4. `sudo apt install -f`（fix-broken）
5. 它是 **snap** 装的（`snap list | grep firefox`），不在 deb 体系里
6. **先查宿主机**：VMware 服务是否在跑、VMnet8 有没有 `192.168.x.1` 的 IP

</details>
