## 035 集 · find / locate / which（课件 9.6.1–9.6.2）

### 要点

- 【课件】**find：从指定目录向下递归遍历各个子目录**，把满足条件的文件或目录显示出来。
  `find [搜索范围] [选项]`，三个典型维度：

  | 维度 | 命令 |
  | --- | --- |
  | 名字 | `find /home -name hello.txt` |
  | 拥有者 | `find /opt -user nobody` |
  | 大小 | `find / -size +200M`（`+n` 大于、`-n` 小于、`n` 等于；单位 k/M/G） |

- 【课件】**locate：不遍历磁盘，查事先建好的数据库**（记录全系统文件名和路径），所以极快；
  代价是数据库要定期更新，**第一次用之前必须 `updatedb`**。
- 【课件】**which** 查某个命令的可执行文件在哪个目录：`which ls`。

### 常用 find 选项

| 选项 | 作用 |
| --- | --- |
| `-name` / `-iname` | 按名字（后者忽略大小写） |
| `-type f` / `-type d` | 只要文件 / 只要目录 |
| `-user` | 按属主 |
| `-size` | 按大小 |
| `-mtime -1` | 一天内修改过 |
| `-maxdepth 1` | 只查当前层 |
| `-exec ... {} \;` | 对每个结果执行命令 |

### 【Ubuntu】

- `locate` **默认没装**。装 `plocate` 会：初始化数据库、建 `plocate` 组、
  挂上 `plocate-updatedb.timer`（每天自动更新）。
- `find /` 会刷满“权限不够” → 加 `2>/dev/null` 丢掉错误输出。
- `which cd` **没有输出**：`cd` 是 shell 内置命令，磁盘上没有对应程序。用 `type cd` 才看得出。

### 实测记录

```
$ locate hello.txt
/home/hello.txt
$ which cd              ← 空
$ type cd
cd 是 shell 内置
$ sudo updatedb
/var/lib/plocate/: Permission denied    ← 异常，但不影响 locate 使用
```

> `sudo updatedb` 那个 `Permission denied` 与 DAC 权限无关（root 不受限），
> 大概率是 AppArmor 或目录属性；`plocate-updatedb.timer` 每天会自动更新，不影响使用。

### find 与 locate 的分水岭

| | `find` | `locate` |
| --- | --- | --- |
| 数据来源 | 实时遍历磁盘 | 数据库快照 |
| 速度 | 慢 | 毫秒级 |
| 新建文件 | 立刻能搜到 | 要等 `updatedb` |

## 036 集 · grep 与管道 `|`（课件 9.6.3）

### 要点

- 【课件】grep 过滤查找；**管道符 `|` 表示把前一个命令的处理结果，输出传递给后面的命令处理**。
  `grep [选项] 查找内容 源文件`
- 课件案例：在 hello.txt 里找 `yes` 所在行并显示行号，两种写法：

```bash
cat /home/hello.txt | grep "yes"      # 写法 1（用管道）
grep -n "yes" /home/hello.txt         # 写法 2（推荐，少一个进程）
```

### 四个常用选项

| 选项 | 作用 |
| --- | --- |
| `-n` | 显示行号 |
| `-i` | 忽略大小写 |
| `-v` | 反向（找不含该内容的行） |
| `-c` | 只输出匹配行数 |

### `|` 与 `>` 的区别

| 符号 | 去向 |
| --- | --- |
| `>` / `>>` | 写进**文件**（覆盖 / 追加） |
| `\|` | 交给**下一个命令** |

### 实测记录

```
$ ls -l /etc | grep -c "conf"
44
$ history | grep "cd"
```

- `grep` 是**子串匹配**，不是单词匹配（`grep -w` 才是整词）。所以 `history | grep cd` 会把
  `abcd` 之类也捞出来。
- `-c` 数的是**行数**，不是文件个数。

### 【Ubuntu】

`alias grep='grep --color=auto'`，匹配部分自动标红；`grep -r 关键词 目录` 可递归搜目录。

## 037 集 · gzip / zip（课件 9.7.1–9.7.2）

### 要点

- 【课件】**gzip 只能把文件压缩成 `*.gz`**；`gunzip` 解压。
- 【课件】`zip [选项] XXX.zip 要压缩的内容`、`unzip [选项] XXX.zip`；
  `zip -r` 递归压目录、`unzip -d 目录` 指定解压位置。

```bash
zip -r myhome.zip /home/
unzip -d /opt/tmp /home/myhome.zip
```

### gzip 的两个脾气

1. **只能压单个文件**：`gzip ztest` → `gzip: ztest is a directory -- ignored`
2. **默认删掉原文件**：压完只剩 `a.txt.gz`；`gzip -k` 可保留

### 实测记录

```
a.txt      11 字节
a.txt.gz   37 字节        ← 小文件压完反而更大
```

原因：gzip 头部（魔数、方法、原始文件名、时间戳、CRC）就有二十多字节。

```
adding: ztest/b.txt (stored 0%)     ← zip 判断"压了不划算"，原样存储（store）而非 deflate
```

小文件打出的 zip（483 字节）里，真实内容只有 21 字节。

### 解压多一层目录的原因

`unzip -d out ztest.zip` 得到 `out/ztest/...`，因为压缩时把 `ztest/` 这个目录名本身也打进去了。
想解开就是文件，在目录**里面**压：

```bash
cd ztest && zip -r ../ztest2.zip .
```

### 【Ubuntu】

Ubuntu 桌面版**默认不带 zip/unzip**（gzip 一定有）：`which zip unzip` 检查，
缺了 `sudo apt install -y zip unzip`。

## 038 集 · tar（课件 9.7.3，重点）

### 要点

- 【课件】**tar 是打包指令**，最终文件是 `.tar.gz`。
  **tar 本身只打包不压缩，`z` 才调用 gzip。**
- `tar [选项] XXX.tar.gz 打包的内容`

| 参数 | 含义 |
| --- | --- |
| `z` | 用 gzip 压缩 |
| `c` | create 创建包 |
| `x` | extract 解压 |
| `v` | verbose 显示过程 |
| `f` | file，**后面跟文件名，必须放最后** |

**打包 `-zcvf`，解压 `-zxvf`，只差中间那个字母。**

### 课件四案例

```bash
tar -zcvf pc.tar.gz /home/pig.txt /home/cat.txt   # 压多个文件
tar -zcvf myhome.tar.gz /home/                    # 压整个目录
tar -zxvf pc.tar.gz                               # 解压到当前目录
tar -zxvf /home/myhome.tar.gz -C /opt/tmp2        # 解压到指定目录（-C 大写）
```

### 三个实用补充

```bash
tar -tzf t.tar.gz                 # 只看包内容，不解压
tar -tf  t.tar.gz                 # 同上（-t 不需要 z）
tar -zxvf t.tar.gz 路径/某文件      # 只解压其中一个
```

### 绝对路径的坑

`tar -zcvf x.tar.gz /home/` 会把绝对路径存进包，解压时警告
`Removing leading '/' from member names`。**标准做法：cd 到上一级，用相对路径打包。**

### 实测记录

21 字节内容 → `t.tar.gz` 201 字节。列表里 `ztest/` 结尾的斜杠表示目录条目。

## 附录 B · 自测题（6 道）

1. `find / -name "*.conf"` 为什么满屏报错？怎么屏蔽？
2. `locate` 为什么搜不到刚建的文件？怎么解决？
3. `which cd` 为什么没输出？
4. `ls -l /etc | grep -c conf` 里的 `-c` 数的是什么？
5. `gzip ztest/` 报什么错？想压目录用什么？
6. `tar -zcvf` 和 `tar -zxvf` 中间那个字母分别代表什么？
7. 解压 zip 后多出一层目录，是什么原因？怎么避免？

<details>
<summary>答案</summary>

1. 遍历 `/` 会撞上大量 root 独占目录，产生“权限不够”；加 `2>/dev/null`。
2. locate 查的是数据库快照，新文件还没入库；`sudo updatedb` 刷新。
3. `cd` 是 shell 内置命令，不是磁盘上的可执行程序；用 `type cd` 查。
4. 匹配的**行数**（不是文件个数）。
5. `gzip: ztest is a directory -- ignored`；压目录用 `zip -r` 或 `tar -zcvf`。
6. `c` = create（打包），`x` = extract（解压）。
7. 压缩时把目录名本身也打进了包；应 `cd 目录 && zip -r ../x.zip .`

</details>

## 附录 C · 本段踩的坑

| 现象 | 原因 | 解法 |
| --- | --- | --- |
| `apt install locate` 后搜不到 | 装的是过渡包/数据库旧 | 装 `plocate`，`sudo updatedb` |
| `sudo updatedb` → `/var/lib/plocate/: Permission denied` | 非 DAC 问题（root 不受限），疑似 AppArmor | 不影响使用，`plocate-updatedb.timer` 每天自动更新 |
| `gzip ztest` → `is a directory -- ignored` | gzip 只压单文件 | `zip -r` 或 `tar -zcvf` |
| 小文件压完变大（11 → 37 字节） | gzip 头部开销 | 小文件不必压 |
| zip 里 `stored 0%` | 压了不划算，原样存储 | 正常现象 |
| 解压多一层 `ztest/` | 压缩时含了目录名 | 在目录里 `zip -r ../x.zip .` |
