# 二、149：io 读写监控（课件 26.11）

## 2.1 课件原题

> **Linux 查看内存、io 读写、磁盘存储、端口占用、进程查看命令是什么？（瓜子）**

课件答案：`top, iotop, df -lh, netstat -tunlp, ps -aux | grep 关心的进程`

## 2.2 五类资源 ↔ 命令对照（这一集的骨架）

| 要看什么 | 命令 | 关键参数与解释 |
| --- | --- | --- |
| **内存** | `free -h` | `available` 才是真正可用（`free` 那列包含可回收的缓存） |
| **CPU / 整体** | `top` | 看 `%us`（用户态）、`%sy`（内核态）、**`%wa`（等 IO）**、`load average` |
| **io 读写** | `iotop -oPa` | ⚙️ **要装**：`sudo apt install iotop`。`-o` 只显示有 IO 的、`-P` 按进程、`-a` 累计 |
| **io 细分** | `iostat -x 1` | ⚙️ 要装 `sysstat`。看 `%util`（设备忙不忙）、`await`（平均等多久） |
| **磁盘用量** | `df -h` | 按**分区**看用了多少 |
| **目录占用** | `du -sh *` | 按**目录**逐层找谁占的多 |
| **盘和分区结构** | `lsblk -f` | 分区 + 文件系统 + UUID + 挂载点，一次看全 |
| **端口占用** | `ss -tlnp` | `-t`TCP `-l`监听 `-n`不反解 `-p`带进程 ← **Ubuntu 用 `ss`，不用 `netstat`** |
| **进程** | `ps aux \| grep xxx` | 快照；`ps -ef` 是另一种风格（System V） |

## 2.3 三个最容易混的点

| 混点 | 分辨 |
| --- | --- |
| `df` vs `du` | **`df` 看分区总量**（文件系统层），**`du` 看目录加起来多少**（文件层）。`df` 满了但 `du` 对不上 → 查"已删但仍被占用"的文件：`sudo lsof +L1` |
| 内存"少了" | Linux 会把空闲内存拿去做 **cache**，所以 `free` 很小是**正常且健康**的，看 `available` |
| `%wa` 高 | **不是 CPU 忙**，是 CPU 在等磁盘/网络 → 换 `iostat`/`iotop` 找是谁 |

> ⭐ **排障黄金顺序**：`top` 看整体（谁高？）→ 高在 `wa` 就 `iotop`/`iostat` 找进程 → 高在 `us` 就 `ps` 找进程 → 内存问题看 `free` + `ps aux --sort=-%mem`。

# 三、150：统计文件个数和行数（课件 26.12–26.16）

五个小题，都是"面试小题"，答案都能一行搞定。

## 3.1 求第二列的和（美团）

数据：`张三 40 / 李四 50 / 王五 60`

```bash
cat t2.txt | awk -F" " '{sum+=$2} END{print sum}'      # 150
```

| 部分 | 作用 |
| --- | --- |
| `-F" "` | 按空格分列（**同 `cut -d` 的思路**） |
| `{sum+=$2}` | 每读一行，把**第 2 列**累加到 `sum` |
| `END{print sum}` | **所有行读完之后**才输出（这是 `awk` 和 `cut` 的本质区别） |

## 3.2 检查文件是否存在并提示（百度）

```bash
if [ -f 文件名 ]; then
    echo "存在"
else
    echo "不存在"
fi
```

| 测试符 | 判断 |
| --- | --- |
| `[ -f 路径 ]` | 存在**且是普通文件** |
| `[ -d 路径 ]` | 存在且是**目录** |
| `[ -e 路径 ]` | 存在（不管类型） |
| `[ -s 路径 ]` | 存在且**非空** |

> ⚠️ **中括号里必须有空格**：`[ -f x ]` 不是 `[-f x]`。这个坑在 096–104 踩过。

## 3.3 无序数字排序 + 输出总和（百度）

数据：9 8 7 6 5 4 3 2 10

```bash
sort -nr t3.txt | awk '{sum+=$0; print $0} END{print "和="sum}'
```

- `$0` = **整行**（这里每行只有一个数）
- `print $0` 在**每行**都执行一次 → 顺手把排好序的数列打出来
- `END{print "和="sum}` 最后打总和

> 📌 **和 3.1 对比**：3.1 只输出总和；这里**边读边输出 + 最后再输出总和** —— `awk` 的 `{}`（每行）和 `END{}`（收尾）两段结构就这样记住了。

## 3.4 找含 "cat" 的文件名（金山）

```bash
grep -r "cat" /home | cut -d":" -f1
```

- `grep -r` 递归搜
- 输出格式是 `文件路径:匹配的那一行`，所以 `cut -d":" -f1` 取**冒号前的文件名**
- ⚠️ 如果**文件名本身含冒号**会截错；严谨写法：`grep -rl "cat" /home`（`-l` 只输出文件名，一步到位）

## 3.5 统计文件个数与总行数（金山）

```bash
# 文件个数
find /home/test -name "*.*" | wc -l

# 所有文件的总行数
find /home/test -name "*.*" | xargs wc -l
```

| 命令 | 注意 |
| --- | --- |
| `wc -l` 单个文件 | 会多打一行 `总计`；用 `tail -1` 或 `wc -l` 与 `xargs` 配合 |
| ⚠️ **`-name "*.*"` 的毛病** | 它**只匹配带点的文件名**，没有扩展名的文件（如 `README`、`Makefile`）会漏掉。严谨写法：`find /home/test -type f` |
| `xargs` 的坑 | 文件名带空格会被拆坏 → `find … -print0 \| xargs -0 wc -l` |

# 四、151：无人值守备份目录（课件 26.18）

## 4.1 课件原题

> 每天晚上 10 点 30 分，打包站点目录 `/var/spool/mail` 备份到 `/home` 目录下（**每次备份按时间生成不同的备份包，比如按照年月日时分秒**）（滴滴）

## 4.2 答案

**备份命令**：

```bash
tar -zcf /home/mail-$(date +%Y%m%d%H%M%S).tar.gz /var/spool/mail
```

**写进 crontab**（`crontab -e`）：

```cron
30 22 * * * /bin/tar -zcf /home/mail-$(date +\%Y\%m\%d\%H\%M\%S).tar.gz /var/spool/mail
```

## 4.3 两个必须知道的细节

**① 时间格式串**

| 格式 | 值 | 说明 |
| --- | --- | --- |
| `%Y` | 2026 | **四位年**（`%y` 是两位，第 34 集踩过） |
| `%m` `%d` `%H` `%M` `%S` | 月日时分秒 | 全部**两位补零** |

所以 `mail-20261111223000.tar.gz` 一眼就能看出是"2026-11-11 22:30:00"备份的。

**② ⚠️ crontab 里的 `%` 必须转义**

> **cron 把 `%` 当"命令输入换行"的特殊字符**，不转义就会把命令截断。
> 正确写法：`\%Y\%m\%d\%H\%M\%S`（**每个 `%` 前面加反斜杠**）。
> 更稳的做法：把命令写进一个 `.sh` 脚本，crontab 只调脚本 —— **这也是 105–107 你那个备份脚本的做法**。

## 4.4 ⚙️ 顺带核对本机

| 项 | 说明 |
| --- | --- |
| `/var/spool/mail` | Ubuntu 桌面版**通常没有**这个目录，邮件目录是 `/var/mail`（`/var/spool/mail` 是它的软链，也可能不存在） |
| 要备份什么 | 你的场景更有意义的是 `~/shcode`、`~/backup`、配置文件 |
| 检查是否在跑 | `crontab -l`、`systemctl status cron`、`journalctl -u cron` |

## 5.2 ⭐ 比 11 条更重要的：优化的**分层思路**

| 层 | 优化什么 | 例子 | 收益/风险 |
| --- | --- | --- | --- |
| **架构层** | 加机器、做缓存、读写分离 | Nginx → 多台后端 | 收益最大，成本最高 |

| **监控与备份** | 不是"优化性能"，是**保命** | 备份、告警 | 出事时救命 |

## 6.1 26.17 web 服务器负载架构（滴滴）

课件只列了四个名字，**没解释**。补上它们的定位：

| 组件 | 层级 | 干什么 |
| --- | --- | --- |
| **Nginx** | 七层（HTTP） | 反向代理、静态资源、负载均衡、缓存 |
| **Haproxy** | 四层/七层 | **专业负载均衡**，健康检查强 |
| **Keepalived** | — | **高可用**：VRRP 协议做 VIP 漂移，主挂了备顶上 |
| **LVS** | **四层**（内核态） | Linux 虚拟服务器，**性能最高**（在内核里转发） |

**典型的组合**：

```
用户 → Keepalived(VIP 高可用) → LVS 或 Haproxy(负载均衡) → Nginx(反向代理/静态) → 应用
```

**面试要点**：
- **LVS 四层 vs Nginx/Haproxy 七层** —— 四层转发快但看不懂 HTTP，七层能做路由/改写但慢一些
- **Keepalived 解决的是"单点"，不是"分流"** —— 这两个概念别混

# 七、附录：143 找回 MySQL root 密码

## 7.1 课件（26.3）

> 问题：如果忘记了 mysql5.7 数据库的 ROOT 用户的密码，如何找回？（滴滴）

**课件只有题目，没有答案** —— 答案在视频里。下面是通行做法。

## 7.2 【补充】标准做法（MySQL 5.7）

```bash
# ① 停服务
sudo systemctl stop mysql

# ② 临时跳过权限验证（/etc/mysql/my.cnf 或 mysqld.cnf 的 [mysqld] 段）
sudo sed -i '/\[mysqld\]/a skip-grant-tables' /etc/mysql/mysql.conf.d/mysqld.cnf

# ③ 启动后免密登录
sudo systemctl start mysql
mysql -u root

# ④ 改密码（MySQL 5.7 用 authentication_string）
FLUSH PRIVILEGES;
ALTER USER 'root'@'localhost' IDENTIFIED BY '新密码';
-- 或旧写法：UPDATE mysql.user SET authentication_string=PASSWORD('新密码') WHERE user='root';

# ⑤ 去掉 skip-grant-tables，恢复正常重启
```

| 关键点 | 说明 |
| --- | --- |
| `skip-grant-tables` | 启动时**不加载权限表**，所以谁都能进 —— **必须在改完后立刻去掉**，否则等于没密码 |
| MySQL 5.7 vs 5.6 | 5.7 用 `authentication_string`，5.6 用 `password` |
| 改完必须 `FLUSH PRIVILEGES` | 让权限表重新加载 |
| ⚠️ 生产注意 | 整个过程服务是**无密码可访问**状态，必须在停机维护窗口做 |

> 📌 **通用原则比步骤重要**：**"改配置 → 绕过验证 → 改密码 → 恢复配置"** —— 这个套路在"忘记任何服务的管理员密码"时都适用（第 9 章找回 root 密码用的是同一个思路：GRUB 加 `init=/bin/bash`）。

# 八、自测题（5 题，覆盖 149–153）

1. `df -h` 显示 `/` 用了 100%，但 `du -sh /*` 加起来远不到，可能是什么？怎么查？
2. `top` 里 `%wa` 很高说明什么？接下来该用哪个命令定位？
3. `awk '{sum+=$2} END{print sum}'` 和 `awk '{print $2}'` 的区别在哪？
4. 用 crontab 写"带时间戳的备份"，为什么 `%` 必须转义？更稳的写法是什么？
5. 系统优化为什么要"分层"？如果一上来就改 `sysctl.conf`，可能出什么问题？

<details>
<summary>答案</summary>

1. **文件被删除但仍被进程占用**（`du` 看不到，`df` 算在内）。查：`sudo lsof +L1` 或 `lsof | grep deleted`；重启对应进程即释放。也可能是挂载点被覆盖、或 inode 用尽（`df -i`）。
2. **CPU 在等磁盘/网络 IO**，不是 CPU 忙。接下来用 `iotop`（按进程）或 `iostat -x 1`（按设备）定位。
3. 前者**遍历所有行累加，只在 `END` 输出一次总和**；后者**每行输出一次**。区别就是 `{}`（每行执行）和 `END{}`（收尾执行）。
4. 因为 **cron 把 `%` 当成"命令输入换行"**，会截断命令。要写 `\%Y\%m\%d…`。更稳的是把命令写进 `.sh` 脚本，crontab 只调用脚本。
5. 因为优化有**架构 → 系统 → 应用 → 监控**四层，`sysctl.conf` 是系统层且**影响全局**。不先看监控数据就改，既不知道改前改后的效果，也可能把网络栈/文件句柄改坏导致服务起不来。**没有监控的优化是盲目的。**

</details>
