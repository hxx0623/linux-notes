## 一、【课件】18.1 Ubuntu 介绍

> Ubuntu 是一个**以桌面应用为主**的开源 GNU/Linux 操作系统，基于 GNU/Linux，支持 **x86、amd64、ppc** 架构，由 **Canonical Ltd** 打造。**专业的 Python 开发者一般会选择 Ubuntu 作为生产平台。**

### ⭐ 课件最重要的一句"温馨提示"

> Ubuntu 和 CentOS 都是基于 GNU/Linux 内核的，因此**基本使用和 CentOS 是几乎一样的**，它们的**各种指令可以通用**……只是**界面和预安装的软件有所差别**。

**一句话**：**概念全通用，命令一半通用，路径和工具名经常不同。**

## 二、🎁 CentOS → Ubuntu 完整差异总表

### 包管理

| 目的 | CentOS | Ubuntu |
| --- | --- | --- |
| 装/删/升级 | `yum install/remove/update` | `apt install/remove/upgrade` |
| 底层工具 | `rpm` | `dpkg` |
| 包格式 | `.rpm` | `.deb`（+ snap） |
| 更新索引 | `yum makecache` | `apt update` |
| 源配置 | `/etc/yum.repos.d/` | `/etc/apt/sources.list.d/*.sources` |
| 修依赖 | — | `apt install -f` |

### 服务与系统

| 目的 | CentOS | Ubuntu |
| --- | --- | --- |
| 服务管理 | `service xxx start` | `systemctl start xxx`（`service` 只是转发壳） |
| 开机自启 | `chkconfig` | `systemctl enable` |
| 服务脚本目录 | `/etc/init.d/` | 基本空了，用 systemd unit |
| 运行级别 | `runlevel` / `/etc/inittab` | `systemctl get-default`（target） |
| 定时任务服务 | **`crond`** | **`cron`** |
| 防火墙 | `firewalld` + `firewall-cmd` | **`ufw`** |
| 开端口 | `--permanent --add-port` + `--reload` | **`ufw allow 22/tcp`（立即生效）** |
| 日志 | `/var/log/cron`、`/var/log/messages` | **`journalctl -u xxx`**（24.04 无 `/var/log/syslog`） |
| **SSH 服务名** | **`sshd`** | **`ssh`** |

### 网络

| 目的 | CentOS | Ubuntu |
| --- | --- | --- |
| 配置文件 | `ifcfg-ens33` | **`/etc/netplan/*.yaml`** + NetworkManager |
| 网卡名 | `ens33` | **`ens160`**（按 PCI 位置生成） |
| 生效 | `service network restart` | `sudo netplan apply`（桌面版 GUI 最稳） |
| 网络服务 | `network.service` | **不存在** |
| SSH 进程 | `sshd` 常驻 | **`ssh.socket` 按需激活，空闲时无 sshd** |

### 账户与权限

| 项 | CentOS | Ubuntu |
| --- | --- | --- |
| root 登录 | 直接可用 | **密码锁定**，全程 `sudo` |
| 启用 root | 天然可用 | `sudo passwd` 后 `su` 才可用 |
| `/bin/sh` | → **bash** | → **dash** |
| 家目录权限 | 700 | **750** |
| 默认 umask | 0022 → 644 | 0002 → 664 |
| `/etc/hosts` | 无 `127.0.1.1` | **有** |
| locale 配置 | `/etc/locale.conf` | **`/etc/default/locale`** |

### 其他

| 项 | CentOS | Ubuntu |
| --- | --- | --- |
| 包体系 | 只有 rpm/yum | **deb + snap + flatpak** |
| GRUB 菜单 | 默认显示 | **默认隐藏**（`GRUB_TIMEOUT=0`） |
| swap | 独立分区 | **`/swap.img` 文件** |
| Python | `python` = 2.7 | **只有 `python3`**（无 `python`） |
| 装 Python 包 | `pip install` 随便装 | **PEP 668 禁止**，必须用 `venv` |

## 三、🔑 差异三步判断法

```
第一步：是不是「包管理」？
        yum/rpm → apt/dpkg
              ↓ 不是
第二步：是不是「服务 / 防火墙 / 网络」？
        crond → cron     firewalld → ufw
        ifcfg → netplan  sshd(服务名) → ssh
              ↓ 不是
第三步：是不是「路径 / 设备名」？
        /etc/sysconfig/ → /etc/apt/ 或 /etc/netplan/
        ens33 → ens160
              ↓ 都不是
        通用命令，直接敲 ✅
```

## 四、【课件】18.3 设置中文（locale）

### 课件四步

1. 打开 **Language Support**
2. **Install / Remove Languages** → 勾 **Chinese (Simplified)** → Apply
3. 把"汉语（中国）"**拖到第一位**
4. **下一次登录才生效**

> Ubuntu 24.04 的界面路径变了：**设置 → 系统 → 区域与语言 → 语言**。

### 本机情况：**装机时已选中文，无需操作**

证据：所有命令输出都是中文（`总用量`、`权限不够`、`已终止`）。

```bash
locale                    # 看当前生效
locale -a | grep -i zh    # 看已生成的 locale
cat /etc/default/locale   # 看默认配置
```

### 命令行方式（四步）

```bash
sudo apt install language-pack-zh-hans fonts-noto-cjk   # 语言包 + 字体
sudo locale-gen zh_CN.UTF-8                             # 生成
sudo update-locale LANG=zh_CN.UTF-8 LANGUAGE=zh_CN:zh   # 设为默认
# 重新登录
```

### ⚠️ 关键补充

| 坑 | 现象 | 原因 |
| --- | --- | --- |
| 装了包界面还英文 | 全英文 | 没设 `LANG` |
| 中文显示 `□□□` | 方块 | **缺字体 `fonts-noto-cjk`** |
| 中文文件名变 `???` | 问号 | locale 不是 UTF-8 |
| 设置后不生效 | — | 没重新登录 |

### 💡 实用技巧：报错信息保持英文

```bash
sudo update-locale LANG=zh_CN.UTF-8 LC_MESSAGES=C
```

**中文报错搜不到答案**（别人都是英文报错），`LC_MESSAGES=C` 让界面中文、报错英文。

### locale 变量优先级

```
LC_ALL  >  LC_*  >  LANG
```

## 五、【课件】18.4 Ubuntu 的 root 用户

### 课件要点

> 装完 Ubuntu 都是**普通用户权限**，需要用 root 就在命令前加 **`sudo`**。
> 用 `su` 切 root，但**没设初始密码会报 `su: Authentication failure`**。

**本机 10-22 实测过这个失败** —— `/etc/shadow` 里 root 密码字段是 `!`（锁定）。

### 四步操作

```bash
sudo passwd     # 给 root 设密码（不带用户名 = 改 root 的密码）
su -            # 切换（- 表示完整登录：加载 root 环境 + 切到 /root）
# 提示符 $ → #
exit            # 返回普通用户
```

### `$` vs `#`

| 提示符 | 身份 |
| --- | --- |
| `$` | 普通用户 |
| **`#`** | **root（所有操作都无保护）** |

### `su` 和 `su -` 的区别（课件没细说）

| 命令 | 环境变量 | 工作目录 |
| --- | --- | --- |
| `su root` | 保留原来的 | 不变 |
| **`su -`** | **加载 root 的** | **`/root`** |

**永远用 `su -`。**

### ⚠️ 建议：方法要会，但平时别启用 root

| # | 理由 |
| --- | --- |
| 1 | Ubuntu 的设计哲学：禁 root 直登 + 强制 sudo |
| 2 | `sudo` 有审计日志，root 直登没有 |
| 3 | `#` 下误操作无保护 |
| 4 | 服务器规范普遍 `PermitRootLogin no` |

### 更好的替代：`sudo -i`

| | `su -` | **`sudo -i`** |
| --- | --- | --- |
| 要输的密码 | root 的（没设就用不了） | **你自己的** |
| 结果 | root shell | root shell |

**所以根本不需要启用 root。**

### sudo 进阶速查

| 命令 | 作用 |
| --- | --- |
| `sudo -i` | 切 root 交互 shell（用自己密码） |
| `sudo -u 用户 命令` | 以指定用户身份执行 |
| **`sudo -v`** | **预热凭证**（15 分钟免输，解决 `sudo cmd &` 卡死） |
| `sudo -k` | 立即失效凭证 |
| `sudo -l` | 看我能 sudo 什么 |
| **`sudo visudo`** | 改 sudoers（**别用 vim 直接改**，语法错会锁死系统） |

### 恢复锁定

```bash
sudo passwd -l root      # 重新锁定
```

## 六、【课件】18.5 Ubuntu 下开发 Python

> 安装好 Ubuntu 后，**默认就已经安装好 Python 的开发环境**。

**原因**：Ubuntu 大量系统工具用 Python 写（`apt`、`netplan`、`snap`），是系统级依赖。

```bash
python3 --version        # Python 3.12.3
vi hello.py              # print("hello, world~")
python3 hello.py
```

### ⚠️ 坑 ①：没有 `python` 命令

```bash
python hello.py
# Command 'python' not found
```

**Ubuntu 不提供 `python` 别名**（Python 2 已 EOL），强制用 `python3`。

想恢复 `python`：`sudo apt install python-is-python3`

### ⚠️ 坑 ②：`pip install` 被禁止（PEP 668）

```
error: externally-managed-environment
```

**Ubuntu 24.04 禁止 pip 直接装进系统 Python** —— 系统 Python 归 `apt` 管，混装会搞坏 `apt` 本身。

### 正确做法：`venv`

```bash
sudo apt install python3-venv python3-pip
python3 -m venv ~/myenv
source ~/myenv/bin/activate      # 前面出现 (myenv)
pip install requests             # 现在随便装
deactivate
```

| | 系统 Python | venv |
| --- | --- | --- |
| 包装在 | `/usr/lib/python3/dist-packages` | `~/myenv/lib/.../site-packages` |
| 能 pip install | ❌ | ✅ |
| 影响系统 | 会 | 不会 |

### 常用

| 命令 | 作用 |
| --- | --- |
| `python3 -c "代码"` | 直接执行一行 |
| `python3` | 进交互解释器（`exit()` 退出） |
| `python3 -m http.server 8000` | **一行起 HTTP 服务器** |
| `python3 -m json.tool f.json` | 格式化 JSON |

### Shell 与 Python 的分工

| 场景 | 用谁 |
| --- | --- |
| 串联系统命令、定时任务、备份 | **Shell** |
| 文本处理（grep/awk/sed） | Shell |
| 复杂数据结构、JSON/API | **Python** |
| 浮点运算 | **Python**（Shell 只有整数） |
| 几十行以上逻辑 | **Python** |

## 七、【课件】19.1–19.2 APT

> **apt 是 Advanced Packaging Tool 的简称**，一款安装包管理工具……类似于 Windows 中的软件管理工具。

### 三者关系（易混）

```
        apt     ← 新前端（2014+），统一入口，有进度条和颜色
       ↙   ↘
  apt-get   apt-cache    ← 老命令，脚本里仍常用（输出格式稳定）
```

### 课件九条命令 + 现代写法

| # | 课件原文 | 作用 | 现代写法 |
| --- | --- | --- | --- |
| 1 | `apt-cache search pkg` | 搜索 | `apt search 关键词` |
| 2 | `apt-get install pkg --reinstall` | 重装 | `apt install --reinstall pkg` |
| 3 | `apt-get -f install` | **修依赖断裂** | `apt install -f` |
| 4 | `apt-get remove pkg --purge` | 删包**含配置** | `apt purge pkg` |
| 5 | `apt-get build-dep pkg` | 装编译环境 | `apt build-dep pkg` |
| 6 | `apt-get upgrade` | 升级已装包 | `apt upgrade` |
| 7 | `apt-get dist-upgrade` | 升级系统（可增删包） | `apt full-upgrade` |
| 8 | `apt-cache depends pkg` | 我依赖谁 | `apt depends pkg` |
| 9 | `apt-cache rdepends pkg` | **谁依赖我** | `apt rdepends pkg` |

### 三对易混

| 对比 | 差别 |
| --- | --- |
| `remove` vs **`purge`** | purge **连配置文件一起删** |
| `upgrade` vs `dist-upgrade` | 后者**允许安装新包、删除冲突包**（可装新内核） |
| `depends` vs `rdepends` | 前者"我需要谁"，后者"**谁需要我**"（删包前必看） |

### apt 四层结构

```
① 源      /etc/apt/sources.list.d/*.sources
      ↓ apt update
② 索引    /var/lib/apt/lists/
      ↓ apt install
③ 缓存    /var/cache/apt/archives/*.deb
      ↓ dpkg -i
④ 已安装  /var/lib/dpkg/status
```

| 报错 | 卡在哪层 |
| --- | --- |
| `无法定位软件包` | ② 索引没有 → `apt update` |
| `无法下载` / 解析失败 | ① 网络/源不通 |
| `dependency problems` | ④ → `apt install -f` |
| `无法获得锁` | 有别的 apt 在跑 |

## 八、【课件】19.3 更新软件源

> **所谓的镜像源**：可以理解为提供下载软件的地方，比如 Android 上的安卓市场；iOS 上的 App Store。

镜像 = 国内服务器上的一份完整副本。官方源在国外 → 慢；换国内镜像 → 快。

**本机 10-21 已换清华 TUNA，并修复过一次遗留的 `sg.archive.ubuntu.com`。**

### ⚠️ Ubuntu 24.04 的配置方式变了

| 版本 | 配置文件 | 格式 |
| --- | --- | --- |
| 老（≤20.04） | `/etc/apt/sources.list` | 一行一条 |
| **新（24.04）** | **`/etc/apt/sources.list.d/ubuntu.sources`** | **deb822 多行键值** |

```
Types: deb
URIs: https://mirrors.tuna.tsinghua.edu.cn/ubuntu/
Suites: noble noble-updates noble-backports noble-security
Components: main restricted universe multiverse
```

**`noble` = 24.04 的代号**（写错就 404）。

### 换源推荐做法：只换域名

```bash
sudo cp -r /etc/apt/sources.list.d /etc/apt/sources.list.d.bak

sudo sed -i 's|http://archive.ubuntu.com|https://mirrors.tuna.tsinghua.edu.cn|g' \
           /etc/apt/sources.list.d/ubuntu.sources

sudo apt update
```

**为什么用 sed**：只改域名，**不动格式和代号**，不会因为手打漏了 `Components` 而搞坏。

### 验证

`apt update` 输出里出现 `https://mirrors.tuna.tsinghua.edu.cn/ubuntu noble InRelease` = 成功。

### 国内镜像

清华 TUNA、阿里云、中科大 USTC、华为云、网易 —— **格式一样，只改域名**。

## 九、【课件】19.5 SSH 远程登录

> **SSH 为 Secure Shell 的缩写**，由 IETF 制定；建立在**应用层和传输层基础上的安全协议**……**专为远程登录会话和其他网络服务提供安全性**。

| 关键词 | 含义 |
| --- | --- |
| Secure | 全程加密（对比 telnet 的明文） |
| Shell | 远程命令行 |
| 端口 | **22** |

### 客户端 / 服务端分工（课件原文）

> 如果 **A 机器想被 B 机器远程控制**，那么 **A 机器需要安装 SSH 服务器，B 机器需要安装 SSH 客户端**。

### ⚠️ 两个 Ubuntu 差异

**① Ubuntu 桌面版默认没装 `openssh-server`**

```bash
sudo apt install openssh-server
```

（本机的 `ubuntu-vm-setup.sh` 早就装了）

**② 服务名是 `ssh`，不是 `sshd`**

| | CentOS | Ubuntu |
| --- | --- | --- |
| 服务单元 | `sshd` | **`ssh`** |
| 启动 | `systemctl start sshd` | **`systemctl start ssh`** |

课件写的 `service sshd restart` 在 Ubuntu 上会报 `sshd.service not found`。

**而且本机还有 `ssh.socket`**（按需激活），`systemctl list-units 'ssh*'` 能看到。

### 登录

```bash
ssh 用户名@IP
ssh cxh@192.168.139.100
```

**第一次会问 `Are you sure you want to continue connecting?`** → 输 `yes`。

### `known_hosts`（课件提到的文件）

存的是**服务器指纹**。服务器重装或换密钥后，指纹变了会报：

```
REMOTE HOST IDENTIFICATION HAS CHANGED!
```

**精准清理（别删整个文件）：**

```bash
ssh-keygen -R 192.168.139.100
```

### 登出

```bash
exit        # 或 logout
```

### ⭐ 免密登录（课件没讲，但极实用）

```powershell
# Windows 侧
ssh-keygen -t ed25519
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh cxh@192.168.139.100 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
ssh cxh@192.168.139.100      # 不再要密码
```

**⚠️ 权限要求严格**：`~/.ssh` 必须 **700**、`authorized_keys` 必须 **600** —— 这是第 10 章 `rwx` 规则在 SSH 上的应用，权限不对 SSH 直接拒绝。

**免密的意义**：自动化脚本里**没法输密码**（跟 079 集 `sudo cmd &` 卡死是同一类问题）。

## 十、今日踩的坑 / 注意点

1. **`python` 命令不存在** —— Ubuntu 只有 `python3`；要 `python` 得装 `python-is-python3`
2. **`pip install` 报 `externally-managed-environment`** —— PEP 668，必须用 `venv`
3. **`systemctl status sshd` 找不到服务** —— Ubuntu 服务名是 **`ssh`**
4. **`python -m http.server 8000`** 显示 `0.0.0.0` —— **所有网卡监听，外部可访问**；只想本机用 `--bind 127.0.0.1`
5. **用 `python -m http.server` 起服务时终端被占用** —— 要后台跑用 `&` + `$!` 记 PID

## 十二、跨章综合自测 10 题

1. 文件权限 `-rw-r-----`，数字怎么写？谁能读？
2. `chmod g=r file` 和 `chmod 640 file` 结果一样吗？
3. `*/10 2-4 * * * date` 一天执行几次？
4. `df` 满了但 `du` 加起来只有一半，怎么查？
5. `systemctl stop` 和 `disable` 的区别？
6. `kill -9` 掉的 systemd 服务为什么会自己回来？
7. `[ "$a" = "$b" ]` 里 `$a` 为什么要加引号？
8. `cat f | while read` 里改的变量为什么循环后消失？
9. Ubuntu 上 `service crond restart` 和开防火墙端口怎么写？
10. 虚拟机突然连不上外网，第一步查什么？

<details>
<summary>答案</summary>

1. **640**；所有者 rw，**同组可读**，其他人无权限
2. **不一样**：`g=r` 只改 g 栏；`640` 是**重设全部 9 位**
3. **18 次**（`*/10` 每小时 6 次 × 2/3/4 三个小时）
4. **文件被删但进程还开着** → `sudo lsof | grep deleted`
5. `stop` 管当前状态（重启恢复）；`disable` 取消开机自启（永久）
6. 因为 **`Restart=on-failure`**（意外死亡会重启）；正确做法是 `systemctl stop`（计划内停止）
7. 变量为空时会变成 `[ = "$b" ]` → 语法错误；加引号后是 `[ "" = "$b" ]` 才合法
8. 管道右边是**子 shell**，变量改动随子 shell 消失 → 用 `while read ... done < f`
9. `sudo systemctl restart cron`；`sudo ufw allow 端口/tcp`
10. **先查宿主机**：VMware 服务是否在跑、VMnet8 有没有 `192.168.x.1` 的 IP
