## 一、【课件】12.1 分区原理

### Linux 只有一棵树

> Linux 无论有几个分区，归根结底只有**一个根目录**；采用**“载入”**的方法，**将一个分区和一个目录联系起来**。

| | Windows | Linux |
| --- | --- | --- |
| 盘符 | `C:` `D:` 多棵树 | 只有 `/`，一棵树 |
| 加硬盘 | 多一个盘符 | **挂到树上某个目录** |

本机现状：

| 分区 | 挂载点 |
| --- | --- |
| `sda1`（1G） | `/boot/efi` |
| `sda2`（58.9G） | `/` |
| `sdb1`（5G） | `/newdisk`（新加的） |

### 硬盘命名（课件 12.1.2）

| 类型 | 格式 | 例 |
| --- | --- | --- |
| IDE | `hd` + 盘号 + 分区号 | `hda3` = 第一块 IDE 盘第 3 个主/扩展分区 |
| SCSI/SATA（现在全是） | `sd` + 盘号 + 分区号 | `sdb1` = 第二块盘的第 1 个分区 |

**分区号铁律：1–4 = 主分区/扩展分区；5 起 = 逻辑分区。**

补充：NVMe 是 `nvme0n1p1`；光驱是 `sr0`。

### `lsblk`

| 命令 | 多给了什么 |
| --- | --- |
| `lsblk` | 树状 + 大小 + **挂载点** |
| `lsblk -f` | 再加**文件系统类型 / UUID / 卷标** |

**`df` 只看已挂载，`lsblk` 能看未挂载的裸设备** —— 判断“新盘有没有被识别”用 `lsblk`。

## 二、【课件】12.2 加硬盘 5 步（本机已全程跑通）

```
① 虚拟机加硬盘（VMware，关机状态）→ 开机能识别
② fdisk 分区
③ mkfs 格式化
④ mount 挂载
⑤ /etc/fstab 永久挂载
```

### ② `fdisk` 分区

```bash
sudo fdisk /dev/sdb
```

| 键 | 作用 |
| --- | --- |
| `m` | 帮助 |
| `p` | 打印分区表 |
| `n` | **新增** |
| `d` | 删除 |
| `w` | **写入退出（真的改盘）** |
| `q` | **不保存退出（反悔）** |

**课件给的按键序列**：`n` → `p`（主分区）→ 回车（分区号 1）→ 回车（起始）→ 回车（剩余全部）→ `w`

分区后 `lsblk` 应出现 `sdb1`。没出现：`sudo partprobe /dev/sdb`。

### ③ 格式化

```bash
sudo mkfs -t ext4 /dev/sdb1
```

**分区只是容器，`mkfs` 才是装文件系统** —— 没格式化的分区挂不上。
验证：`lsblk -f` 里 `sdb1` 出现 `FSTYPE ext4` + `UUID`。

> `mkfs.ext4` 会自动建 `lost+found` 目录（`drwx------ root root`），用于 `fsck` 恢复孤儿文件，**别删**。

### ④ 挂载

```bash
sudo mkdir -p /newdisk        # ⚠️ 课件省了这一步，不建会报 mount point does not exist
sudo mount /dev/sdb1 /newdisk
df -h | grep sdb1
```

卸载：

```bash
sudo umount /newdisk           # 或 umount /dev/sdb1
```

**⚠️ `umount: target is busy`** = 你正在挂载点目录里，或有进程占用 → `cd ~` 退出，必要时 `sudo lsof +D /newdisk`。

### ⑤ 永久挂载 `/etc/fstab`

> 课件原话：**用命令行挂载，重启后会失效。**

```bash
sudo cp /etc/fstab /etc/fstab.bak       # 必须先备份
sudo vim /etc/fstab
# /dev/sdb1  /newdisk  ext4  defaults  0  2
sudo mount -a
```

**六个字段**：设备 / 挂载点 / 类型 / 选项 / dump / 自检顺序（根分区是 1，其它 2）。

**本机改成 UUID（比课件更规范）**：

```bash
sudo blkid /dev/sdb1
# fstab 写：UUID=xxxx-xxxx  /newdisk  ext4  defaults  0  2
```

> 设备名会变（插 U 盘可能从 `sdb` 变 `sdc`），**UUID 永远不变**，所以生产环境一律用 UUID。

### 🚨 fstab 写错 = 开不了机

会卡在 `Welcome to emergency mode!`。救援：

```
输入 root 密码
mount -o remount,rw /
vim /etc/fstab        # 删掉/注释掉错的那行
reboot
```

**或者直接回滚快照。** 所以 `cp /etc/fstab /etc/fstab.bak` 不是客套。
改完可以先 `sudo findmnt --verify` 在重启之前检查语法。

## 三、【课件】12.3 磁盘情况查询

### `df -h`（disk free）

六列：Filesystem / Size / Used / Avail / Use% / Mounted on。

- **只显示已挂载的文件系统**
- 读文件系统元数据，**瞬间出结果**
- `df -hT` 多一列文件系统类型
- Ubuntu 有一堆 `tmpfs`/`squashfs` 行（CentOS 少），可 `df -h -x tmpfs`

### `du -h`（disk usage）

| 选项 | 含义 |
| --- | --- |
| `-s` | 只给汇总 |
| `-h` | 带单位 |
| `-a` | 含文件 |
| `--max-depth=1` | **只看一层子目录（最常用）** |
| `-c` | 末尾加总计 |

```bash
du -h --max-depth=1 /usr | sort -hr     # ⚠️ sort -h 是升序，-r 才是降序
```

`sort -h` 的价值：能正确比较 `K/M/G`；不加 `h` 会按字典序乱排。
`--max-depth=1` 的输出**最后一行是父目录自己**。

### `df` vs `du`

| | `df` | `du` |
| --- | --- | --- |
| 视角 | 文件系统（块设备） | 目录树（逐文件累加） |
| 速度 | 快 | 慢 |

**经典问题：`df` 满了但 `du` 找不到** → 文件被 `rm` 了但进程还开着（持有文件描述符）：

```bash
sudo lsof | grep deleted
```

## 四、【课件】12.4 工作实用指令

| 需求 | 命令 |
| --- | --- |
| 数文件 | `ls -l /opt \| grep "^-" \| wc -l` |
| 数目录 | `ls -l /opt \| grep "^d" \| wc -l` |
| 递归数文件 | `ls -lR /opt \| grep "^-" \| wc -l` |
| 递归数目录 | `ls -lR /opt \| grep "^d" \| wc -l` |
| 树状显示 | `tree /opt`（Ubuntu：`sudo apt install tree`） |

- `^` 是**行首锚点** —— 去掉会把文件名里带 `-` 的行也算进去
- **别用 `ls -la`**：`. ` 和 `..` 也是 `d` 开头，会多算 2 个（你的 `ll` 别名就带 `-a`）
- `ls -lR` 多出的 `/path:` 标题行和 `总用量` 行**不会干扰计数**（行首不是 `-`/`d`）

工程上更推荐 `find`：

```bash
find /opt -maxdepth 1 -type f | wc -l
find /opt -type f | wc -l
```

理由：`ls -l` 是“给人看的”格式，文件名带换行会解析错；`find` 专为此设计。

## 五、今日踩的坑（10-29，第 12 章部分）

1. **`du -sh /root` 报“权限不够”却仍输出 `4.0K`** —— 那个 `4.0K` 是**目录本身**的大小（一张名字→inode 的表，ext4 最小 4096 字节），里面内容一个都没算。
   - 错误走 **stderr**，`4.0K` 走 **stdout**，两条流互不影响
   - `sudo du -sh /root` 才是真实大小
2. **`ls -lR /etc | grep "^-" | wc -l` 得到 1682，`sudo` 后是 1683** —— 有几个 `700` 目录读不到，里面的文件**静默消失**。
   - **绝不加 `2>/dev/null` 掩盖** —— 那样连“数字不完整”的信号都没了
3. **`sort -h` 是升序不是降序**（我讲错过一次） —— 要 `sort -hr`
4. **新挂载点属主是 root** —— `/newdisk` 是 `drwxr-xr-x root root`，`cxh` 建不了文件；`sudo chown cxh:cxh /newdisk` 才解决（第 10 章的权限规则）
5. **`mount -a` 后提示 systemd still uses the old version** —— Ubuntu 22.04+/systemd 的新提示，**不是错误**，`sudo systemctl daemon-reload` 可消除；CentOS 7 没有
6. **`df` 显示 4.9G 而 `lsblk` 显示 5G** —— 差的是 ext4 元数据，正常

## 六、三条铁律

**① 分区 ≠ 文件系统** —— `fdisk` 划地，`mkfs` 铺规则，没格式化挂不上。

**② 命令行 `mount` 是临时的，`fstab` 才是永久的** —— `mount` 不写任何配置文件。

**③ 改 `fstab` 先备份、改完先验证** —— 写错开不了机。

## 七、自测题

1. 一块新硬盘从裸设备到能存文件，要经过哪几个动作？
2. `fdisk` 里 `w` 和 `q` 的区别？
3. 为什么 `fstab` 推荐写 `UUID=`？
4. `df` 显示 100% 但 `du` 加起来只有一半，最可能是什么原因？
5. `du -sh /root` 输出 `4.0K` 说明了什么？
6. `ls -lR /etc | grep "^-" | wc -l` 的结果为什么不完整？

<details>
<summary>答案</summary>

1. 加硬盘 → `fdisk` 分区 → `mkfs` 格式化 → `mount` 挂载 →（可选）写 `fstab` 永久挂载
2. `w` 真的写入分区表；`q` 不保存退出，什么都没改
3. 设备名会变（`sdb`→`sdc`），UUID 唯一且不变
4. 有文件被删除但**进程仍持有它的文件描述符**，数据块没释放；`sudo lsof | grep deleted` 可查
5. `du` 只统计到 `/root` **目录本身**的 4KB（名字→inode 表），里面的内容因为没权限读而一个都没算；错误走了 stderr
6. 有几个 `700` 的目录（`/etc/ssl/private`、`/etc/polkit-1/rules.d` 等）读不到，**里面的文件静默不计入** —— 数字是“你能读到的部分”

</details>
