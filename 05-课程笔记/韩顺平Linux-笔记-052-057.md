## 一、【课件】11.1.1 概述

> 任务调度：是指系统在某个时间执行的特定的命令或程序。

| 类别 | 课件原文举例 |
| --- | --- |
| 系统工作 | 有些重要的工作必须周而复始地执行，如**病毒扫描** |
| 个别用户工作 | 个别用户希望执行某些程序，比如对 **MySQL 数据库的备份** |

任务存放位置：

| 位置 | 谁的任务 | 怎么改 |
| --- | --- | --- |
| `/etc/crontab`、`/etc/cron.d/` | 系统级 | 编辑文件（一般要 root） |
| 每个用户自己一份 | 个人级 | `crontab -e` |

## 二、【课件】11.1.2–11.1.3 语法与选项

```bash
crontab [选项]
```

课件 11.1.3 是**表格截图**，抽不出文字；标准三个选项：

| 选项 | 作用 |
| --- | --- |
| `-e` | 编辑当前用户任务 |
| `-l` | 列出当前用户任务 |
| `-r` | **删除全部**任务（无确认） |

> `-r` 是**清空全部**，不是删一条。想稳妥用 `-ri`（带 y/n 确认）。
> 改之前先备份：`crontab -l > ~/cron.bak`。

## 三、【课件】11.1.4 五段格式（时间规则）

```
分 时 日 月 周   要执行的命令
```

### 五个占位符

| 位置 | 字段 | 取值 | 英文写法 |
| --- | --- | --- | --- |
| 1 | 分钟 | 0–59 | — |
| 2 | 小时 | 0–23 | — |
| 3 | 日 | 1–31 | — |
| 4 | 月 | 1–12 | `jan`–`dec` |
| 5 | 星期 | **0–7（0 和 7 都是周日）** | `sun`–`sat` |

### ⚠️ 日与周是「或」不是「且」

```
0 3 15 * 1  命令      ← 15 号，或者每周一（任一满足就执行）
```

要表达“15 号且是周一”，cron 做不到，只能在命令里自己判断。

### 四个特殊符号

| 符号 | 含义 | 例子 |
| --- | --- | --- |
| `*` | 任意 | `* * * * *` 每分钟 |
| `,` | 枚举 | `1,15,30 * * * *` |
| `-` | 范围（**闭区间**） | `1-5 * * * *` |
| `/` | 步长 | `*/5` 每 5 分钟；`10-50/5` 从 10 起每 5 分到 50 |

### 常用时间（背这七个够了）

| 需求 | 写法 |
| --- | --- |
| 每 5 分钟 | `*/5 * * * *` |
| 每小时整点 | `0 * * * *` |
| 每天凌晨 2 点 | `0 2 * * *` |
| 每天 2:30 | `30 2 * * *` |
| 每周一 3 点 | `0 3 * * 1` |
| 每月 1 号 0 点 | `0 0 1 * *` |
| 工作日 9–18 点每 30 分 | `*/30 9-18 * * 1-5` |

### ⚠️ `%` 必须转义

cron 里 **`%` 表示换行**，会把命令从这里切断：

```bash
* * * * * date +%F >> /tmp/d.txt      # ❌ 会被截断
* * * * * date +\%F >> /tmp/d.txt     # ✅
```

`crontab -l` 里看起来完全正常，**任务就是不按你想的跑** —— 这是最隐蔽的坑。

## 四、【课件】11.1.5 三个应用实例

### 案例 1：每分钟追加日期

```bash
*/1 * * * * date >> /tmp/mydate
```

`>>` 追加；用 `>` 会覆盖，文件里永远只剩一行。

### 案例 2：用脚本干活（重点）

```bash
# 步骤1：建脚本
vim ~/my.sh
#!/bin/bash
date >> /home/cxh/mycal
cal >> /home/cxh/mycal

# 步骤2：给执行权限
chmod u+x ~/my.sh

# 步骤3：交给 cron
crontab -e
*/1 * * * * /home/cxh/my.sh
```

**为什么用脚本而不是塞进 crontab：**

| 塞进 crontab | 写进脚本 |
| --- | --- |
| `%`、空格都要转义 | 随意写 |
| 多命令挤一行 | 一行一条，可加注释 |
| 改时容易改坏 | 单独 `vim` 改，不影响调度 |

**脚本三条铁律：**

1. 第一行 `#!/bin/bash` —— **Ubuntu 的 `/bin/sh` 是 dash**，不写会被 dash 解释，`[[ ]]`、数组、`==` 全挂。
2. 命令尽量写**绝对路径** —— cron 的 `PATH` 只有 `/usr/bin:/bin`。
3. 先手动 `bash ~/my.sh` 跑通，再挂 cron。

### 案例 3：每天凌晨 2 点备份 MySQL

```bash
0 2 * * * mysqldump -uroot -proot testdb > /home/db.bak
```

- `-p密码` **中间不能有空格**
- ⚠️ **密码会出现在 `ps -ef` 里**，同机任何用户都能看到 → 生产用 `--defaults-extra-file`

## 五、【课件】11.1.6 crond 相关指令

| 课件写法 | 作用 | Ubuntu |
| --- | --- | --- |
| `crontab -r` | “终止任务调度”（实为删除全部） | 同 |
| `crontab -l` | 列出任务 | 同 |
| `service crond restart` | 重启调度服务 | **`sudo systemctl restart cron`** |

> **`crontab -e` 保存后不需要重启 cron** —— cron 每分钟自己重读任务表，保存即生效。

## 六、【课件】11.2.1–11.2.2 `at` 机制

| 课件要点 | 内容 |
| --- | --- |
| 1 | 一次性任务，`atd` 守护进程后台运行，检查作业队列 |
| 2 | `atd` 默认**每 60 秒**扫一次队列，匹配就运行（所以会晚几秒） |
| 3 | **执行完不再执行** |
| 4 | 用 `at` 必须保证 `atd` 进程已启动 |
| 5 | `ps -ef \| grep atd`（更稳：`grep [a]td`） |

### 与 cron 的区别

| | `cron` | `at` |
| --- | --- | --- |
| 类型 | 周期性 | **一次性** |
| 守护进程 | `cron` | `atd` |
| 加任务 | `crontab -e` | `at 时间` + `Ctrl+D` |
| 查看 | `crontab -l` | **`atq`** |
| 删除 | `crontab -r`（全清） | `atrm 编号`（精确） |
| Ubuntu 默认 | 已装 | **没装**（`apt install at`） |

**口诀**：每天/每周 → `cron`；今晚/明天 → `at`。

### 命令格式

```bash
at [选项] [时间]
# 出现 at> 提示符后输入命令，按 Ctrl+D 结束
# 确认信息：job 3 at Wed Oct 28 18:05:00 2026
```

## 八、【课件】11.2.4 六种时间写法

| # | 写法 | 例子 | 说明 |
| --- | --- | --- | --- |
| 1 | `hh:mm` | `at 04:00` | **时间已过 → 自动排到第二天** |
| 2 | 模糊词 | `midnight` / `noon` / `teatime` | 00:00 / 12:00 / **16:00** |
| 3 | 12 小时制 | `at 12pm` | 加 `AM` 或 `PM` |
| 4 | 带日期 | `at 04:00 2026-10-30` | 也有 `mm/dd/yy`、`dd.mm.yy` |
| 5 | 相对时间 | `at now + 5 minutes` | 单位 `minutes`/`hours`/`days`/`weeks` |
| 6 | 相对日期词 | `at today` / `at tomorrow` | 可组合：`at 5pm tomorrow` |

**`12am` = 00:00（午夜），`12pm` = 12:00（中午）** —— 别搞反。

## 十、今日踩的坑（10-28）

1. **`watch` 里按 `q` 退不出去** → `Ctrl+C` 一定管用；`q` 只在自己是前台进程时有效（输入法、焦点问题都会截走按键）。
2. **Ubuntu 24.04 根本没有 `/var/log/syslog`** → 24.04 起默认不装 rsyslog，日志全进 `journald`：`journalctl -u cron`。
3. **Ubuntu 默认没装 `at`** → `sudo apt install at` + `sudo systemctl enable --now atd`（装包和起服务是两件事）。
4. **`at` 的输出默认当邮件发**，没有 MTA 就直接丢弃 → **等多久都看不到**，命令里必须 `> 文件 2>&1`。
5. **后台任务里不能用 `sudo`**（没有终端输密码）→ 需要 root 就用 `sudo at …` 或 `sudo crontab -e`。
6. **日和周是“或”关系**，不是“且”。
7. **`2-4` 是闭区间 = 3 个小时**，配合 `*/10`（每小时 6 次）→ 一天 18 次，不是 12 次。
8. **`crontab -e` 在 Ubuntu 打开的是 nano** → `select-editor` 改成 `/usr/bin/vim.basic`。
9. **`crontab -r` 与 `-e` 删一行的差别**：`-r` **清空全部且无确认**；`-e` 只删一行且不保存可反悔。

## 十一、任务不跑：排查五步

```bash
① systemctl is-active cron          # 服务活着吗
② systemctl is-enabled cron         # 开机自启吗
③ crontab -l                        # 任务在吗
④ journalctl -u cron | grep CMD     # cron 触发了吗
⑤ 手动跑一遍命令                     # 命令本身对吗
```

**第 ④ 步是分水岭：**

| 现象 | 结论 |
| --- | --- |
| 有 `(cxh) CMD (...)` | cron 触发了，问题在**命令本身** |
| 没有这一行 | cron 没跑，问题在**服务/时间/语法** |

**三个隐形杀手**：`%` 未转义 · `PATH` 太短 · 脚本没 `x` 或没 shebang。

## 十二、第 11 章的 Ubuntu 差异汇总

| 课件（CentOS） | 你（Ubuntu 24.04） |
| --- | --- |
| 服务名 `crond` | **`cron`** |
| `service crond restart` | `sudo systemctl restart cron` |

## 十三、自测题

1. `*/10 2-4 * * *` 一天执行几次？
2. 每工作日 9:15 执行一次，五个位置怎么写？
3. `0 0 1 * 1 命令` 什么时候执行？
4. cron 里要写 `date +%F`，正确写法是什么？
5. `at` 任务里为什么不能直接写 `sudo systemctl restart cron`？
6. `crontab -r` 和“在 `-e` 里删掉一行”有什么本质区别？

<details>
<summary>答案</summary>

1. **18 次**：`*/10` 每小时 6 次 × `2-4` 三小时
2. `15 9 * * 1-5`
3. 每月 1 号**或者**每周一（“或”关系，任一满足就执行）
4. `date +\%F` —— `%` 被 cron 当作换行，必须转义
5. 后台没有终端，`sudo` 要输密码会失败；要用 `sudo at …` 或 `sudo crontab -e` 以 root 身份加任务
6. `-r` **清空全部任务且无确认**；`-e` 删一行只影响那一行，且不保存就等于没做
