## 040 集 · 组的基本介绍（课件 10.1）

### 课件原文（就四行）

> 在 Linux 中，每个用户**必须属于一个组，不能独立于组外**。
> 每个文件有 **所有者、所在组、其它组** 的概念：
> 1) 所有者　2) 所在组　3) 其它组　4) 改变用户所在的组

### 三个身份

| 身份 | 是谁 |
| --- | --- |
| **所有者**（User） | 文件的创建者 |
| **所在组**（Group） | 文件属于哪个组，组里的人 |
| **其它组**（Other） | 既不是所有者、也不同组的所有人 |

### `ls -l` 的那串字符 = 1 + 3 + 3 + 3

```
-  rw-  rw-  r--
│   │    │    └── 其它组（Other）
│   │    └─────── 所在组（Group）
│   └──────────── 所有者（User）
└──────────────── 类型：- 普通文件  d 目录  l 软链接
```

后面 044 集会把这 10 个位置逐个讲透。

### 实测记录

```
$ id
uid=1000(cxh) gid=1000(cxh) 组=1000(cxh),4(adm),24(cdrom),27(sudo),
   30(dip),46(plugdev),100(users),114(lpadmin),123(lxd)
```

- **第一个是主组**（`cxh`），后面全是附加组
- `sudo` 组决定能不能 `sudo`；`adm` 决定能不能读 `/var/log/syslog`
- `groups` 与 `id` 只是输出格式不同

### umask：为什么你的文件和课件的不一样

| 系统 | umask | 新建文件权限 |
| --- | --- | --- |
| 课件 / CentOS 常见 | `0022` | `666 - 022 = 644`（`rw-r--r--`） |
| 本机 Ubuntu 桌面 | `0002` | `666 - 002 = 664`（`rw-rw-r--`） |

公式：**默认权限 = 满权限 − umask**（文件满 666，目录满 777）。用 `umask` 查看当前值。

## 041 集 · 文件的所有者（课件 10.2）

### 要点

- 一般为**文件的创建者**，谁创建谁就是所有者。
- **查看**：`ls -ahl`（`-a` 隐藏文件、`-h` 人类可读大小、`-l` 列表）。
- **修改**：`chown 用户名 文件名`。
- **只有 root 能改所有者** → 必须 `sudo`。

### 命令

```bash
ls -l apple.txt
sudo chown tom apple.txt      # 只改所有者，属组不变！
sudo chown tom:tom apple.txt  # 用户:组 一起改
sudo chown -R 用户 目录        # 递归
```

### 安全线

**永远不要对系统文件 `chown`**：

```bash
sudo chown cxh /etc/passwd     # ✗ 一敲就把系统搞坏
```

`/etc` 下所有东西的属主都必须是 root。练习只在 `~` 里做。

## 042 集 · 文件/目录的所在组（课件 10.4）

### 要点

- 【课件】**用户创建文件后，文件的所在组就是该用户所在的组**（准确说是创建者的**主组**）。
- **查看**：`ls -ahl`
- **修改**：`chgrp 组名 文件名`

### 课件案例

```bash
groupadd fruit          # 建组
touch orange.txt        # 建文件（属组 = 创建者主组）
ls -l orange.txt        # 看当前属组
chgrp fruit orange.txt  # 改成 fruit
```

### 那个“不需要 sudo”的例外

> 普通用户可以把**自己的文件**改到自己**所属的组**，不需要提权。

```bash
chgrp sudo ~/apple.txt     # 你在 sudo 组里 → 直接成功，不用 sudo
```

### 副作用提醒

改属组 = 改变“谁能动这个文件”。把文件组设成 `sudo`，就意味着 **sudo 组所有成员都能写它**。

## 043 集 · 改变用户所在的组（课件 10.5–10.6）

### 要点

- 【课件】`usermod -g 新组名 用户名` 改变用户所在组（案例：把 zwj 改到 wudang 组）。
- 【课件】`usermod -d 目录名 用户名` 改变用户登录的初始目录，**用户需要有进入新目录的权限**。
- 【课件】10.5 其它组：除所有者和所在组用户外，系统其它用户都是“其它组”。

### 三个参数必须分清

| 参数 | 作用 | 风险 |
| --- | --- | --- |
| `-g 组` | 改**主组**（只有一个，决定新建文件属组） | 低 |
| `-G 组1,组2` | **替换**全部附加组 | **高**：不带 `-a` 会把人踢出 sudo 等组 |
| `-aG 组` | **追加**一个附加组 | 低（推荐） |
| `-d 目录` | 只改登记的家目录路径 | 中：不搬文件 |
| `-d 目录 -m` | 连文件一起搬 | **高**：移动整个家目录 |

### 实操记录

```
$ id tom
uid=1001(tom) gid=1001(tom) 组=1001(tom),100(users)
$ sudo usermod -g fruit tom
$ id tom
uid=1001(tom) gid=1004(fruit) 组=1004(fruit),100(users)     ← 只有主组变了
$ sudo usermod -g tom tom
uid=1001(tom) gid=1001(tom) 组=1001(tom),100(users)
```

**`-g` 只改主组，附加组 `100(users)` 原封不动**。

### 两点注意

1. 改了主组，**对已经登录的会话不生效**，要重新登录。
2. 改主组**不会改变**该用户以前创建文件的属组。

## 附录 A · 本段最重要的机制：三栏只选一个

Linux 判断权限时**从上往下找第一个匹配，命中即停**：

```
① 我是所有者吗？    → 是 → 只看「所有者」那一栏
② 我在所在组里吗？  → 是 → 只看「所在组」那一栏
③ 那我是其它人      → 只看「其它组」那一栏
```

### 实测印证（非常有代表性）

```bash
sudo chown tom apple.txt      # 只改所有者，属组仍是 cxh
ls -l apple.txt
# -rw-rw-r-- 1 tom cxh ...
echo "test" >> apple.txt      # ✅ 竟然还能写！
```

原因：cxh 虽然不是所有者，但**仍在 `cxh` 组里**，走「所在组」的 `rw`，
不会掉到「其它组」的 `r--`。

想真正验证“别人写不了”，必须连组一起改：

```bash
sudo chown tom:tom apple.txt
echo "x" >> apple.txt          # ❌ 权限不够
```

> **权限栏不是叠加的，是互斥选择。** 这是理解整套权限体系的钥匙。

## 附录 C · 自测题（6 道）

1. `ls -l` 输出的前 10 个字符怎么分组？
2. `chown tom file` 之后，文件的属组变了吗？
3. 为什么把文件交给 tom 之后，你**仍然**能写它？
4. 把文件改到自己所属的组，需要 sudo 吗？
5. `usermod -G docker jenny` 有什么风险？正确写法是什么？
6. 你的 umask 是 0002，新建文件权限是几位几？

<details>
<summary>答案</summary>

1. 1 位类型 + 3 位所有者 + 3 位所在组 + 3 位其它组。
2. **没有变**，chown 只改所有者。要一起改用 `chown 用户:组`。
3. 属组还是 `cxh`，你仍在组里，命中「所在组」的 `rw` 栏。
4. 不需要（前提是自己的文件 + 自己所属的组）。
5. 会**替换**掉 jenny 原有的全部附加组（含 sudo），把人踢出管理员。正确写法 `-aG`。
6. `666 - 002 = 664`，即 `rw-rw-r--`。

</details>

## 附录 D · 本段踩的坑

| 现象 | 原因 |
| --- | --- |
| `chown tom a.txt` 后自己还能写 | 属组没变；三栏是互斥选择，命中了「所在组」 |
| 文件权限 664 而课件是 644 | umask 不同（0002 vs 0022） |
| `chorgp` / `chwon` 之类打错 | 命令没有拼写纠正；`command-not-found` 只会给装包建议 |
| 改 `usermod -G` 后用户失去 sudo | `-G` 是替换不是追加，要用 `-aG` |
