## 二、【课件】17.2 Shell 是什么

> **Shell 是一个命令行解释器**，为用户提供向 Linux 内核发送请求以便运行程序的**界面系统级程序**，可以启动、挂起、停止甚至编写程序。

```
你敲回车
   ↓
Shell（bash）   ← 解释器：把 "ls -l" 翻译成系统调用
   ↓ 系统调用
内核            ← 真正干活
   ↓
硬件
```

**Shell 不是内核，它是你和内核之间的翻译官。**

## 三、【课件】17.3 第一个脚本

### 17.3.1 两条格式要求

| # | 要求 |
| --- | --- |
| 1 | 脚本以 **`#!/bin/bash`** 开头（shebang） |
| 2 | 脚本需要有**可执行权限**（⚠️ 只有方式 1 需要） |

### 17.3.2 第一个脚本

```bash
#!/bin/bash
echo "hello,world~"
```

```bash
mkdir -p ~/shcode && cd ~/shcode
vim hello.sh          # 写入上面两行
```

> 课件路径 `/root/shcode`，本机用 **`~/shcode`**

### 17.3.3 两种执行方式 ⭐

| 方式 | 命令 | 需要什么权限 |
| --- | --- | --- |
| ① 路径执行 | `./hello.sh` 或绝对路径 | **必须 `x`** |
| ② 交给 sh | `sh hello.sh` | **只需 `r`** |

### 为什么有这个差别（串起第 10 章）

```
./hello.sh    → 内核直接执行这个文件 → 需要 x 位
sh hello.sh   → sh 把文件当输入读 → 只需要 r 位
```

| 方式 | 用到权限 | 谁在执行 |
| --- | --- | --- |
| `./hello.sh` | **`x`** | 内核（用 shebang 指定的解释器） |
| `sh hello.sh` | **`r`** | `sh` 进程 |

### ⚠️【Ubuntu】`sh 脚本` 有坑：`/bin/sh` 是 dash

| 命令 | 实际解释器 | 结果 |
| --- | --- | --- |
| `./hello.sh` | shebang 指定 → **bash** | ✅ |
| **`bash hello.sh`** | bash | ✅ |
| **`sh hello.sh`** | **dash** | ⚠️ bash 特有语法报错 |

**dash 不支持**：`[[ ]]`、`==`、数组、`function`、`source`（要写 `.`）

**实测：**

```bash
printf '#!/bin/bash\ns=abc\n[[ $s == a* ]] && echo "bash-ok"\n' > ~/shcode/t.sh
bash ~/shcode/t.sh     # → bash-ok
sh   ~/shcode/t.sh     # → [[: not found
```

## 四、【课件】17.4 变量

### 17.4.1 两类变量

| 类型 | 例子 |
| --- | --- |
| **系统变量** | `$HOME` `$PWD` `$SHELL` `$USER` `$PATH` `$?` |
| **用户自定义变量** | 自己 `A=100` |

```bash
set                 # 显示当前 shell 所有变量 + 函数（很长）
set | grep "^A="    # 找自己定义的
```

### 17.4.2 定义的三条语法

| # | 语法 | 说明 |
| --- | --- | --- |
| 1 | `变量名=值` | 定义 |
| 2 | `unset 变量` | 撤销 |
| 3 | `readonly 变量` | 静态变量，**不能 unset 也不能改** |

### ⚠️ 等号两边绝对不能有空格（第一大坑）

| 你写的 | bash 理解成 |
| --- | --- |
| `A=100` | 变量赋值 ✅ |
| `A = 100` | **执行命令 `A`**，参数 `=` 和 `100` ❌ |
| `A= 100` | A 设为空，然后**执行命令 `100`** ❌ |

### 17.4.3 命名规则

| 规则 | 反例 |
| --- | --- |
| 字母/数字/下划线，**不能数字开头** | `5A=200` ❌ |
| 等号两侧不能有空格 | `A = 200` ❌ |
| 习惯用大写（规范） | — |

### 把命令结果赋给变量

```bash
A=`date`      # 反引号（老写法）
A=$(date)     # ⭐ 新写法，可嵌套、不容易被引号搞乱，推荐
```

### 单引号 vs 双引号 ⭐

```bash
A=100
echo A=$A       # A=100
echo "A=$A"     # A=100     双引号：展开（最常用）
echo 'A=$A'     # A=$A      单引号：完全不展开
```

| 引号 | 变量展开 | 用途 |
| --- | --- | --- |
| 无引号 | 展开，但**空格会拆参数** | 简单输出 |
| **`" "`** | **展开** | **默认用它** |
| `' '` | **不展开** | 要字面量 |

### `${}` 的必要性

```bash
A=100
echo $Abc        # 空（bash 找的是变量 Abc）
echo ${A}bc      # 100bc ✅
```

### `readonly` 的局限

```bash
readonly B=2
unset B      # ❌ 无法取消只读变量
B=3          # ❌ 只读变量
exit         # 退出后重开 shell → B 就没了（变量是会话级）
```

## 五、【课件】17.5 设置环境变量

### 17.5.1 三条语法

| # | 语法 | 功能 |
| --- | --- | --- |
| 1 | **`export 变量名=变量值`** | 把 shell 变量**输出为环境变量/全局变量** |
| 2 | **`source 配置文件`** | 让修改后的配置**立即生效** |
| 3 | `echo $变量名` | 查询 |

### 🔑 普通变量 vs 环境变量的真正区别

```bash
A=100
env | grep -c "^A="              # 0   —— 不在环境变量里
bash -c 'echo 子进程: [$A]'       # []  —— 子进程看不到

export A
env | grep -c "^A="              # 1   ✅
bash -c 'echo 子进程: [$A]'       # [100] ✅
```

| | 普通变量 `A=100` | 环境变量 `export A=100` |
| --- | --- | --- |
| 当前 shell | ✅ | ✅ |
| **子进程** | ❌ | ✅ |
| `set` 里 | ✅ | ✅ |
| `env` 里 | ❌ | ✅ |

**`export` 的作用 = 把变量的可见范围从「我」扩大到「我和我所有后代」。**

### 17.5.2 课件的三步

1. 在 `/etc/profile` 定义 `TOMCAT_HOME`
2. 查看
3. 在另一个 shell 程序里使用（**注意先 `source /etc/profile`**）

```bash
sudo vim /etc/profile
# 末尾加：
export TOMCAT_HOME=/opt/tomcat

source /etc/profile
echo "$TOMCAT_HOME"                 # /opt/tomcat
bash -c 'echo 子进程: $TOMCAT_HOME'   # /opt/tomcat
```

### ⭐ `source` 和 `bash` 的本质区别

| 命令 | 是否新建进程 | 变量留在哪 |
| --- | --- | --- |
| **`source 文件`**（= `. 文件`） | **不新建** | **当前 shell** ✅ |
| `bash 文件` | 新建子 shell | 子 shell（退出即消失）❌ |
| `./文件`（有 x） | 新建子 shell | 同上 |

```bash
B=hello
bash -c 'B=changed; echo 子shell: $B'   # changed
echo "父shell: $B"                       # hello ← 子 shell 改不到父
```

**`source` 的本质：不新建进程，在当前 shell 里“就地执行”。**

## 六、⚠️【Ubuntu】两个大坑（实测踩过）

### 坑 ①：桌面版新终端**不读** `/etc/profile`

Ubuntu 桌面图形界面开的终端是**非登录 shell**，只读：

```
~/.bashrc  →  /etc/bash.bashrc
```

**不读** `/etc/profile`、`~/.profile`。

```bash
source /etc/profile
echo $TOMCAT_HOME        # ✅ 当前终端有
# 新开一个终端窗口
echo $TOMCAT_HOME        # ❌ 空
```

| 目标 | 写在哪 |
| --- | --- |
| 当前终端生效 | `source /etc/profile` |
| 所有用户新终端生效 | `/etc/bash.bashrc` 或 `/etc/profile.d/xxx.sh` |
| **自己用户新终端生效（最常用）** | **`~/.bashrc`** |

### 坑 ②：`source /etc/profile` 有连带副作用

Ubuntu 的 `/etc/profile` 里有：

```bash
if [ "${PS1-}" ]; then
  if [ "${BASH-}" ] && [ "$BASH" != "/bin/sh" ]; then
    if [ -f /etc/bash.bashrc ]; then
      . /etc/bash.bashrc          # ⭐ 又 source 了 bash.bashrc
    fi
  fi
fi
umask 022                          # ⭐ 还改了 umask
```

**后果两个：**

| 现象 | 原因 |
| --- | --- |
| **绿色提示符消失** | `/etc/bash.bashrc` 里有 `PS1='\u@\h:\w\$ '`（**non-color**），把彩色 PS1 覆盖了 |
| **`umask` 从 `0002` 变 `0022`** | 以后新建文件是 **644** 而不是 664（呼应第 10 章） |

**修复：**

```bash
source ~/.bashrc      # 恢复彩色提示符
umask 002             # 恢复写权限 umask（或新开终端）
```

**教训**：`source` 一个系统级配置文件，它「顺带」执行的每一行都会在你当前 shell 生效。**个人变量写 `~/.bashrc` 最安全。**

## 七、【课件】17.6 位置参数变量

### 17.6.2 四个变量

执行 `./position.sh 100 200 300`：

| 变量 | 含义 | 值 |
| --- | --- | --- |
| **`$0`** | **命令本身**（脚本名） | `./position.sh` |
| **`$1`–`$9`** | 第 1–9 个参数 | `100` / `200` / `300` |
| **`${10}`** | 第 10 个及以后 | ⚠️ **必须大括号** |
| **`$#`** | **参数个数** | `3` |
| **`$*`** | 所有参数，**看成一个整体** | `100 200 300` |
| **`$@`** | 所有参数，**每个区分** | `100` `200` `300` |

### 两个易错点

1. **`$0` 是脚本名，不是第一个参数** —— 数参数从 `$1` 开始
2. **第 10 个参数必须 `${10}`** —— `$10` 会被理解成 `$1` 后面跟字符 `0`

### `$*` vs `$@`（难点）

**不加引号时完全一样**；加引号才分家：

| 写法 | 效果 |
| --- | --- |
| `"$*"` | 合并成一个字符串 `"100 200 300"` |
| `"$@"` | 保留成多个独立参数 |

```bash
for i in "$*"; do echo "【*】$i"; done     # 循环 1 次
for i in "$@"; do echo "【@】$i"; done     # 循环 3 次
```

> **写脚本时几乎永远用 `"$@"`** —— 参数里的空格不会被拆散。

## 八、【课件】17.7 预定义变量

> shell 设计者事先已经定义好的变量，可以直接在脚本中使用。

| 变量 | 含义 |
| --- | --- |
| **`$$`** | **当前进程**的 PID |
| **`$!`** | **最后一个后台运行**进程的 PID |
| **`$?`** | **最后一次执行命令**的返回状态：`0` 成功，非 0 失败 |

### `$$` 的用途

```bash
TMP=/tmp/mydata.$$        # 生成不冲突的临时文件
echo "[$$] 开始备份"       # 日志里标进程号
```

### `$!` 的用途（正好接上上次的坑）

```bash
sleep 300 &
echo "后台 PID = $!"
kill $!
```

> **实战价值**：之前 `sudo -u tom sleep 300 &` 卡死时，如果当时记了 `$!`，就能直接 `kill -9 $!`，不用去 `ps` 里翻。

### `$?` 的用法与陷阱 ⭐

| `$?` | 含义 |
| --- | --- |
| **0** | 成功 |
| **非 0（1–255）** | 失败，数字由命令自己定义 |

| 命令 | 失败码 |
| --- | --- |
| `ls /不存在` | 2 |
| `grep 没找到` | 1 |
| `ping 不通` | 1 |
| 脚本 `exit 5` | 5 |

**⚠️ 陷阱：`echo $?` 会覆盖自己**

```bash
ls /nonexistent
echo "第一次: $?"     # 2  ✅
echo "第二次: $?"     # 0  ❌ 因为上一条 echo 成功了
```

**正确做法：立刻存起来**

```bash
ls /nonexistent
RC=$?                 # ⭐
echo "结果: $RC"
```

### 课件案例 `preVar.sh`

```bash
#!/bin/bash
echo "当前执行的进程id=$$"
/home/cxh/shcode/myshell.sh &        # 课件是 /root/shcode/
echo "最后一个后台方式运行的进程id=$!"
echo "执行的结果是=$?"
```

`$?` 这里反映的是「后台任务**有没有成功启动**」，不是它有没有跑完。

## 十、自测题

1. `#!/bin/bash` 叫什么？作用是什么？
2. `./hello.sh` 和 `bash hello.sh` 分别需要什么权限？为什么？
3. 为什么 Ubuntu 上不要用 `sh 脚本` 跑 bash 脚本？
4. `A = 100`（有空格）会发生什么？为什么？
5. `"$A"` `'$A'` `$A` 三者的输出有什么不同？
6. `export` 的作用？`set` 和 `env` 的区别？
7. `source 文件` 和 `bash 文件` 的本质区别？
8. `$0` `$1` `$#` `$*` `$@` 分别是什么？
9. `$$` `$!` `$?` 分别是什么？
10. 为什么连着两次 `echo $?`，第二次是 0？

<details>
<summary>答案</summary>

1. **shebang**，告诉系统用哪个解释器执行这个文件
2. `./hello.sh` 需要 **`x`**（内核执行文件）；`bash hello.sh` 只需 **`r`**（bash 把文件当输入读）
3. Ubuntu 的 `/bin/sh` 是 **dash**，不支持 `[[ ]]`、数组等 bash 语法
4. bash 会把 **`A` 当命令**执行，`=` 和 `100` 当参数 → `A: 未找到命令`
5. `"$A"` 展开成变量的值；`'$A'` 原样输出 `$A`；`$A` 展开但如果含空格会被拆成多个参数
6. `export` 让变量成为**环境变量**，子进程也可见；`set` 显示所有变量+函数，`env` 只显示环境变量
7. `source` **不新建进程**，在当前 shell 执行（变量留下）；`bash` 新建子 shell（变量随子 shell 消失）
8. `$0` 脚本名；`$1` 第 1 个参数；`$#` 参数个数；`$*` 所有参数视为一个整体；`$@` 所有参数各自独立
9. `$$` 当前进程 PID；`$!` 最后一个后台进程 PID；`$?` 上一条命令的退出码
10. 因为上一条 `echo` 命令本身执行成功了，把 `$?` 覆盖成了 0

</details>
