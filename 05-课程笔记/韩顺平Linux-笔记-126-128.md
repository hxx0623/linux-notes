## 二【课件】22.1 基本介绍

> 通过裁剪现有 Linux 系统（CentOS 7.6），创建属于自己的 minLinux 小系统，可以加深我们对 Linux 的理解。

**「裁剪」不是发明，是"认出哪些不能少"。** 完整桌面系统几十 GB，而 Linux 真正开机必需的只有：内核 + initramfs + 一个最小用户态（systemd + 基本命令）。做完的系统能进 shell、能 `ls`、能 `echo`，但**没有 vim、没有图形、很多命令会报"未找到命令"**。

**这章的价值不在"做出一个能用的系统"（它没法日常用），而在于把"开机"这件事拆成可以验证的零件。**

## 三【课件】22.2 启动流程 6 步（本章理论核心）

| 步 | 课件原文 | 谁在干 | 通俗解释 |
| --- | --- | --- | --- |
| 1 | 通过自检，检查硬件设备有没有故障 | **主板固件**（BIOS/UEFI） | 通电后先摸一遍 CPU、内存、硬盘 |
| 2 | 多块启动盘时，在 BIOS 中选启动磁盘 | **固件** | 按**启动顺序**挑一块盘，挑不到就试下一个 |
| 3 | 启动 MBR 中的 bootloader 引导程序 | **GRUB** | 老式 BIOS 读盘的**前 512 字节**；EFI 则是读 ESP 里的 `.efi` 文件 |
| 4 | 加载内核文件 | **bootloader** | 把内核读进内存，CPU 交给它 |
| 5 | 执行所有进程的父进程、老祖宗 systemd | **内核** | 内核初始化完硬件，启动 **PID 1** |
| 6 | 欢迎界面 | **systemd** | 按配置拉起登录界面/桌面/各项服务 |

### 为什么这 6 步是做迷你系统的地图

要做的东西 = **让这 6 步全部走完的最小文件集合**：

- 第 1、2 步：固件的事，管不了，但**能选**（→ 这就是 EFI/BIOS 那个坑）
- 第 3 步：需要一个装进 512 字节的引导代码（MBR）或一个 `.efi` 文件（EFI）→ **GRUB**
- 第 4 步：需要**内核文件** → `vmlinuz`
- 第 4→5 步之间：需要一个**临时小系统**帮忙挂载根分区 → `initramfs`
- 第 5、6 步：需要 **systemd** 及其配置，加上最基本的 `/bin` `/etc` `/lib`

### 这套流程在 Ubuntu 上的证据（126 集实操，全为只读命令）

```bash
ls -lh /boot/                     # ① 内核+initrd 成对存在
uname -r                          # ② 当前内核版本 7.0.0-42-generic
cat /proc/cmdline                 # ③ GRUB 传给内核的启动参数
ps -p 1 -o pid=,comm=,args=       # ④ PID 1 = systemd /sbin/init
sudo efibootmgr -v                # ⑤ 固件层启动项（EFI 特有）
lsblk -f                          # ⑥ 盘布局
```

实测输出要点：

| 命令 | 实测结果 | 说明 |
| --- | --- | --- |
| `ls /boot` | `vmlinuz-7.0.0-42-generic`(17M) + `initrd.img-7.0.0-42-generic`(78M)，另有 `-38` 旧版 | 新旧两套并存，`.old` 软链是 GRUB 留的退路 |
| `cat /proc/cmdline` | `BOOT_IMAGE=/boot/vmlinuz-7.0.0-42-generic root=UUID=91f76578-…` | **根分区用 UUID 不用 `/dev/sda2`** |
| `ps -p 1` | `1 systemd /sbin/init splash` | CentOS 7 也是 systemd，这一步无差异 |
| `efibootmgr -v` | `BootCurrent: 0005` → `\EFI\ubuntu\shimx64.efi` | 注意是 **shim**，不是 grub（安全启动的壳） |
| `lsblk -f` | `sda1 vfat /boot/efi`、`sda2 ext4 UUID 91f76578-…` | ⑥ 的 UUID 与 ③ 完全一致 → 互证成功 |

> 📌 **上一集那个 `1月 1 1970` 的 `/boot/efi` 不要慌**：vfat 目录的 mtime 会显示成 Unix 纪元起点，正常。

## 四【课件】22.2 加载内核时的两个关键文件

```
kernel 文件   vmlinuz-3.10.0-957.el7.x86_64
initrd 文件   initramfs-3.10.0-957.el7.x86_64.img
```

命名拆解（以 CentOS 7.6 为例）：

| 部分 | 含义 |
| --- | --- |
| `vmlinuz` | 压缩过的内核，**`z` = 压缩**（zImage），几百 MB 压到十几 MB |
| `3.10.0` | 主.次.修订版本号 |
| `957.el7` | 发行版打包版本，`el7` = Enterprise Linux 7 |
| `x86_64` | 64 位 Intel/AMD 架构 |

### initrd / initramfs 为什么必须有（经典面试点）

内核刚进内存时**一个驱动都没有** —— 它不知道根分区在 SAS 盘还是 NVMe 上、是 ext4 还是 xfs，可它又必须先挂上根分区才能启动 systemd。死循环。

解法：先给内核一个**内存里的小文件系统**（initramfs），里面预装了"挂载真正根分区"所需的驱动和工具。内核跑它 → 它找到并挂载真的 `/` → 再把控制权交过去。

> **一句话：initrd 是内核的临时拐杖，用完就扔。**

### Ubuntu 对照

| | 课件（CentOS 7.6） | 本机（Ubuntu 24.04） |
| --- | --- | --- |
| 内核 | `/boot/vmlinuz-3.10.0-957.el7.x86_64` | `/boot/vmlinuz-7.0.0-42-generic` |
| initrd | `/boot/initramfs-…img` | `/boot/initrd.img-7.0.0-42-generic` |
| 软链 | 无 | `vmlinuz → vmlinuz-7.0.0-42-generic`、`vmlinuz.old → -38` |

## 五【课件】22.3 制作思路（5 步）

> 1）加一块硬盘 `/dev/sdb`，分两个分区（`/boot` 和 `/`），格式化。
> 　**需要明确的是**：现在这块盘在现有系统里是 `/dev/sdb`，等全部设置好、拔下来放到新系统上，就是 `/dev/sda`。
> 2）在 `/dev/sdb` 上打造成独立的 Linux 系统，所有文件需要拷贝进去。
> 3）内核不能少，要把内核文件和 initramfs 文件夹一起拷过去。
> 4）完成后，新建一个虚拟机，硬盘指向这块盘，启动即可。
> 5）示意图

### 每步背后的「为什么」

| 步骤 | 为什么 | 踩点 |
| --- | --- | --- |
| 分 2 个区 | `/boot` 独立是为了让 GRUB 能**稳定读到内核**（不被 LVM/加密包住，不会被日常写满） | EFI 路线要**多一个 ESP**（FAT32） |
| **盘符会变** | `sdb` 挪到新机器变 `sda` | **所以配置里绝不能硬写 `/dev/sdb*`，必须用 UUID** |
| 拷所有文件 | `/bin` `/lib` `/etc` `/usr` 一个都不能少，少一个依赖就卡住，而且**往往不给有用报错** | 用 `rsync -aAXH`，不用 `cp`（会丢权限位） |
| 内核单独拷 | 它在 `/boot` 里，不在"整个目录"的清单内；且光拷文件没用，GRUB 配置还得指对 | 别忘了 `/usr/lib/modules/<版本>` |
| 拔到新虚拟机 | ① 不能在运行中的系统上换掉自己的根 ② **只有真机启动成功才算验收** | 新虚拟机固件必须和盘匹配 |

### 计划分区（16G 盘，EFI 版）

```
/dev/sdc  16G  GPT
├─ sdc1   300M   FAT32  → /boot/efi   （ESP，存 .efi 文件，必须标 esp 标志）
├─ sdc2   1G     ext4   → /boot       （内核 + initramfs + grub 配置）
└─ sdc3   剩余   ext4   → /            （整个文件系统）
```

## 七【Ubuntu＋EFI】课件要改哪几处

| 环节 | 课件（CentOS 7.6 + BIOS/MBR） | 本机（Ubuntu + EFI/GPT） |
| --- | --- | --- |
| 分区表 | `fdisk` → **MBR**（最多 4 主分区） | **GPT**，且**必须标 `esp` 标志** |
| 分区数 | **2 个**：`/boot` + `/` | **3 个**：**ESP** + `/boot` + `/` |
| 装 GRUB | `grub2-install /dev/sdb`（写 MBR 前 446 字节） | `grub-install --target=x86_64-efi --efi-directory=… --removable`（**往 ESP 里拷文件，不写引导扇区**） |
| 让固件认它 | 不用管，BIOS 直接读 MBR | ① `efibootmgr -c` 加启动项，或 ② **`--removable` 走兜底路径 `\EFI\BOOT\BOOTX64.EFI`**（选 ②，免配 NVRAM） |
| 盘符 | `sdb` → 挪过去变 `sda` | 本机是 **`sdc` → 挪过去变 `sda`** |

**EFI 兜底路径的原理**：EFI 规范规定，NVRAM 里没有可用启动项时，固件要对每块盘尝试 `\EFI\BOOT\BOOTX64.EFI`。所以 U 盘装的 Linux 插到任何电脑都能引导 —— 用的就是这个约定。

## 八【补充】完整施工流程（阶段 0–12，可复用）

> 以下流程已在 2026-11-06 实测跑通，产出一块能独立启动的 16G EFI 系统盘。

### 阶段 0｜先拍快照

VMware → 虚拟机 → 快照 → 拍摄快照。**后面 `fdisk`/`mkfs`/`rsync` 一旦敲错设备名就是灭顶之灾。**

### 阶段 1｜加一块 16G 盘（关机加，最稳）

创建新虚拟磁盘 → 16 GB → **不要**勾"立即分配所有磁盘空间"（稀疏分配，不写不占地方）。

⛔ 检查点：`lsblk` 看到约 16G 的空盘（本次是 `sdc`，`sdb` 已被 `/newdisk` 占用）。

### 阶段 2｜分区：GPT + 三分区

```bash
sudo fdisk /dev/sdc
#   g    新建 GPT 分区表
#   n    分区1，起始回车，+300M
#   n    分区2，起始回车，+1G
#   n    分区3，起始回车，结束回车（用满剩余）
#   p    核对
#   w    写入

sudo parted /dev/sdc set 1 esp on      # ⚠️ 必须标 esp，否则固件不认这是 ESP
```

### 阶段 3｜格式化

```bash
sudo mkfs.vfat -F 32 -n ESP   /dev/sdc1
sudo mkfs.ext4 -L MINI-BOOT   /dev/sdc2
sudo mkfs.ext4 -L MINI-ROOT   /dev/sdc3
lsblk -f /dev/sdc              # 核对：vfat/ESP、ext4/MINI-BOOT、ext4/MINI-ROOT
```

### 阶段 4｜按"将来 / 的样子"挂载

```bash
sudo mkdir -p /mnt/mini
sudo mount /dev/sdc3 /mnt/mini
sudo mkdir -p /mnt/mini/boot
sudo mount /dev/sdc2 /mnt/mini/boot
sudo mkdir -p /mnt/mini/boot/efi
sudo mount /dev/sdc1 /mnt/mini/boot/efi
findmnt -R /mnt/mini           # ⛔ 三层都要在
```

### 阶段 5｜抄下三个 UUID

```bash
sudo blkid /dev/sdc1 /dev/sdc2 /dev/sdc3
```

**本次实测值**（这块盘专用，记下来方便以后核对）：

| 分区 | 文件系统 UUID | PARTUUID（**不是它！**） |
| --- | --- | --- |
| `sdc1` ESP | **`1676-E9EE`** | `5dfc4341-e362-4e95-a9a0-65924b9f5254` |
| `sdc2` /boot | **`780084d7-1692-4327-981f-a2f213b66b87`** | `6cb8a26d-b86c-462e-80ce-e98808cbeb03` |
| `sdc3` / | **`9c09b34a-e011-4fb9-87d3-448ce78ea850`** | `7912cdc9-7c6a-4f65-982e-2ecd1449e12c` |

> 🔴 **`UUID` 和 `PARTUUID` 是两个不同的东西**：前者刻在文件系统里（`mkfs` 生成），后者刻在分区表里（分区时生成）。fstab 写 `UUID=` 就必须用左边那列。

### 阶段 6｜拷文件（本例实拷 5.2G，用 58 秒）

```bash
sudo rsync -aAXH --info=progress2 \
  --exclude='/proc/*'  --exclude='/sys/*'  --exclude='/dev/*'  --exclude='/run/*' \
  --exclude='/tmp/*'   --exclude='/mnt/*'  --exclude='/media/*' --exclude='/snap/*' \
  --exclude='/lost+found' --exclude='/newdisk/*' --exclude='/swap.img' \
  --exclude='/home/*'  --exclude='/boot/*' \
  --exclude='/var/log/*' --exclude='/var/cache/*' --exclude='/var/tmp/*' \
  --exclude='/var/lib/snapd/*' --exclude='/var/lib/docker/*' \
  --exclude='/usr/share/doc/*'  --exclude='/usr/share/man/*'   --exclude='/usr/share/locale/*' \
  --exclude='/usr/share/icons/*' --exclude='/usr/share/fonts/*' --exclude='/usr/share/themes/*' \
  / /mnt/mini/
```

排除项的理由（**每条都能讲出来，别删**）：

| 排除 | 理由 |
| --- | --- |
| `/proc /sys /dev /run` | **不是真文件**，是内核虚拟出来的，必须在新系统启动时自己生成 |
| **`/swap.img`** | 本机 swap 是 **4 GB 文件**，排除能省 4G；mini 系统不需要 swap |
| `/snap/*`、`/var/lib/snapd/*` | snap 应用，几个 G |
| `/home/*` | 个人文件，不带 |
| `/var/log /var/cache /var/tmp` | 垃圾 |
| `/usr/share/doc /man /locale /icons /fonts /themes` | 文档字体图标，能省 1G 以上 |
| **`/boot/*`** | 内核文件下一步**单独**拷 |

> 💡 `-aAXH` 四个字母：`-a` 权限/属主/时间戳、`-A` ACL、`-X` 扩展属性、`-H` 硬链接。**少了 `-a` 会丢 `x` 权限，连 bash 都执行不了** —— 所以拷系统目录从不用 `cp`。

### 阶段 7｜单独拷内核 + initramfs

```bash
sudo cp -av /boot/vmlinuz-$(uname -r)     /mnt/mini/boot/
sudo cp -av /boot/initrd.img-$(uname -r)  /mnt/mini/boot/
sudo ls /mnt/mini/usr/lib/modules/        # ⛔ 必须有同版本目录！
```

**90% 的失败卡在这**：少了 `/usr/lib/modules/<版本>`，开机时所有驱动加载不了，卡在 initramfs。

> Ubuntu 的 `/lib` 是指向 `usr/lib` 的软链（usrmerge），`rsync -a` 会原样保留。

### 阶段 8｜写 fstab（UUID 版）

```bash
sudo tee /mnt/mini/etc/fstab > /dev/null <<'EOF'
# <设备>                                  <挂载点>   <类型>  <选项>     <dump> <pass>
UUID=1676-E9EE                            /boot/efi  vfat    defaults   0      0
UUID=780084d7-1692-4327-981f-a2f213b66b87  /boot      ext4    defaults   0      2
UUID=9c09b34a-e011-4fb9-87d3-448ce78ea850  /          ext4    defaults   0      1
EOF

echo mini01 | sudo tee /mnt/mini/etc/hostname
sudo tee /mnt/mini/etc/hosts > /dev/null <<'EOF'
127.0.0.1  localhost
127.0.1.1  mini01
EOF
```

**⛔ 关键验证：让系统自己翻译一遍**

```bash
findfs UUID=1676-E9EE                            # 期望 /dev/sdc1
findfs UUID=780084d7-1692-4327-981f-a2f213b66b87  # 期望 /dev/sdc2
findfs UUID=9c09b34a-e011-4fb9-87d3-448ce78ea850  # 期望 /dev/sdc3
```

`findfs` 就是 `mount` 用来把 `UUID=` 翻成设备名的那个工具 —— **它认得，开机就认得**。报 `unable to resolve` 就说明那条还是错的。

### 阶段 9｜chroot 里装 GRUB（EFI 方式）

```bash
sudo mount --bind /dev     /mnt/mini/dev
sudo mount --bind /dev/pts /mnt/mini/dev/pts
sudo mount --bind /proc    /mnt/mini/proc
sudo mount --bind /sys     /mnt/mini/sys
sudo chroot /mnt/mini /bin/bash
```

chroot 内：

```bash
grub-install --target=x86_64-efi --efi-directory=/boot/efi \
             --bootloader-id=mini --removable --no-nvram
# 成功输出：Installing for x86_64-efi platform. / Installation finished. No error reported.

update-grub
systemctl set-default multi-user.target    # 直接进文本登录，不拉 GNOME
exit
```

| 参数 | 作用 |
| --- | --- |
| `--target=x86_64-efi` | 装 EFI 版 GRUB（课件是 `grub2-install /dev/sdb` 写 MBR，完全不同） |
| `--removable` | 装到 ESP 的 `\EFI\BOOT\BOOTX64.EFI` 兜底路径，**免配 NVRAM** |
| `--no-nvram` | 不往主板 NVRAM 写启动项（chroot 里写了也是写到旧机器上） |

**chroot 里改动的是"新盘上的系统"，不是你原来的系统** —— 这就是安装程序干的事。

### 阶段 10｜验证后卸载、拔盘

```bash
sudo ls -l /mnt/mini/boot/efi/EFI/BOOT/          # 要看到 BOOTX64.EFI
sudo grep -m2 'root=UUID' /mnt/mini/boot/grub/grub.cfg
# ⛔ 输出的 UUID 必须 = sdc3 的 9c09b34a-…
sudo umount -R /mnt/mini
```

> ⚠️ `grub.cfg` 里写的是 `linux /vmlinuz-…` 而**不是** `/boot/vmlinuz-…` —— 这是对的！因为 `/boot` 是独立分区，配置里的路径相对于 `/boot` 分区。

然后**彻底关机**（不是挂起），虚拟机设置里 → 那块 16G 盘 → **移除（Remove）**。
> 🔴 **绝不能选「从磁盘中删除 / Delete from disk」** —— 移除只是断开引用，删除会毁掉整块盘。

### 阶段 11｜新建虚拟机指向这块盘

1. 虚拟机 → 新建 → **自定义**
2. 稍后安装操作系统（别挂 ISO）
3. Linux → Ubuntu 64 位
4. 固件类型：**🔴 UEFI**（和盘匹配）
5. 虚拟磁盘 → **使用现有虚拟磁盘** → 选中那个 `.vmdk`
6. 问"复制/转换/保留" → **保留现有格式**

> ⚠️ 同一块盘不能同时出现在两台虚拟机里；同一台虚拟机里也不能出现两次，否则报**"另一个程序已锁定文件的一部分"**。

### 阶段 12｜验收

成功标志：

```
Ubuntu 24.04.5 LTS mini01 tty1

mini01 login:
```

用 `cxh` + 原密码登录（`/etc/shadow` 是拷过去的）。然后：

```bash
uname -r          # 7.0.0-42-generic
hostname          # mini01
lsblk             # ⭐ 这次是 sda！sda1=ESP sda2=/boot sda3=/
df -h /           # 15G，用了约 5G
systemctl --failed
```

**`sda` 而不是 `sdc`** —— 22.3 那句"盘符会变"的现场直播。而全程用 UUID，所以毫发无伤。

## 九 这次踩的坑（含排查方法）

### 坑 1｜fstab 抄成了 PARTUUID

`blkid` 一行里同时有 `UUID="…"` 和 `PARTUUID="…"`，抄了后面那个 → 开机时 `/boot` 挂不上 → emergency mode（本次在 chroot 阶段就发现，未上线）。
**根治**：改完 fstab 用 `findfs UUID=<值>` 让系统自己翻译。

### 坑 2｜`rsync` 排除项漏了 `/boot/*`

结果整个 `/boot`（两个内核 + memtest86+ + **宿主真实的 `/boot/efi`**）都被搬过去，还多了个 `EFI/ubuntu/` 目录（10 月 21 日的宿主启动文件）。
**无害但说明一件事**：拷完必须核对 `du -sh` 和内容，不能只看"跑完了"。

### 坑 3｜装完 GRUB 直接拔盘，没验证

第一次启动 → **PXE 网络启动死循环**：

```
PXE-E51: No DHCP or proxyDHCP offers were received
PXE-M0F: Exiting Intel PXE ROM
Operating System not found        ← 反复循环
```

**含义**：固件把所有设备试了一遍，没有能启动的。排查顺序 → ① 固件类型对不对 ② 盘在不在 ③ **ESP 里到底有没有引导文件**（最常被跳过的一步）。

> 📌 有个很好用的查法：`D:\VMs\<虚拟机名>\vmware.log` 里搜 `About to do EFI boot`，能看到固件到底试了哪些设备；搜 `DISKUTIL` 能看到盘容量是否认对。

### 坑 4｜同一块盘被登记了三次 → 文件锁

`vmx` 配置文件里出现 `scsi0:0` 和 `scsi0:1` 指向**同一个 vmdk**，旧虚拟机里还有 `scsi0:2` → 报"另一个程序已锁定文件的一部分"。
**规则**：一块盘同一时刻只能属于一台虚拟机；一台虚拟机里只能出现一次。

### 坑 5｜GRUB 装好了，但开机直接掉进 `grub>` 救援提示符

```
GNU GRUB version 2.12
grub>
```

**这跟 PXE 循环是两回事**：PXE 是"固件找不到引导文件"，`grub>` 是"**引导程序起来了，但找不到自己的配置文件**"。后者是进展，不是退步。

排查三连（在 `grub>` 里直接测）：

```
echo $prefix        # GRUB 到底去哪个目录找配置  ← 决定性证据
echo $root          # 当前根设备
search --fs-uuid <UUID>   # 搜索功能是否正常（能返回 hdX,gptY 就是好的）
```

**本次真相**：

```
$prefix = (hd0,gpt1)/boot/grub     ← GRUB 去 ESP 上的 /boot/grub/ 找
我们把 grub.cfg 放在了  /EFI/BOOT/  ← 目录差了一级，改了三次都没用
```

**推理方法（很实用）**：跳板第一行是 `set root=(hd0,gpt2)`，如果它被执行了，`echo $root` 就该是 `hd0,gpt2`；实测是 `hd0,gpt1` → **说明文件根本没被执行过**。

### 坑 6｜修法：在 `$prefix` 真正的路径放一个"两行跳板"

```bash
sudo mkdir -p /boot/efi/boot/grub
sudo tee /boot/efi/boot/grub/grub.cfg > /dev/null <<'EOF'
set root=(hd0,gpt2)
configfile /grub/grub.cfg
EOF
sudo sed -i 's/\r$//' /boot/efi/boot/grub/grub.cfg   # 防 Windows CRLF
sudo cat -A /boot/efi/boot/grub/grub.cfg             # 行尾必须是 $，不是 ^M$
```

**为什么这样就行**：GRUB 读 `$prefix/grub.cfg` → 这个两行文件 → `set root=(hd0,gpt2)` → `configfile /grub/grub.cfg` → 读到 `/boot` 分区上的真菜单 → 菜单项自己 `search --fs-uuid` 找到内核 → 启动。

**为什么用"地址"而不是"UUID 搜索"**：`set root=(hd0,gpt2)` 只需要 GPT 分区表解析（已内置），零依赖；UUID 搜索要多绕几层，任何一环出错都失败。**修引导时，能用地址就别用号码。**

**残留脆弱点**：写死了 `hd0,gpt2`。若盘变成 `hd1` 或前面插了别的盘，就得改数字。备用写法：

```
search --no-floppy --fs-uuid --set=root 780084d7-1692-4327-981f-a2f213b66b87
configfile /grub/grub.cfg
```

### 坑 7｜开机后一堆红色 `Failed to start`（正常）

12 个失败单元，全部是**裁剪的必然代价**：

| 失败单元 | 原因 |
| --- | --- |
| 10 个 `snap-*.mount` | 排除了 `/snap` 和 `/var/lib/snapd`，挂载点没东西可挂 |
| `apparmor.service` | 要给这些 snap 应用套策略，目录没了 |
| `NetworkManager-wait-online.service` | 等"网络完全就绪"，虚拟机里等不到 |

它们**不参与开机到登录的必要链条**。想清理（可选）：

```bash
sudo systemctl disable --now snapd.service snapd.socket 2>/dev/null
sudo rm -f /etc/systemd/system/snap-*.mount
sudo systemctl daemon-reload && sudo systemctl reset-failed
sudo systemctl disable NetworkManager-wait-online.service
```

### GRUB 救援备忘（真机上同样适用）

```text
ls                                    # 列出所有设备
ls (hd0,gpt2)/                        # 找哪个分区里有 vmlinuz，那个就是 /boot
set root=(hd0,gpt2)
configfile /grub/grub.cfg             # 手动加载菜单
# 或者直接手打内核：
linux /vmlinuz-7.0.0-42-generic root=UUID=9c09b34a-… ro

```

## 十 故障对照表（下次直接查）

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 新虚拟机报 `no bootable device` | 固件是 BIOS（盘是 EFI/GPT），或 ESP 没标 `esp` | 改 UEFI；回旧系统 `parted /dev/sdX set 1 esp on` 后重装 GRUB |
| **PXE 循环** | 固件找不到任何引导文件 | 查固件类型 / 盘是否挂上 / ESP 里有没有 `.efi` |
| **`grub>` 救援提示符** | GRUB 找不到 `$prefix/grub.cfg` | `echo $prefix` 看它找哪，把配置放到那儿 |
| `error: cannot find EFI directory` | chroot 里 `/boot/efi` 没挂上 | 退出，`findmnt -R` 检查后重挂 |
| 卡在 `(initramfs)` | 根 UUID 错，或 `/usr/lib/modules` 没拷 | 提示符里敲 `blkid` 对照；模块回旧系统补拷 |
| `emergency mode` | fstab 里有挂不上的条目 | 给 root 密码进去，`cat /etc/fstab` 逐个对 `blkid` |
| `另一个程序已锁定文件的一部分` | 同一 vmdk 被挂了多次 | 每台虚拟机只留一处引用 |

**救砖总原则**：任何一步失败，**原来的 Ubuntu 一点没坏**。把盘加回去、挂到 `/mnt/mini`、修完再挪出来，可无限重试。这也是"用虚拟机学 Linux"最大的价值。

## 十一 自测题

1. Linux 启动流程 6 步，第 3 步和第 4 步分别谁在干活？EFI 和 BIOS 在这一步有什么不同？
2. `vmlinuz` 里的 `z` 是什么？内核为什么要压缩？
3. initramfs 是干什么的？没有它会怎样？
4. 为什么 fstab 和 GRUB 都写 `UUID=` 而不写 `/dev/sda2`？
5. `blkid` 里的 `UUID` 和 `PARTUUID` 有什么区别？fstab 写 `UUID=5dfc4341-…`（实际是 PARTUUID）会怎样？
6. EFI 路线比课件（BIOS/MBR）多需要哪样东西？它为什么必须是 FAT32？
7. `grub-install --removable` 做了什么？为什么它能免配 NVRAM？
8. 开机掉进 `grub>` 和陷入 PXE 循环，哪一个更接近成功？为什么？
9. 在 `grub>` 里 `echo $root` 显示 `hd0,gpt1`（ESP），说明了什么？
10. 拷系统目录为什么用 `rsync -aAXH` 而不用 `cp -r`？

<details>
<summary>答案</summary>

1. 第 3 步 **GRUB**（bootloader），第 4 步 **bootloader 加载内核**。BIOS 读盘的**前 512 字节**（MBR 引导代码）；EFI 读 **ESP 分区里的 `.efi` 文件**（本机是 `\EFI\ubuntu\shimx64.efi`），不碰引导扇区。
2. **压缩**（zImage）。内核体积大，压缩后塞得进小空间，由 bootloader 加载时解压。
3. 一个**内存里的小文件系统**，装好了"挂载真正根分区"所需的驱动和工具。没有它，内核不知道根分区在哪、用什么文件系统，会在挂载根之前卡死（掉进 initramfs 提示符）。
4. 设备名随位置变（`sdc` 挪到新机器变 `sda`，加盘/换接口也会变），**UUID 刻在文件系统里，盘怎么挪都不变**。
5. `UUID` 是**文件系统**的身份证（`mkfs` 生成，ESP 是 `1676-E9EE` 这种短格式）；`PARTUUID` 是**分区表**的身份证（分区时生成）。fstab 写 `UUID=<PARTUUID>` → 系统拿它找文件系统，找不到 → 该挂载点失败 → 常掉进 emergency mode。
6. **ESP 分区**（EFI System Partition）。必须是 FAT32，因为**固件的文件系统驱动极简，只认 FAT**；而且它要被 Windows/Linux 共享。
7. 把 GRUB 装到 ESP 的 `/EFI/BOOT/BOOTX64.EFI`（**可移除介质兜底路径**），而不是 `/EFI/ubuntu/`。因为 EFI 规范规定"找不到有效启动项时，固件会对每块盘尝试这个固定路径"，所以不用往 NVRAM 写启动项。
8. **`grub>` 更接近成功** —— 说明固件已找到并运行了引导程序，只差配置文件；PXE 循环说明固件连可启动文件都没找到。
9. 说明 **`set root=(hd0,gpt2)` 那句没被执行过**（否则 root 会是 gpt2），即 GRUB 根本没读过那个文件 —— 于是要去查 `$prefix` 指向哪。
10. `-a` 保留权限/属主/时间戳、`-A` ACL、`-X` 扩展属性、`-H` 硬链接。`cp -r` 会丢失 ACL 等信息，**少了 `x` 位连 `/bin/bash` 都执行不了**。

</details>

## 十二 一句话总结

> **造一块能自己开机的盘 = ① 分对分区（EFI 要多一个 ESP 并标 `esp`）→ ② 用 `rsync -aAXH` 拷最小文件集（排除 `swap.img` 和虚拟目录）→ ③ 单独拷 `vmlinuz`/`initramfs`/`modules` → ④ fstab 用 **文件系统 UUID**（并用 `findfs` 验证）→ ⑤ chroot 里 `grub-install --target=x86_64-efi --removable` + `update-grub` → ⑥ 拔盘挂到新虚拟机（固件也必须 UEFI）→ ⑦ 看到 `mini01 login:` 才算通关。**

**这段最值钱的不是"做出了一个系统"，是学会了三件事**：
1. **启动链每一环都能单独验证**（`efibootmgr` / `$prefix` / `$root` / `search`）
2. **报错提示符长得像，含义完全不同**（PXE 循环 vs `grub>`）
3. **先确认"对方实际在找什么"，再动手改**（`$prefix`、`blkid` 的列名、`lsblk -f` 的列名 —— 全都是这一类）
