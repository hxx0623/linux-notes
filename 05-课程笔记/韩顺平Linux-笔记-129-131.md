## 四【课件】23.2.2 阅读内核源码的四条技巧

| # | 课件原话 | 解释 |
| --- | --- | --- |
| 1 | 阅读需要懂 **C 语言** | 内核几乎全是 C + 少量汇编（启动、中断入口、页表操作这类非汇编不可的地方） |
| 2 | 阅读前应知道**整体分布**。现代 OS 由**进程管理、内存管理、文件系统、驱动程序、网络**组成，各目录大致与之对应 | 见下面那张表 |
| 3 | 阅读方法有**纵向与横向**之分。纵向＝顺着执行顺序；横向＝按模块。**经常结合使用** | ⭐ **最实用的一条** |
| 4 | 启动代码顺着启动顺序读；内存管理可以单独拿出来读。**反复的过程，不可能读一遍就理解** | 别指望一遍懂 |

### 模块 ↔ 目录对应（课件说"大致对应"但没给表，这里补全）

| 内核子系统 | 管什么 | 目录 |
| --- | --- | --- |
| **进程管理** | 创建/调度/消灭进程，CPU 时间怎么分 | `kernel/` |
| **内存管理** | 分页、地址映射、回收 | `mm/` |
| **文件系统** | VFS 抽象 + ext4/xfs/fat 实现 | `fs/` |
| **驱动程序** | 显卡、网卡、磁盘、USB | `drivers/`（**现代内核体积最大，占一半以上**） |
| **网络** | TCP/IP 协议栈 | `net/` |

> **这张表比任何命令都有用**：以后想知道"某个现象归谁管"（磁盘 IO 卡住 → `block/` + `drivers/`；进程 `D` 状态 → `kernel/` + IO 等待），它就是地图。

### 纵向 / 横向，具体长什么样

```
纵向（跟执行顺序）                    横向（按模块）
开机 → 引导 → 内核入口                只读 mm/ 一个目录
 → 内存初始化                        看它怎么分配页、怎么换出
 → 中断/时钟/设备初始化                看 memory.c / page.s
 → 启动第一个进程
```

- **启动代码必须纵向**：价值就在顺序里，少一步后面全崩
- **内存管理适合横向**：自成体系、代码量大，顺读反而看不到全貌

## 五【补充】linux 0.01 的真实目录结构（实测）

```
linux/
├── boot/        引导：boot.s、head.s（实模式 → 保护模式切换）
├── fs/          文件系统：buffer、inode、namei、open、read_write、super…
├── include/     头文件：linux/、asm/、sys/
├── init/        ★ main.c —— 内核入口
├── kernel/      进程管理核心：fork、exit、sched、signal、panic、printk、
│                system_call、traps、vsprintf
├── lib/         小工具函数：ctype、string、errno、wait、write
├── mm/          内存管理：memory.c、page.s
├── tools/       build.c（构建辅助）
└── Makefile     ⭐ 课件没提，但 0.01 时代就已经用 make 了（1 万行手工 gcc 不现实）
```

**实测 `ls -F linux`**：8 个目录 + `Makefile`，**88 个文件**。

**实测 `ls linux/mm`**：`Makefile`、`memory.c`、`page.s` —— 只有 3 个，印证"0.01 的内存管理还很简陋"。

**实测 `wc -l linux/boot/head.s`**：**175 行**。

> 🔑 **175 行汇编，是整个系统的地基** —— GDT/IDT、页目录、页表、栈切换全在这里。
> **它解释了一件重要的事**：`main()` 第一行是 `time_init()` 而不是"内存初始化"，因为**轮到 C 代码执行时，内存分页已经能用了**。
> **最底层的活，永远是汇编干的。**

## 六【补充】`init/main.c` 逐段拆解（本集核心，实测 147 行）

### 6.1 先看规模

```bash
wc -l linux/init/main.c      # 147
```

**整个内核的入口文件，147 行。** "内核"给人的恐怖感一大半来自体量，而不是难度 —— 入口这件最重要的事反而极简，**因为复杂的东西都被它调用了**。

### 6.2 用 grep 定位，不逐行读（这正是"面对不认识的代码"的正确姿势）

```bash
grep -n "_init(" linux/init/main.c
```

实测输出（**注意要分清三类**）：

| 行 | 内容 | 是 |
| --- | --- | --- |
| 40 | `extern void hd_init(void);` | **声明**（实现在别处） |
| 58 | `static void time_init(void)` | **定义**（函数体在本文件） |
| 85 | `time_init();` | **调用** |
| 86 | `tty_init();` | 调用 |
| 87 | `trap_init();` | 调用 |
| 88 | `sched_init();` | 调用 |
| 89 | `buffer_init();` | 调用 |
| 90 | `hd_init();` | 调用 |

**只有 85–90 六行在"干活"。** 而比 `main()` 早 27 行的 58 行，是 `time_init()` 的**定义** —— 一个文件里同时有"入口"和"某个初始化函数的实现"，这不奇怪，老代码就是紧凑。

### 6.3 一个反直觉的发现：**`_init(` 里没有内存**

0.01 的内存初始化**内联写在 `main()` 里**（更准确地说：分页早在 `head.s` 搭好了，`main()` 里的内存相关活很少），**没有包成 `mem_init()` 函数**。到 **0.11** 才拆出独立的 `mem_init()`。

> 📌 **教训："搜不到 ≠ 不存在"。** `grep "_init("` 找不到内存，不代表没做内存初始化 —— **只是它没用这个命名。**

### 6.4 `BCD_TO_BIN` 宏 —— 位运算的真实用途

```c
#define BCD_TO_BIN(val) ((val)=((val)&15) + ((val)>>4)*10)
```

**CMOS 时钟芯片存的是 BCD 编码**：高 4 位放十位、低 4 位放个位。

```
BCD 的 0x45 → 意思是"45"（秒）
            但机器读出来是十六进制 0x45 = 十进制 69  ← 必须转换

&15  → 低 4 位 = 5（个位）
>>4  → 高 4 位 = 4（十位）→ 4*10 = 40
5 + 40 = 45 ✅
```

> **第 17 章学的 `&`、`>>` 不是考试题** —— 它是处理硬件寄存器时唯一能用的办法。**硬件给你的是"位"，不是"数字"。**

### 6.5 `time_init()` —— "重复直到一致"的经典模式

```c
do {
    time.tm_sec = CMOS_READ(0);
    time.tm_min = CMOS_READ(2);
    ... 全部读一遍 ...
} while (time.tm_sec != CMOS_READ(0));
```

**为什么读完要回头再读一次秒？** 你读顺序的某一瞬间，时钟正好从 `…:59` 跳到 `…:00` —— 你拿到的是"秒是 59、分是上一分钟的"这种**半新半旧的错数据**。

解法：读完后**再核对一次秒**。秒变了 → 中途跨过边界 → **整组作废重来**。

> 这个模式叫 **read twice / 双读校验**。读 RTC、读多字节配置、读传感器、读数据库一致快照 —— **凡是"一组数据必须同时有效"的地方都要它**。

### 6.6 `void main(void)` 的两行注释 —— 作者在提前吵架

```c
void main(void)      /* This really IS void, no error here. */
{                    /* The startup routine assumes (well, ...) this */
```

| 对比 | 普通程序 | 内核 |
| --- | --- | --- |
| `main` 返回 | `int`（有 OS 等你的退出码） | **`void`**（没有调用者，`head.s` 一条 `call main` 进来，返回给谁？） |

> 翻译：作者在说 **"我真的就是想返回 void，别报这错。"**
> 现代内核一样：`start_kernel(void)` 前面挂着 `asmlinkage __visible void __init __noreturn` —— **别指望它返回。**

### 6.7 六行初始化的顺序**不能乱** —— 关键在 `sti()` 的位置

```c
/* Interrupts are still disabled. Do necessary setups, then enable them */
    time_init();
    tty_init();
    trap_init();
    sched_init();
    buffer_init();
    hd_init();
    sti();                    ← 到这里才"开中断"
    move_to_user_mode();
    if (!fork()) {            /* we count on this going ok */
        init();
    }
```

**为什么 `sti()` 必须在最后？** 如果在最前面开中断：时钟中断立刻开始触发 → 中断处理程序要去调调度器、读时钟变量 → 可 `sched_init()`、`time_init()` 还没跑，那些变量是垃圾值 → **内核当场崩在第一次时钟中断上。**

> **这就是"顺序"的意义：不是风格，是依赖图 —— 谁先准备好、谁后需要谁。**
> 以后排 systemd 的 `After=` / `Requires=`、排 rc 脚本、排自己的脚本步骤，都是同一个道理。

### 6.8 `move_to_user_mode()` —— 从"内核"变成"进程"的那一瞬间

一个宏，**伪造一次"中断返回"**，把 CPU 从 **ring 0（内核态）** 降到 **ring 3（用户态）**。

在这之前代码是"内核"；这一步之后，这段代码变成了 **0 号任务（task 0）**，一个真正的进程。

> 你敲的每一条命令，都运行在某个"从内核态降到用户态"的进程里。

### 6.9 `fork` + task 0 的 `pause` 注释

```c
    if (!fork()) {          /* we count on this going ok */
        init();
    }
```

- **子进程**（`fork()` 返回 0）→ 跑 `init()` → 最终 `execve("/bin/sh")` 给你一个 shell
- **父进程**（task 0）→ 掉进无限循环（`for(;;) __asm__("int $0x80");`）

课件后面对应的注释说：别的进程 `pause()` 是等信号唤醒；**task 0 是唯一例外** —— 它 `pause()` 的意思是"我没事干，让调度器看看别人要不要跑"。

> **这就是你现在机器上那个 idle 进程的老祖宗。** `top` 里看到的 CPU 空闲率，就是这个进程在"占着 CPU 什么也不干"。

### 6.10 实测另一处：`static inline _syscall0(int,fork)`（第 17 行）

配着文件开头的注释：

```
* we need this inline - forking from kernel space will result
* in NO COPY ON WRITE (!)
```

**1991 年内核还没有写时复制（COW）** —— `fork` 会**真复制**整个地址空间。若从内核态用普通函数调用 fork，栈帧会被复制出的内存搞乱，所以必须 `inline` 展开、不建栈帧。

> 现在的 `fork` 早就是 COW（只复制页表，写时才复制页）。**这 8 行注释，就是"为什么现代 fork 那么快"这段历史的一端。**

### 6.11 一个纠正：0.01 **没有 `/etc/rc`**

```bash
grep -n "fork\|execve\|/bin/sh\|/etc/rc\|tty0" linux/init/main.c
```

实测出现的：
```
 17: static inline _syscall0(int,fork)
 93: if (!fork()) {
125: if (!fork())
126:     _exit(execve("/bin/update",NULL,NULL));    ← /bin/update，不是 /etc/rc
127: (void) open("/dev/tty0",O_RDWR,0);
133: if ((i=fork())<0)
138: (void) open("/dev/tty0",O_RDWR,0);
141:     _exit(execve("/bin/sh",argv,envp));
```

**0.01 执行的是 `/bin/update`**（把内存里攒的缓冲刷回磁盘）。**`/etc/rc` 开机脚本是 0.11 才有的东西。**

### 6.12 `_exit(execve(...))` 这个写法

`execve` **成功就永不返回**（它把当前进程整个换成新程序）。所以这行的真实含义是：

> "去执行 `/bin/sh`；**万一它返回了**，说明替换失败，那就 `_exit` 退出。"

**把"不可能发生的分支"当成错误处理** —— 老 C 代码的经典紧凑写法。

<details>
<summary>答案</summary>

1. **纵向**＝顺着程序的执行顺序读；**横向**＝按模块单独读。启动代码用纵向（价值在顺序），内存管理用横向（自成体系）。
2. 进程管理→`kernel/`；内存管理→`mm/`；文件系统→`fs/`；驱动程序→`drivers/`；网络→`net/`。
3. 负责 **GDT/IDT、页目录、页表、进入保护模式、栈切换**。因为这层地基已经打好，`main()` 才能直接用内存。
4. `&15` 取**低 4 位（个位）**，`>>4` 取**高 4 位（十位，再 ×10）**。CMOS 用 BCD 编码，不转换就会把"45 秒"读成"69"。
5. 防止在**秒边界**上读到"半新半旧"的时间。读完再核对一次秒，变了就整组重来（双读校验）。
6. 因为 `sti()` 一开中断，时钟中断立刻会触发，而中断处理程序要用调度器、时钟变量 —— 那些还没初始化完，会**崩在第一次时钟中断**。
7. **伪造一次中断返回，把 CPU 从 ring 0 降到 ring 3**。让这段内核代码变成"0 号任务"这个真正的进程，之后才能 fork 出用户进程。
8. `execve` 成功永不返回；**返回了就说明替换失败**，于是 `_exit` 退出 —— 把"不可能的分支"当错误处理。
9. 0.01 是 **`/bin/sh`**（还先跑 `/bin/update`）；现在是 **systemd**（由 `start_kernel → rest_init → kernel_init` 拉起）。
10. 带 `extern` 的是**声明**，带 `static`/返回类型 + `{` 的是**定义**，只有 `名字();` 的是**调用**。

</details>

## 十 一句话总结

> **linux 0.01 = 88 个文件、9877 行；内核入口 `init/main.c` 只有 147 行 —— 它自己不干活，只按顺序点名六个初始化；真正的地基是 `boot/head.s` 的 175 行汇编。**
> **读内核的方法：先看分布（模块↔目录表），再选方向（纵向跟流程 / 横向进模块），最后用 `grep` 定位而不是逐行啃。**
