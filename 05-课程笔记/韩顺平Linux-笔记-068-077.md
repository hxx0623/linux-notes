## 一、【课件】14.1 进程基本介绍

| # | 课件要点 |
| --- | --- |
| 1 | 每个执行的程序都称为**进程**，分配一个 ID 号（**pid**） |
| 2 | 进程有两种存在方式：**前台**（屏幕上可操作）、**后台**（实际在跑但屏幕看不到） |
| 3 | 系统的**服务都是后台进程**，而且**常驻**，直到关机才结束 |

**前台 vs 后台**：`ping www.baidu.com`（前台，占着终端）vs `ping www.baidu.com &`（后台，加 `&`）。

**Windows 类比**：任务管理器里那一列进程。

## 二、【课件】14.2 `ps`

### `ps -aux`（看资源）

```bash
ps -aux | grep xxx
```

| 列 | 含义 |
| --- | --- |
| `USER` | 用户名称 |
| `PID` | 进程号 |
| `%CPU` / `%MEM` | 占 CPU / 物理内存百分比 |
| `VSZ` / `RSS` | 虚拟内存 / 物理内存大小（KB） |
| `TT` / `TTY` | 终端名称 |
| `STAT` | **进程状态** |
| `STARTED` | 启动时间 |
| `TIME` | 占用 CPU 的总时间 |
| `COMMAND` | 命令和参数（过长截断） |

### `ps -ef`（看父子）

```bash
ps -ef | grep xxx
```

| 列 | 含义 |
| --- | --- |
| `UID` | 用户 ID |
| `PID` | 进程 ID |
| **`PPID`** | **父进程 ID** |
| `C` | CPU 计算优先级的因子 |
| `STIME` / `TTY` / `TIME` | 启动时间 / 终端 / CPU 时间 |
| `CMD` | 命令和参数 |

### 两者最实用的差别

| | `ps -aux` | `ps -ef` |
| --- | --- | --- |
| 独有列 | **`%CPU` `%MEM`** | **`PPID`** |
| 用途 | 查“谁在吃资源” | 查“**谁生出来的**” |

**课件笔误**：课件把 `ps -aux` 标成「SystemV 风格」、`ps -ef` 标成「BSD 风格」，**按传统是反的**（`ps aux` 不带横线才是 BSD 风格）。**不影响使用，记住独有列就行。**

### `STAT` 状态码

| 字母 | 含义 |
| --- | --- |
| `S` | 睡眠（**绝大多数**） |
| `R` | 正在运行 |
| `Z` | **僵死进程** |
| `D` | 短期等待 |
| `T` | 被跟踪/停止 |
| `s` | 会话的先导进程 |
| `N` | 优先级更低 |

### `grep` 把自己也搜进去的问题

```bash
ps -ef | grep sshd            # 会多出一行 grep --color=auto sshd
ps -ef | grep [s]shd          # ✅ 方括号技巧，不匹配自己
pgrep -a sshd                 # ✅ 更干净
```

## 三、【课件】14.2.3 父子进程与 `PPID`

### 规则

> **`PPID` = 谁生了我。** 除了 1 号进程，每个进程都有父进程。

| 进程 | PPID |
| --- | --- |
| `systemd`（PID 1） | **0**（内核启动的，没有父进程） |
| 各系统服务 | 1（systemd 直接拉起） |
| 你的 `bash` | 终端程序 或 `sshd` |
| `ps` 命令自己 | 你的 `bash` |

### `echo $$` / `echo $PPID`（最直观的验证）

```bash
echo $$        # 当前 shell 的 PID
echo $PPID     # 当前 shell 父进程的 PID
bash           # 套一层子 shell
echo $$        # 新 PID
echo $PPID     # ⭐ 正好等于刚才那个 PID
exit
```

### 实测：sshd 的三层链（10-30 记录）

```
root   5723   1      sshd: /usr/sbin/sshd -D [listener] ...   ← systemd 拉起
root   5724   5723   sshd: cxh [priv]                          ← listener 分叉
cxh    5812   5724   sshd: cxh@pts/1                           ← [priv] 分叉，已降权
```

| 层 | 身份 | 作用 |
| --- | --- | --- |
| `[listener]` | root | 监听 22（<1024 端口只有 root 能绑） |
| `[priv]` | root | **认证时读 `/etc/shadow`**，必须 root |
| `cxh@pts/1` | **cxh** | 跑用户数据，**绝不能是 root** |

**这是「特权分离」设计**：认证要 root，处理数据不能 root → 分成两层，中间降权。

**只有 systemd 直接启动的进程 PPID 才等于 1**，后面每一层都是 fork 出来的。

### 孤儿与僵尸

| | 孤儿（orphan） | 僵尸（zombie） |
| --- | --- | --- |
| 谁活着 | **子**活，父死 | **父**活，子死 |
| 归宿 | 被 **1 号 systemd 收养** | 等父进程 `wait()`，父不回收就一直留着 |
| 资源 | 正常占用 | **不占 CPU/内存，但占 PID** |
| 危害 | 无害 | 多了**耗尽进程表** |
| 处理 | 不用管 | **杀掉父进程**，僵尸被 1 号回收 |

```bash
setsid sleep 300 &                    # 造孤儿：PPID 会变成 1
ps -eo pid,ppid,stat,cmd | awk '$3 ~ /Z/'   # 查僵尸
```

## 四、【课件】14.3 终止进程 `kill` / `killall`

### `kill` 是**发信号**，不是“杀”

| 命令 | 信号 | 效果 |
| --- | --- | --- |
| `kill PID` | **SIGTERM(15)** | 礼貌请求退出，**进程可捕获、可善后** |
| `kill -9 PID` | **SIGKILL(9)** | 内核直接抹掉，**进程无法捕获、无法善后** |

**铁律：先 `kill`（15），不行再 `kill -9`。**

### 语法

| 命令 | 按什么 | 特点 |
| --- | --- | --- |
| `kill [选项] PID` | 进程号 | 精准，一次一个 |
| `killall 名字` | 进程名 | 一次全杀，支持通配符；**系统卡死时很有用**（ps 都刷不出来） |

### `trap` 实验（亲眼看见 15 和 9 的差别）

```bash
# 实验 A：kill（15）—— 会说话
bash -c 'trap "echo baocun; exit 0" TERM; while :; do sleep 1; done' &
sleep 1
kill %1
# 输出：已终止 + baocun      ← trap 执行了

# 实验 B：kill -9 —— 一句话都说不出
bash -c 'trap "echo baocun; exit 0" TERM; while :; do sleep 1; done' &
sleep 1
kill -9 %1
# 输出：已杀掉（没有 baocun）
```

⚠️ **`&` 必须在同一行末尾**，否则命令变成前台死循环（今天踩过）。

### 课件四个案例（Ubuntu 版）

| 案例 | 做法 |
| --- | --- |
| 踢掉非法登录用户 | `who` / `ps -ef \| grep [b]ash` 找 PID → `kill` |
| 终止 sshd 再启 | `sudo systemctl stop/start ssh.socket` |
| `killall gedit` | 一样 |
| 强制杀终端 | `kill -9 别人的bashPID`（**别杀自己的**） |

### ⚠️ 杀之前的安全清单

| 目标 | 后果 |
| --- | --- |
| 自己的 `bash` | 终端关闭 |
| 1 号 `systemd` | 被内核拒绝 |
| `Xorg` / `gnome-shell` | 桌面崩溃 → `sudo systemctl start gdm3` |
| `ssh.socket` | SSH 断开 |
| `pkill -9 bash` | **杀掉所有 bash，桌面可能黑屏** |

## 五、【课件】14.4 `pstree`

```bash
pstree          # 树状
pstree -p       # 带 PID（课件）
pstree -u       # 带所属用户（课件）
```

**`ps -ef` 是户口本，`pstree` 是族谱图。**

### 符号含义

| 符号 | 含义 |
| --- | --- |
| `─┬─` `├─` `└─` | 树结构、分叉 |
| `(数字)` | PID（仅 `-p`） |
| **`{花括号}`** | **用户态线程**（不是独立进程） |
| **`[方括号]`** | **内核线程**（如 `[kworker/0:1]`） |
| **`2*[...]`** | 同名兄弟合并显示，`2*` = 有两个 |

### 最实用的一招

```bash
pstree -s -p $$        # 看当前 shell 的祖宗链
```

输出形如：`systemd(1)───gdm3───…───bash(3495)───pstree(5100)`

### 【Ubuntu】注意

- 来自 **`psmisc`** 包（`killall` 也是），没装：`sudo apt install psmisc`
- 桌面版树**极长**（GNOME + snap），一定 `| head -30` 或 `| less`

## 六、【课件】14.5 服务管理（073–077）

### 14.5.1 什么是服务

> 服务本质就是进程，但是**运行在后台**，通常**监听某个端口**等待请求（mysqld、sshd、防火墙），又称**守护进程**。

| | 自己起的进程 | 服务（systemd 托管） |
| --- | --- | --- |
| 谁启动 | 你 | `systemd` |
| 挂了 | 没人管 | **可自动重启**（`Restart=on-failure`） |
| 怎么停 | `kill` | **`systemctl stop`**（用 kill 会被拉回来） |

### 14.5.2–14.5.4 `service`（老方法）

```bash
service 服务名 [start|stop|restart|reload|status]
```

- 课件明确：**CentOS 7.0 后很多服务改用 `systemctl`**
- 老服务脚本在 `/etc/init.d` 查看；也可以 `setup` 图形菜单
- 课件案例 `service network status` ⚠️ **Ubuntu 没有 `network` 这个服务**（网络归 NetworkManager + netplan）

### 14.5.5 七种运行级别

| 级别 | 含义 |
| --- | --- |
| 0 | 停机（不能设默认） |
| 1 | 单用户，root，禁止远程登录 |
| 2 | 多用户无网络 |
| **3** | **完全多用户，命令行** |
| 4 | 保留 |
| **5** | **图形界面** |
| 6 | 重启（不能设默认） |

### 14.5.6 target 取代 runlevel

| runlevel | target |
| --- | --- |
| 3 | `multi-user.target` |
| 5 | `graphical.target` |

```bash
systemctl get-default
sudo systemctl set-default graphical.target
```

（025 集已学并实测）

### 14.5.7 `chkconfig`

```bash
chkconfig --list
chkconfig --level 3 network off
```

⚠️ **Ubuntu 没有 `chkconfig`**（RedHat 专属）。改用 `systemctl enable/disable`。
课件细节：改完要 `reboot` 才生效（chkconfig 的老毛病，systemctl 不需要）。

### 14.5.8–14.5.9 `systemctl`（现代方法 ⭐）

```bash
systemctl [start|stop|restart|status] 服务名      # 按名称
# 注意是 systemctl，不是 systemdctl
systemctl list-unit-files | grep 服务名           # 看自启动状态
systemctl enable / disable 服务名                  # 设/取消开机自启
systemctl is-enabled / is-active 服务名            # 查
```

服务定义文件：**`/usr/lib/systemd/system/*.service`**
`systemctl cat 服务名` 可直接打印。

### 🔑 最容易混的一对

| 命令 | 管的是 | 重启后 |
| --- | --- | --- |
| `start` / `stop` | **现在的状态** | 回到原设置 |
| `enable` / `disable` | **开机要不要自启** | **永久** |

**口诀**：`start` = 现在开灯；`enable` = 拉总闸（以后自动亮）。**两者独立**：可以 `stop` 但仍 `enabled`。

### ⭐ `enable` 的真相：就是一个软链接

`systemctl cat cron` 的 `[Install]` 段：

```ini
WantedBy=multi-user.target
```

`systemctl enable cron` = 在 `multi-user.target.wants/` 里建软链：

```bash
ls -l /etc/systemd/system/multi-user.target.wants/ | grep cron
# cron.service -> /usr/lib/systemd/system/cron.service
```

| 命令 | 底层 |
| --- | --- |
| `enable` | 建软链 |
| `disable` | 删软链（**不删服务本身**） |
| `is-enabled` | 查软链在不在 |

### ⭐ `Restart=on-failure` 与 `kill` 的关系

```bash
sudo kill -9 $(pgrep cron)     # 3 秒后自己回来（PID 变了）
sudo systemctl stop cron        # 不会回来
```

**意外死亡**（非零退出/被信号杀）→ 触发重启；**计划内停止**（`systemctl stop`）→ 不重启。

> **结论：管理 systemd 管的服务，永远用 `systemctl stop`，别用 `kill`。**

### 14.5.10–14.5.11 防火墙（课件用 firewalld）

```bash
systemctl status/stop/start firewalld
```

课件细节：**`stop` 只是临时生效，重启后恢复；要永久用 `disable`。**

### 14.5.12–14.5.14 开放端口

```bash
firewall-cmd --permanent --add-port=111/tcp
firewall-cmd --permanent --remove-port=111/tcp
firewall-cmd --reload            # ⚠️ 必须 reload 才生效
firewall-cmd --query-port=111/tcp
```

**`--permanent` 只写配置，不加 `--reload` 不生效** —— CentOS 上最大的坑。

## 七、CentOS → Ubuntu 差异总表（本章最重要的一节）

| 课件（CentOS） | Ubuntu 24.04 |
| --- | --- |
| `service 服务名 …` | **能用，但只是转发给 systemd 的兼容壳** |
| `/etc/init.d` 一堆脚本 | 目录还在，**基本空了** |
| `service network stop/start` | ❌ **没有 `network` 服务**（用 NetworkManager/netplan） |
| `chkconfig` | ❌ **命令不存在** → `systemctl enable/disable` |
| `runlevel` / `init 3` | → `systemctl get-default` / target |
| `firewalld` + `firewall-cmd` | ❌ 默认没装 → **`ufw`** |
| `setup` | ❌ 没有 → `systemctl list-unit-files` |
| 服务定义目录 | ✅ 一样，`/usr/lib/systemd/system` |

### 防火墙对照

| 目的 | CentOS | Ubuntu |
| --- | --- | --- |
| 看状态 | `firewall-cmd --state` | `sudo ufw status verbose` |
| 开/关 | `systemctl start/stop firewalld` | `sudo ufw enable/disable` |
| 开端口 | `--permanent --add-port=111/tcp` | **`sudo ufw allow 111/tcp`** |
| 关端口 | `--permanent --remove-port=111/tcp` | `sudo ufw delete allow 111/tcp` |
| 生效 | **必须 `--reload`** | **立即生效** |
| 看规则 | `firewall-cmd --list-all` | `sudo ufw status numbered` |

> 本机 `sudo ufw status verbose` 实测：**状态：不活动**（Ubuntu 桌面版默认关闭）。

## 八、今日踩的坑（10-30）

1. **多行命令粘贴，`&` 掉到下一行** → 命令变成**前台死循环**，终端“卡住”。
   → `Ctrl+C` 救出；**粘贴后先看光标位置再回车**。（这是继 `^[[200~` 之后第二个粘贴坑）
2. **`ps -ef | [s]shd` 报“未找到命令”** —— 管道后面少打了 `grep`，bash 把 `[s]shd` 当命令执行。
3. **`systemdctl` 拼错**（应是 `systemctl`）—— 多一个 `d` 就跑不起来。
4. **`pstree -u | grep sshd` 无输出** —— 不是命令错，是 **Ubuntu 用 `ssh.socket` 按需激活，没人连时没有 sshd 进程**。
   （这个知识点第三次影响学习：装机时 `is-active ssh` 为 inactive、069 集 `ps` 搜不到、今天 `pstree` 搜不到）
5. **`sshd: cxh [priv]` 的 PPID 不是 1** —— 它是被 listener（5723）fork 出来的，**只有 systemd 直接启动的才是 1**。
6. **history 里看不到刚敲的命令** —— `~/.bash_history` 只在 bash **正常退出**时写盘；父 shell 没退出，子 shell 读到的是旧快照。解法：`PROMPT_COMMAND='history -a'`。
7. **`echo $$` 之后按上键出现的是很久以前的命令** —— 同一个原因（父 shell 未退出、历史未写盘）。

## 九、三条铁律（068–077）

**① `PPID` = 谁生了我**，只有 systemd 直接启动的才是 1。

**② `kill` 是发信号，先 15 后 9** —— `-9` 跳过一切善后。

**③ `start/stop` 管现在，`enable/disable` 管开机** —— 两者独立。

## 十、自测题

1. `ps -aux` 和 `ps -ef` 各有一个对方没有的列，分别是什么？
2. `STAT` 为 `Z` 是什么？怎么处理？
3. `kill` 和 `kill -9` 的区别？哪个能执行 `trap`？
4. 杀掉 systemd 托管的服务进程后会发生什么？正确做法是什么？
5. Ubuntu 上 `chkconfig` 和 `firewall-cmd` 分别对应什么？
6. `systemctl enable` 在磁盘上到底做了什么？

<details>
<summary>答案</summary>

1. `-aux`：`%CPU` `%MEM`；`-ef`：`PPID`
2. 僵尸进程（子死了父不回收）；**杀掉父进程**让它被 1 号回收
3. `kill` 发 SIGTERM(15) 可捕获可善后；`kill -9` 发 SIGKILL 不可捕获。**`kill`（15）能执行 trap**
4. 被 systemd 按 `Restart=on-failure` **自动拉回来**（PID 会变）；正确做法是 `systemctl stop`
5. `chkconfig` → `systemctl enable/disable`；`firewall-cmd` → **`ufw`**（`sudo ufw allow 端口/协议`）
6. 在 `/etc/systemd/system/<target>.wants/` 里**创建一个指向服务单元文件的软链接**

</details>
