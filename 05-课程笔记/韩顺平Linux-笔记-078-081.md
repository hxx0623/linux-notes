## 一、【课件】14.6 `top` 动态监控

### 和 `ps` 的区别（课件原话）

> `top` 与 `ps` 很相似，都用来显示正在执行的进程。**最大不同在于 `top` 在执行一段时间可以更新**正在运行的进程。

| | `ps` | `top` |
| --- | --- | --- |
| 性质 | 一次性快照 | **持续刷新（默认 3 秒）** |
| 退出 | 自动 | 按 `q`（或 `Ctrl+C`） |

### 选项（课件是表格截图，按标准补）

| 选项 | 作用 |
| --- | --- |
| `-d 秒数` | 刷新间隔，默认 **3** |
| `-n 次数` | 刷新几次后退出（`-n 1` 只看一眼） |
| `-p PID` | 只看指定进程（多个用逗号） |
| `-u 用户` | 只看某用户 |
| `-b` | **批处理**：不刷新、纯文本（适合重定向） |
| `-i` | 不显示闲置/僵尸进程 |

### 界面解读（本集核心，课件只给图）

```
top - 16:21:19 up 2 days, 3:12, 1 user, load average: 0.52, 0.58, 0.59
Tasks: 245 total, 1 running, 244 sleeping, 0 stopped, 0 zombie
%Cpu(s): 2.3 us, 1.0 sy, 0.0 ni, 96.4 id, 0.2 wa, 0.0 hi, 0.1 si, 0.0 st
MiB Mem : 7900.4 total, 3245.0 free, 2100.0 used, 2555.4 buff/cache
MiB Swap: 4096.0 total, 4096.0 free, 0.0 used. 5200.0 avail Mem
```

**第 1 行 · load average（1 / 5 / 15 分钟平均负载）**

- 定义：**正在跑的 + 排队等着的**进程数（**含卡在 IO 的 `D` 状态**）
- 判断：**load ÷ CPU 核数**。4 核 → load ≈ 4 是满载，> 4 在排队
- 趋势：1 分钟 >> 15 分钟 = 正在恶化；反过来 = 正在恢复
- ⚠️ **load 高 ≠ CPU 忙**，可能是 IO 卡

**第 2 行**：总进程数 / running / sleeping / stopped / **zombie（持续增长 = bug）**

**第 3 行 · CPU**

| 字段 | 含义 | 诊断 |
| --- | --- | --- |
| `us` | 用户态 | 高 = 程序在算 |
| `sy` | 内核态 | 高 = 系统调用/驱动 |
| `id` | 空闲 | 越高越闲 |
| **`wa`** | **等 IO** | **高 = 磁盘/IO 慢，不是 CPU 问题** |
| `st` | 被虚拟机宿主偷走 | **虚拟机上看常见** |

**第 4–5 行 · 内存**

- **不要看 `free` 就慌**：`buff/cache` 是可回收的缓存
- **该看 `avail Mem`（可用内存）**
- **`Swap used` 持续增长 = 性能断崖**

**下半部分每进程一行**

| 列 | 含义 |
| --- | --- |
| `VIRT` | 虚拟内存总量（**含未真正分配的，别被吓到**） |
| **`RES`** | **实际占用的物理内存 ⭐** |
| `SHR` | 共享内存 |
| `S` | 状态 |
| `TIME+` | 累计 CPU 时间 |

### 交互键（课件 14.6.4，表格截图，按标准补）

| 键 | 作用 | 要不要回车 |
| --- | --- | --- |
| **`u`** | 按用户筛选（**留空回车 = 恢复全部**） | 要 |
| **`k`** | 杀进程（输 PID → 再问信号，**默认 15**） | 要 |
| **`P`** | 按 CPU 排序（默认） | 不要 |
| **`M`** | 按**内存**排序 | 不要 |
| `q` | 退出 | 不要 |
| `h` | 帮助（列出全部键） | 不要 |
| `1` | **展开每个 CPU 核心** | 不要 |
| `T` / `N` | 按累计时间 / PID 排序 | 不要 |
| `c` | 显示完整命令行 | 不要 |
| `i` | 隐藏空闲进程 | 不要 |
| `s` | 交互改刷新间隔 | 要 |

### 三个应用实例（课件 14.6.5）

| 案例 | 操作 |
| --- | --- |
| 监视特定用户 `tom` | `top` → 按 `u` → 输 `tom` → 回车 |
| 结束 `tom` 的登录 | `top` → 按 `k` → 输 PID → 回车 → 信号处回车（15）或输 `9` |
| 每 10 秒刷新 | `top -d 10` |

### ⚠️ `top` 里按 `k` 的权限限制

**`top` 以你的身份运行，只能杀你自己的进程。** 属主是 `root` 或别人的 → 报「发送信号失败，未被许可」。

| USER 列 | 能否 `k` |
| --- | --- |
| 你自己 | ✅ |
| 别人 / root | ❌ 需 `sudo top` 或改用 `sudo kill -9` |

## 二、【课件】14.7 监控网络状态

### `netstat`（课件 14.7.1）

```bash
netstat [选项]
netstat -anp | grep sshd      # 课件案例
```

| 选项 | 含义 |
| --- | --- |
| `-a` | **all**，所有套接字（课件写“按一定顺序排列输出”，**不准确**） |
| `-n` | **numeric**，数字显示，不解析主机名/服务名 |
| `-p` | 显示哪个进程在用 |
| `-t` `-u` `-l` | TCP / UDP / 只看监听 |

**输出列**：`Proto Recv-Q Send-Q Local Address Foreign Address State`

### 四个状态

| 状态 | 含义 |
| --- | --- |
| **`LISTEN`** | 正在监听等待连接 |
| **`ESTABLISHED`** | 已建立，正在通信 |
| `TIME_WAIT` | 主动关闭后等待（正常） |
| **`CLOSE_WAIT`** | **对方关了本端没关，大量堆积 = 程序 bug** |

### ⚠️ `0.0.0.0` vs `127.0.0.1`（安全关键）

| 地址 | 含义 |
| --- | --- |
| `0.0.0.0:3306` | **所有网卡**都听，外网可连（云服务器上这是事故起点） |
| `127.0.0.1:3306` | **只有本机**能连 |

### 【Ubuntu】`netstat` 已被 `ss` 取代

| 目的 | netstat | **ss** |
| --- | --- | --- |
| 所有连接 | `-an` | `ss -an` |
| **看监听端口** | `-tlnp` | **`ss -tlnp`** |
| 看路由 | `-rn` | **`ip route`** |
| 连接汇总 | — | **`ss -s`** |

- `netstat` 来自 **`net-tools`**（已停止维护，Ubuntu 默认不装）
- **`ss` 来自 `iproute2`（自带、更快）**

### 四个实用场景

```bash
ss -tlnp                          # 本机开了哪些端口
sudo ss -tlnp | grep :22          # 端口被谁占（解决 Address already in use）
ss -tn state established          # 谁连着本机
ss -s                             # 连接数汇总
```

本机实测监听：`53`（systemd-resolved，仅 127.0.0.53）、`22`（ssh.socket）、`631`（CUPS，仅 127.0.0.1）。

### `ping`（课件 14.7.2）

> 网络检测工具，检测远程主机是否正常，或主机间网线/网卡故障。

**已在 064 集详细学过**（黄金四步、`-c` 次数、Ubuntu 不会自动停）。

## 三、第 14 章复盘（081，课件无此节）

### 三条主线

```
看进程            管进程             管服务
ps / ps -ef   →   kill / kill -9  →  systemctl
top / pstree                      （systemd 托管）
```

### 排障决策流程

| 症状 | 先查 | 结论 |
| --- | --- | --- |
| 机器变卡 | `top` 的 `us` 高 | 有程序猛算 → `ps aux --sort=-%cpu` |
| 机器变卡 | `top` 的 **`wa` 高** | **IO 问题，不是 CPU** |
| load 高但 CPU 闲 | `ps -eo stat,pid,cmd \| grep "^D"` | 有进程卡在 IO |
| 内存不够 | `free -h` 看 **available** | 不看 free；Swap 增长危险 |
| 服务起不来 | `systemctl status` → `journalctl -u` | 先状态后日志 |
| 端口被占 | `sudo ss -tlnp \| grep :端口` | 找到占用者 |
| 端口不通 | `ping` 四步 + `ss` + `ufw status` | 分层排查 |
| **杀不掉进程** | ①是 `user` 自己的吗 ②`STAT` 是 `T` 吗 | 两者中任一 → `sudo kill -9` |

### 第 14 章 CentOS → Ubuntu 差异

| 课件（CentOS） | Ubuntu |
| --- | --- |
| `service xxx start` | 能用，只是**转发给 systemd 的兼容壳** |
| `/etc/init.d` 一堆脚本 | 基本空了 |
| `service network start` | ❌ 没有 `network` 服务 |
| `chkconfig` | ❌ 不存在 → `systemctl enable/disable` |
| `firewalld` + `--permanent` + `--reload` | ❌ 没装 → **`ufw`**（`allow` 即生效） |
| `setup` | ❌ 没有 |
| `netstat` | ⚠️ 需装 `net-tools`，**推荐 `ss`** |
| 常驻 `sshd` 进程 | **`ssh.socket` 按需激活，平时没有** |
| `runlevel` | `systemctl get-default` |

> **“sshd 平时不存在”这一章出现了三次**（`ps`、`pstree`、`netstat` 各一次）。
> 记住：**Ubuntu 上“SSH 服务正常”≠“有个 sshd 进程在跑”。**

## 四、今日踩的坑（10-31）⭐ 含一次安全事件

1. **🔴 把 sudo 密码直接敲进了命令行**（那串数字被 shell 当成命令执行，报“未找到命令”）。
   - 后果：密码被打印在屏幕上，并进入 `~/.bash_history`（**明文**）
   - 清理：`history | grep 密码` 找编号 → `history -d 编号` → `sed -i '/密码/d' ~/.bash_history`
   - **教训：只在 `[sudo] ... 的密码:` 提示出现后再输入；提示没出现就 `Ctrl+C`**
   - 📌 这条的密码原文已从笔记里抹掉（笔记会被同步/备份，不该留明文口令）。
2. **`sudo cmd &` 会卡死** —— 后台进程不能读终端，sudo 等密码被内核 `SIGTTIN` **停止**（`已停止`）。
   - 正解：**先 `sudo -v` 预热凭证，再 `&`**；或用 `sudo -b`
3. **`kill %1` 杀不掉「已停止」的作业** —— **停止状态的进程只认 `SIGKILL` 和 `SIGCONT`**，其它信号挂起。
   - 加上这些进程属主是 **root**（sudo 本身以 root 跑）→ 最终解法 `sudo kill -9`
4. **`top` 里按 `k` 报「未被许可」** —— top 以 cxh 身份跑，属主 root/tom 的进程杀不了。
   - 解法：`sudo top` 或退出后用 `sudo kill -9`
5. **`netstat -anp | grep sshd` 无输出** —— 又一次 ssh.socket 按需激活（第三次）。

## 五、自测题

1. `top` 和 `ps` 最大的区别？
2. `load average: 8.0` 在 4 核机器上说明什么？
3. `top` 里 `wa` 高说明什么？该怎么查？
4. `VIRT` 和 `RES` 哪个是真实内存占用？
5. `netstat` 在现代 Ubuntu 上被什么取代？命令怎么写？
6. `0.0.0.0:3306` 和 `127.0.0.1:3306` 的安全差别？
7. 一个进程 `STAT` 是 `T`，普通 `kill` 无效，为什么？

<details>
<summary>答案</summary>

1. `top` 会**持续刷新**（默认 3 秒），`ps` 是**一次性快照**
2. **满载且已排队**：8 ÷ 4 = 每个核上排 2 个任务
3. **IO 在等**（磁盘/网络慢），不是 CPU 忙 → `vmstat 1`、`iotop`
4. **`RES`**（`VIRT` 包含还没真正分配的部分）
5. **`ss`**，例如 `ss -tlnp`
6. `0.0.0.0` 对所有网卡开放（外网可连，风险高）；`127.0.0.1` 只有本机能连
7. 因为进程被**停止（`T`）**了，普通信号会挂起不投递；**只有 `SIGKILL(9)` 和 `SIGCONT` 能作用于停止的进程**

</details>
