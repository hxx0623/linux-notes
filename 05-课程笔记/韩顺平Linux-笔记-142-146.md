# 二、142：统计访问量和连接数（腾讯）

## 2.1 26.1 访问量统计（课件原文）

> 分析日志 `t.log`（访问量），将各个 ip 地址截取，并统计出现次数，并按从大到小排序。

```
http://192.168.200.10/index1.html
http://192.168.200.10/index2.html
http://192.168.200.20/index1.html
http://192.168.200.30/index1.html
http://192.168.200.40/index1.html
http://192.168.200.30/order.html
http://192.168.200.10/order.html
```

**标准答案**（与腾讯给的一字不差）：

```bash
cat t.log | cut -d"/" -f3 | sort | uniq -c | sort -nr
```

```
      3 192.168.200.10
      2 192.168.200.30
      1 192.168.200.40      ← 平局时 .40 在前，因为 -r 把"兜底比较"也反转了
      1 192.168.200.20
```

> ⚠️ 课件题面写 `t.log`，答案那行写 `t.txt` —— **课件自身不一致**，统一用 `t.log`。

## 2.2 ⭐ 四阶段方法论（这一集真正的收获）

从原始日志到结果，必须经过四步，**顺序不能乱**：

| 阶段 | 干什么 | 为什么非要这一步 |
| --- | --- | --- |
| **① 截取** | 从每行 URL 里把 IP 抠出来 | 整行没法统计 |
| **② 排序** | 把相同 IP 排到一起 | **`uniq` 只能合并"相邻"的重复行**，不排序相同 IP 散在各处，一个都数不出来 |
| **③ 计数** | `uniq -c` 合并并计数 | 题目核心 |
| **④ 再排序** | 按次数从大到小 | 题目要求 |

**口诀：先聚拢，再统计。**

## 2.3 `-f3` 为什么是第 3 段（本题最容易错的地方）

`http://192.168.200.10/index1.html` 用 `/` 切：

| 字段 | 内容 |
| --- | --- |
| `-f1` | `http:` |
| `-f2` | **空** ← ⚠️ `//` 之间什么都没有，**它算一个空字段** |
| `-f3` | `192.168.200.10` ✅ |
| `-f4` | `index1.html` |

> **验证方法**：`echo 'http://…' | cut -d'/' -f2` → 输出空行。
> **遇到"取哪一段"的问题，永远先拿一行试一遍。**

## 2.4 `sort` 为什么出现两次？`-n` 是什么？`-s` 是什么？

```bash
... | sort | uniq -c | sort -nr
      ↑第1次            ↑第2次
```

| 问题 | 答案 |
| --- | --- |
| 第一次 `sort` | **纯为了把相同行聚拢**，让 `uniq` 能数 |
| `uniq` 的限制 | **只合并相邻行** —— 不排序则计数全是 1 |
| `-n` | 按**数值**比。不加则按字典序：`1 → 10 → 2`（字符 `1` < `2`） |
| `-r` | 反向 |
| `-s` | **稳定排序**：平局时保持原顺序。不加则平局按整行比较，且 `-r` 会把兜底比较一起反转 |

> **平局实例**：两行都是 1 次，`192.168.200.40` 排在 `.20` 前面 —— 因为整行比较 `.40 > .20`，而 `-r` 反转了它。

## 2.5 26.2 统计连接数（课件原文）

> 统计连接到服务器的各个 ip 情况，并按连接数从大到小排序。

```bash
netstat -an | grep ESTABLISHED | awk -F" " '{print $5}' | cut -d":" -f1 | sort | uniq -c | sort -nr
```

| 段 | 命令 | 作用 |
| --- | --- | --- |
| ① 截取 | `netstat -an \| grep ESTABLISHED` → `awk '{print $5}'` → `cut -d":" -f1` | `-an`＝所有连接＋数字显示；`$5` 是"对端地址:端口"；`cut` 去掉端口 |
| ②③④ | `sort \| uniq -c \| sort -nr` | **和 26.1 完全一样** |

**⭐ 关键观察：后三段不变，只换了第一段。这就是"抓方法，不背命令"。**

**Ubuntu 现代写法**：

```bash
ss -tan | grep ESTAB | awk '{print $5}' | cut -d: -f1 | sort | uniq -c | sort -nr
```

> ⚠️ **IPv6 坑**：IPv6 地址本身带冒号，`cut -d: -f1` 会截成 `2a04`。
> 解法：只看 IPv4 用 `ss -tan4`，或 `grep -v '::'` 过滤。

## 2.6 取字段必须"看语义"，不能"碰巧能跑"

实测对比两种取法（nginx 日志，IP 在第一列）：

| 写法 | 结果 | 评价 |
| --- | --- | --- |
| `awk '{print $1}'` | 正确 | ✅ **语义清楚：空格分隔的第 1 列** |
| `cut -d "-" -f 1` | **碰巧也对** | ⚠️ 取出来是 `192.168.200.10 `（**末尾带空格**），只因每行格式一致才没出错；`-` 在别处出现（如 User-Agent）就崩 |

> **原则：先想"这一列的边界是什么字符"，再选命令。**

```bash
awk '{print $1}' nginx.log | sort | uniq -c | sort -nr -s | head -2
```

- 取列换成 `awk`（按空格）
- 末尾加 `head -2`
- **其余三阶段完全相同**

## 3.2 26.5 tcpdump（课件原文）

> 使用 tcpdump 监听本机，将来自 ip 192.168.200.1、tcp 端口为 22 的数据，保存输出到 tcpdump.log，用作将来数据分析。

```
tcpdump -i ens33 host 192.168.200.1 and port 22 >> /home/tcpdump.log
```

| 部分 | 意思 | 本机填什么 |
| --- | --- | --- |
| `-i ens33` | 指定**网卡** | **`ens160`** |
| `host 192.168.200.1` | 只抓这个 IP 相关的包 | **`192.168.139.1`**（宿主机 VMnet8） |
| `and port 22` | 且端口 22 | 一样 |
| `>> 文件` | **追加**输出 | 一样（`>` 会覆盖，抓包日志必须追加） |

> **`-i` 非写不可**：机器可能有多块网卡（`ens160`、`lo`）。不指定则抓第一块 —— **你以为没流量，其实抓错网卡了**，这是排查最常见的自坑。

## 3.3 tcpdump 输出怎么读

```
15:51:21.316624 IP 192.168.139.1.56048 > 192.168.139.100.22: Flags [S], seq …, win 65535, options [mss 1460,…], length 0
└─── 时间戳 ───┘    └── 源地址.源端口 ┘ > └── 目的地址.目的端口 ┘  └ TCP 标志 ┘
```

### Flags 含义（用上了 068–081 那章的底子）

| 标志 | 含义 | 什么时候出现 |
| --- | --- | --- |
| `[S]` | SYN | 客户端发起连接 |
| `[S.]` | SYN-ACK | 服务端同意 |
| `[.]` | ACK | 确认 |
| `[P.]` | PSH-ACK，**带数据** | 有内容传输 |
| `[FP.]` | FIN+PSH+ACK | **主动关闭**（实测：某个 HTTPS 站点主动断开） |
| `[R]` | RST | 端口没开 / 连接被拒 |

**三次握手就是三行：`[S]` → `[S.]` → `[.]`** —— 实测耗时 **252 微秒**。

### 常用参数

| 参数 | 作用 |
| --- | --- |
| `-i 网卡` | 指定网卡 |
| `-nn` | 不反解域名/服务名（快、准、不乱） |
| `-c N` | 抓 N 个包就停 |
| `-w 文件` | 存原始包（`.pcap`），可给 Wireshark |
| `-A` | 按 ASCII 显示内容（**但对已知协议 tcpdump 会自己解析**，不需要 `-A`） |
| `host` / `port` / `and` / `or` / `not` | 过滤表达式 |

## 3.4 ⭐ 实测：机器上永远有"背景流量"

第一次抓 5 个包，本想抓 ping，结果抓到的全是噪音：

| # | 包 | 解释 |
| --- | --- | --- |
| 1–2 | `…> 185.125.190.56.123: NTPv4, Client/Server` | **系统在对时**（端口 123，NTP，48 字节固定） |
| 3 | `183.36.42.103.443 > …: Flags [FP.]` | 某个 HTTPS 站点**主动断开** |
| 4 | `…> 183.36.42.103.443: Flags [.]` | 本地回 ACK |
| 5 | `192.168.139.1.5353 > 224.0.0.251.5353: PTR hxxPC._dosvc._tcp.local` | **Windows 宿主在做 mDNS 广播**，宣传自己的"传递优化服务" |

**结论：不过滤就抓不到想看的东西。** 26.5 那题为什么写 `host … and port 22`？**不是为了好看，是不这么写根本没用。**

## 3.5 ⭐ 第二次抓 SSH：**版本号是明文发的**

```
192.168.139.1.56048 > .22: length 33: SSH: SSH-2.0-OpenSSH_for_Windows_9.5
192.168.139.100.22 > .56048: length 43: SSH: SSH-2.0-OpenSSH_9.6p1 Ubuntu-3ubuntu13.20
```

**加密之前双方必须先交换版本号字符串** → 抓包就能看出：

- 客户端：**Windows 自带的 OpenSSH 9.5**（连"是 Windows"都暴露）
- 服务端：**Ubuntu 24.04 的 OpenSSH 9.6p1**

> 🔴 **安全含义**：攻击者抓包就知道你跑什么系统、什么版本，拿去对 CVE。
> **所以安全加固会建议改 SSH banner。**

**加密生效的铁证**：之后的包 `length` 变成 1432 / 1120 / 48 / 492，**再也看不到可读内容**。

## 3.6 三个数字别搞混

```
10 packets captured             ← 记下来了
35 packets received by filter   ← 内核交给过滤器的
0 packets dropped by kernel     ← 来不及记、丢了的
```

> **抓不到想要的包时先看 `dropped`**：丢包 → 调大 `-s` 或减流量；`dropped=0` 还没抓到 → **根本没走这网卡或没过过滤条件**（两个完全不同的方向）。

## 3.7 输出的重定向：为什么日志里没有统计摘要

```
tcpdump
  ├── 数据包行 → stdout → 被 >> 重定向进文件
  └── 统计摘要 → stderr → 留在屏幕上
```

实测 `wc -l tcpdump.log` = **10**（正好 10 个包），**没有那三行摘要**。

| 写法 | 重定向谁 |
| --- | --- |
| `cmd > file` | 只 stdout |
| `cmd 2> file` | 只 stderr |
| `cmd > file 2>&1` | 两个都（**顺序：先 `> file` 后 `2>&1`**） |
| `cmd &> file` | bash 简写，同上 |

> **`2>&1` 为什么必须放后面**：它是"把 2 指向 **1 当前指向的地方**"。写成 `2>&1 > file` 的话，2 先指向屏幕，之后 1 才指向文件 —— 错误信息仍然打在屏幕上。**经典面试题。**

## 3.8 用 142 的管道分析抓包日志（串成一条线）

```bash
cat ~/tcpdump.log | awk '{print $3}' | cut -d "." -f 1-4 | sort | uniq -c | sort -nr -s
      5 192.168.139.1
      5 192.168.139.100
```

- `$3` 是源地址（`head -1` 先看清列）
- `cut -d "." -f 1-4` 去掉粘在后面的端口
- 结果 **5 : 5** —— 因为过滤器两个方向都收，**一次 TCP 连接两方向大致对称**

**进阶**：如果问"**连接次数**"而不是"包数"，数 `[S]` 就行：

```bash
grep '\[S\]' ~/tcpdump.log | wc -l
```

> `grep '\[S\]'` 不会误匹配 `[S.]` —— 因为方括号把 `S` 单独框住。

### 全貌

> **抓包负责"拿到数据"，管道负责"把数据变成结论"。两件事合起来才叫"分析日志"。**

# 四、145：系统权限划分(1)（腾讯）

## 4.1 课件题面与答题框架

> 如果你是系统管理员，在进行 Linux 系统权限划分时，应考虑哪些因素？

课件的答题结构**本身就是教材**：

> 1）**首先阐述 Linux 权限的主要对象**
> 2）**根据自己实际经验谈考虑因素**

**面试题不是"想到什么说什么"，是"先给框架再填细节"。**

## 4.2 第 1 步：权限的主要对象

| 对象 | 说明 |
| --- | --- |
| 用户 / 组 / 其他人 | `u` `g` `o` 三栏，**第一个匹配就停**（第 10 章实测） |
| **文件** | `w` 决定**能不能改内容** |
| **目录** | `w` 决定**能不能增删条目**（删文件看目录的 `w`） |
| **路径** | 每层目录都要有 `x` |
| **进程** | 每个进程以某个**用户身份**运行 → 权限就是那个用户的权限（`ps aux` 第一列） |
| **服务** | 也以某用户跑（`www-data`、`sshd`、`root`） |
| **特殊权限位** | SUID / SGID / Sticky（见 146） |

## 4.3 第 2 步：四条考虑因素（课件原文 + 为什么）

| # | 课件原文 | 为什么 | 本机实例 |
| --- | --- | --- | --- |
| 1 | **权限分离**：Linux 系统权限和数据库权限不要在同一部门 | 一个人通吃 → 出事了查不出、也拦不住 | 应用跑在 `www-data` 而不是 root |
| 2 | **最小权限原则**（满足使用的情况下最少优先） | 多给的那份权限，你不知道哪天被利用 | 家目录 `750`；`~/.ssh` 700；`/tmp` 1777 |
| 3 | **减少 root**，用「普通用户 + sudo」 | ① 有审计（`/var/log/auth.log`）② 防手滑 ③ 被盗损失小 | Ubuntu 默认**锁定 root 密码**，逼你走 sudo（026 集验证过） |
| 4 | **`chattr` 锁定重要文件**：`/etc/passwd` `/etc/shadow` `/etc/fstab` `/etc/sudoers` | **连 root 都挡得住**，最后一道防线 | 见下面实测 |

## 4.4 实测盘点（本机 2026-11-09）

```bash
id
# uid=1000(cxh) 组=1000(cxh),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),100(users),114(lpadmin),123(lxd)

ls -l /etc/passwd /etc/shadow /etc/fstab /etc/sudoers
-rw-r--r-- 1 root root   2981 /etc/passwd       ← 全世界可读，只有 root 写
-rw-r----- 1 root shadow 1622 /etc/shadow       ← 只有 root + shadow 组能读
-rw-r--r-- 1 root root    661 /etc/fstab
-r--r----- 1 root root   1800 /etc/sudoers      ← 440，连写位都没有

sudo lsattr /etc/passwd /etc/shadow /etc/fstab /etc/sudoers
--------------e------- /etc/passwd              ← 只有 e（extent），什么都没锁

sudo -l
用户 cxh 可以在 … 运行以下命令：
    (ALL : ALL) ALL                              ← 全权，不是最小权限
```

### 表格解读

| 观察 | 结论 |
| --- | --- |
| `/etc/passwd` 644 vs `/etc/shadow` 640 | ⭐ **"最小权限"最好的例子**：一个必须公开（登录/`ls`/`ps` 都要查），一个必须保密。1990 年代把密码从 passwd 搬出去的原因 |
| `lsattr` 只有 `e` | `e` 是 ext4 的 extent 标记，**不是防护**；真防护是 `i`（不可变）/`a`（只可追加） |
| `(ALL : ALL) ALL` | ⚠️ **本机没有实现最小权限**（学习机故意放开）。**面试时别把学习环境说成最佳实践** |

### 你在 9 个组里 —— 这就是"权限分离"的活标本

| 组 | 能干什么 |
| --- | --- |
| `sudo` | 提权（成员只有 cxh） |
| **`adm`** | ⭐ **读系统日志**（`/var/log/syslog` 是 `640 root:adm`）→ **"能看日志但改不了系统"** |
| `cdrom` / `plugdev` / `lpadmin` | 硬件分权 |
| `dip` | 拨号，历史遗留 |
| **`lxd`** | ⚠️ **等价于 root**（容器能挂宿主机文件系统）。虚拟机无所谓，生产要警惕 |

### `sudo -l` 那四行配置，全是安全设计

| 设置 | 防什么 |
| --- | --- |
| `env_reset` | 清空环境变量，防 `LD_PRELOAD` 注入 |
| `secure_path=…` | sudo 用**固定 PATH**，不用你的 → 防你在 PATH 里放假 `ls` 让 root 执行 |
| `use_pty` | 强制伪终端，防管道注入 |
| `mail_badpass` | 密码错就发邮件（本机没配邮件，不生效） |

> **这四行才是"权限划分要考虑什么"的终极答案**：不只给谁什么权限，还要**防权限被窃取后怎么用**。

## 4.5 `chattr` 实测：连 root 都挡得住

```bash
sudo chattr +i /etc/passwd
sudo lsattr /etc/passwd            # ----i---------e-------
sudo touch /etc/passwd             # touch: 无法 touch: 不允许的操作   ← 用了 sudo 也失败
sudo adduser ooop                  # 失败
sudo chattr -i /etc/passwd         # 解锁
sudo touch /etc/passwd             # 无报错（能写了）
```

| 属性 | 含义 | 用途 |
| --- | --- | --- |
| `i` | immutable，完全不可变 | `/etc/passwd` `/etc/shadow` `/etc/sudoers` |
| `a` | append-only，只可追加 | **日志防篡改**（攻击者只能加，删不掉） |

**保护为什么能强过 root**：它作用在**文件系统层**（ext4 inode 属性），不是普通权限位 —— 内核在写盘前就拦下。

## 4.6 ⭐⭐ 实测暴露的漏洞：**只锁一个文件挡不住"半截操作"**

`sudo adduser ooop` 的完整输出：

```
info: 正在添加用户"ooop"...
info: 正在添加新组"ooop" (1005)...          ← /etc/group 已经被改了！
info: 正在添加新用户"ooop" (1005) 到组"ooop" (1005)...
useradd: 无法打开 /etc/passwd               ← 这里才被 i 属性挡住
fatal: … 返回错误代码 1，退出。
```

**结论：用户没造成，但 `/etc/group` 里多了一个 `ooop` 组（GID 1005）。**

> **要真正防护，必须把 `/etc/passwd`、`/etc/shadow`、`/etc/group`、`/etc/gshadow` 一起锁。** 少锁一个，就会留下这种"半个东西"。
> **这类"实验中途失败"的残留最难发现，也最容易一直躺着。**

# 五、146：系统权限划分(2) —— SUID / SGID / Sticky

## 5.1 三组普通权限之外的第四组

```
   4 7 5 5
   ↑ └┬┘
   │  └── 普通 rwx（owner 7、group 5、other 5）
   └───── 特殊权限位（4/2/1 可相加）
```

| 位 | 名字 | 占哪个 `x` | 样子 | 效果 |
| --- | --- | --- | --- | --- |
| **4** | **SUID** | owner 的 `x` | `rws` | 执行时**变成文件属主** |
| **2** | **SGID** | group 的 `x` | `r-s` | 执行时**变成属组**；**目录内新建文件继承组** |
| **1** | **Sticky** | other 的 `x` | `rwt` | 目录内**只能删自己的** |

> **`s` vs `S`**：小写 `s` = 设了 SUID **且有** `x`（正常）；**大写 `S` = 设了 SUID 但没有 `x`**（位是废的，通常是配置错误）→ 看到大写要警觉。

## 5.2 SUID：`passwd` 凭什么能改密码

```
-rwsr-xr-x 1 root root 64152 /usr/bin/passwd
   ↑ s = SUID
```

**逻辑链**：

```
普通用户 cxh 要改密码 → 必须写 /etc/shadow
                      → 但 /etc/shadow 是 640 root:shadow，cxh 读都读不了
                      → 可"改密码"这个最普通的操作为什么能做？
```

**答案：`passwd` 带了 SUID 位。** 执行时进程的**有效用户临时变成 root**，于是能写 `/etc/shadow`；程序一结束身份立刻消失。

> **SUID 的本质：允许你这个程序"以我的身份"跑一次，只限这一段时间、这一个程序。**

| 关键点 | 说明 |
| --- | --- |
| 谁能设 | 文件属主或 root |
| ⚠️ **对脚本无效** | Linux 内核**故意忽略** `#!` 脚本上的 SUID/SGID（否则写个脚本就能提权） |
| 🔴 风险 | SUID root 程序是提权首选目标 —— **它自己一旦有漏洞，任何用户都能拿到 root** |

## 5.3 SGID 实测：目录内新建文件继承组

```bash
mkdir -p ~/sgid-test
chgrp users ~/sgid-test          # 免 sudo（cxh 在 users 组且是目录属主）
chmod 2775 ~/sgid-test
ls -ld ~/sgid-test
# drwxrwsr-x 2 cxh users 4096 /home/cxh/sgid-test/     ← group 位变 s
touch ~/sgid-test/a.txt
ls -l ~/sgid-test/a.txt
# -rw-rw-r-- 1 cxh users 0 /home/cxh/sgid-test/a.txt   ← ⭐ 属组是 users，不是 cxh
```

**对比**：普通目录新建文件属组会是 `cxh`。**SGID 的唯一作用就是"把新文件的属组钉死"** —— 团队共享目录的标准做法。

## 5.4 Sticky 实测：别人的文件删不掉

```bash
sudo mkdir -p /sticky-demo && sudo chmod 1777 /sticky-demo
touch /sticky-demo/cxh.txt
sudo -u nobody rm -f /sticky-demo/cxh.txt
# rm: 无法删除 '/sticky-demo/cxh.txt': 不允许的操作      ← 内核拦的
ls -l /sticky-demo/
# -rw-rw-r-- 1 cxh cxh 0 … cxh.txt                      ← 文件还在
sudo rm -rf /sticky-demo
```

```
drwxrwxrwt 2 root root 4096 /sticky-demo     ← 1777，带 t
```

**Sticky 规则**：目录里的文件，**只有"文件属主 / 目录属主 / root"能删**。

**为什么需要它**：`/tmp` 必须人人可写（所有程序都要临时文件），但**不能让人删别人的** —— 一个位解决这个矛盾。

> ⚠️ **实验教训（第一次失败了）**：不加 `-f` 时 `rm` 会先问"是否删除有写保护的普通空文件"，**根本走不到内核**。
> **`-f` 在这里的作用不是"强制删除"，是"跳过上层工具的礼貌询问，让底层真实错误露出来"。**
> **验证权限是否拦得住，一定要去掉上层工具的交互确认** —— 否则看到的永远是客气话。

## 5.5 SUID 审计（本机实测）

```bash
sudo find / -xdev -perm -4000 -type f 2>/dev/null | wc -l     # 18
```

- `-perm -4000`：**至少包含** 4000 这一位（前面的减号是关键）
- `-xdev`：不跨文件系统（避开 `/newdisk`、`/proc`）
- **18 个** —— 干净 Ubuntu 的正常范围（十几个到二十几个）。**上百个才需要查**

实测清单（前 12 个）：`passwd` `chsh` `sudo` **`pkexec`** `mount` `chfn` `newgrp` `umount` `gpasswd` `su` `vmware-user-suid-wrapper` `at`

### 攻击者挑哪个下手？

```
有已知漏洞的 > 版本旧的 > 被遗忘/没人维护的 > 到处都有的
```

| 目标 | 为什么 |
| --- | --- |
| **`pkexec`** | ⭐ **PwnKit / CVE-2021-4034**：polkit 的提权程序，**2009–2022 整整 12 年**影响所有主流发行版，**本地普通用户一条命令直接拿 root**。这就是"SUID 有漏洞 = 全系统沦陷"的最著名案例 |
| `vmware-user-suid-wrapper` | ⚠️ **第三方 SUID**（VMware Tools 装的）—— **不随 `apt upgrade` 更新**，容易被遗忘，却要 SUID root |
| `sudo` | ❌ **不是好答案**：它自己查 `/etc/sudoers`，不在组里直接拒绝，还要密码；而且审计最严 |

### 审计"野生 SUID"的真正手法

```bash
sudo find / -xdev -perm -4000 -type f 2>/dev/null | while read -r f; do
    dpkg -S "$f" >/dev/null 2>&1 \
    || dpkg -S "$(basename "$f")" >/dev/null 2>&1 \
    || echo "⚠️ 疑似无主：$f"
done
```

**逻辑**：每个 SUID 文件都应被某个包"认领"（`dpkg -S` 查得到）。**查不到 = 来路不明 = 最可疑。**

> ⚠️ 按 `basename` 查会带来**假阴性**（真有个恶意文件叫 `sudo`，会被误认为有主）。**这只是粗筛，警告还得人工核实。没有任何命令能替代"你认识清单上每一个名字"。**

## 5.6 ⭐ 实测假警报：`fusermount3` 与 **usrmerge**

审计报了唯一一条：

```
⚠️不属于任何软件包：/usr/bin/fusermount3
```

调查三步：

```bash
ls -l /usr/bin/fusermount3
# -rwsr-xr-x 1 root root 39296 4月 8 2024 /usr/bin/fusermount3     ← 权限 4755，SUID 正常

stat /usr/bin/fusermount3 | head -8
# 权限: (4755/-rwsr-xr-x)  Uid: (0/root)  Gid: (0/root)
# 修改时间: 2024-04-08 23:57          ← 包构建时间
# 创建时间: 2026-10-20 16:11          ← ⭐ 装系统那天

dpkg -S fusermount3
# fuse3: /usr/share/man/man1/fusermount3.1.gz
# fuse3: /bin/fusermount3            ← ⭐ 记的是 /bin，不是 /usr/bin！

dpkg -l | grep -i fuse
# ii  fuse3  3.14.0-5build1          ← 确实装了
```

**结论：假警报。** 原因：

> **Ubuntu 的 usrmerge —— `/bin` 是 `/usr/bin` 的符号链接。**
> deb 包里记录的是 **`/bin/fusermount3`**，而 `dpkg -S` 是**按字面路径字符串**匹配的，你给它 `/usr/bin/fusermount3` 就查不到。
> **同一个文件两个名字，dpkg 只认它记账时那个。**

**双向印证**：`stat` 的 **birth = 2026-10-20 16:11**，正是装 Ubuntu 那天。

### 三个时间的区别（重要）

| 时间 | 含义 | 常见误读 |
| --- | --- | --- |
| **mtime**（`ls -l` 显示的） | 文件**内容**最后修改 | "这文件是 2024 年的" ← 其实是**打包时间** |
| **ctime** | **元数据**（权限/属主）最后变化 | — |
| **birth** | 文件**创建**时间 | 这才是"什么时候进到这台机器的" |

> 📌 与 131 集同一个坑：`linux-0.01.tar.gz` 显示 1993 年，那是**归档时间**，不是诞生时间（1991）。
> **`ls -l` 只给 mtime；想知道"什么时候来的"，必须 `stat` 看 birth。**

## 5.7 那 11 个 SGID 文件：每个都在解决同一个问题

实测 `sudo find / -xdev -perm -2000 -type f 2>/dev/null`：

```
/usr/bin/plocate    /usr/bin/expiry    /usr/bin/ssh-agent   /usr/bin/crontab
/usr/bin/at         /usr/bin/chage     /usr/lib/xorg/Xorg.wrap
/usr/lib/…/utempter/utempter           /usr/libexec/camel-lock-helper-1.2
/usr/sbin/unix_chkpwd                  /usr/sbin/pam_extrausers_chkpwd
```

| 文件 | 属组 | 为什么需要 SGID |
| --- | --- | --- |
| **`unix_chkpwd`** | `shadow` | ⭐ **最关键**：普通用户登录/改密码要验证密码，而 `/etc/shadow` 只有 shadow 组能读 → 借组身份比对，**但只回答"对/不对"，不把散列给你** |
| `chage` / `expiry` | `shadow` | 能看**自己**的密码过期时间，看不到别人的 |
| `crontab` / `at` | `crontab` | 能写自己的定时任务（在 root 管理的目录里），改不了别人的 |
| `plocate` | `plocate` | 借组身份读 `locate` 数据库 |
| `utempter` | `utmp` | 写 `/var/run/utmp`，让 `who`/`w` 能看到登录 |
| `Xorg.wrap` | root | X 服务器启动需要部分特权 |

> 🔑 **`unix_chkpwd` 是 SUID/SGID 设计哲学的最佳范例**：
> **"我给你验证密码的能力，但不给你密码本身。"**
> 这就是安全设计里的**能力最小化** —— 不是给你一把钥匙，而是给你一个只会回答对错的窗口。

> ⚠️ **我的一个错**：我说 `/usr/bin/wall` 是 SGID（老版本行为）。**实测它是 `-rwxr-xr-x`，没有 SGID** —— 现代 Ubuntu 里 `wall` 通过 systemd-logind 拿终端权限，不再需要 SGID。
> **特殊权限位会随系统演进被去掉** —— 每多一个就是多一个提权面，发行版一直在减少。

## 5.8 完整性与 rootkit 检测（课件后半）

> ✓ chkrootkit / rootkithunter 检测 rootkit
> ✓ Tripwire 检测文件系统完整性

**rootkit 的手法**：

| 手法 | 例子 |
| --- | --- |
| 替换系统命令 | 换掉 `ps` `ls` `netstat`，**不显示**攻击者的进程和端口 |

**Tripwire 的原理**（比工具重要）：先给系统文件建**基线哈希**，之后定期重算比对 —— **rootkit 能骗过 `ps`，骗不过文件哈希**。

| # | 坑 | 教训 |
| --- | --- | --- |
| 1 | `sort` 只写一次 → 计数全是 1 | **`uniq` 只合并相邻行**，必须先排序聚拢 |
| 2 | `sort -n` 不加 → `10` 排在 `2` 前 | 默认字典序，按"数字"必须 `-n` |
| 3 | `cut -d "-" -f1` 碰巧能跑 | 取出来带**尾随空格**；**取字段要看语义，不是"能跑就行"** |
| 4 | 抓包抓到一堆 NTP/mDNS/HTTPS | **机器永远有背景流量**，不过滤抓不到想要的 |
| 5 | `>>` 没把统计摘要写进日志 | **统计摘要走 stderr**；`2>&1` 必须放 `>` 之后 |
| 6 | `chattr +i` 只锁 `/etc/passwd` | **`adduser` 先改了 `/etc/group`** → 留下半个组。要锁就锁全 |
| 7 | `grep 'oop'` 命中 `whoopsie`/`kernoops` | **`grep` 是子串匹配**，精确用 `grep -E '^x:'` / `-w` / `-x` |
| 8 | **我把组名 `ooop` 抄成 `oop`**，`groupdel` 报"不存在"，我**还编了个"NSS 缓存"去解释** | 🔴 **出现"命令说没有、grep 却有"时，第一反应是核对自己的输入，不要先编技术原因** |
| 9 | Sticky 实验第一次没加 `-f` | `rm` 自己的确认挡住了，**看不到内核真实的拒绝** |
| 10 | `fusermount3` 报"不属于任何软件包" | **usrmerge**（`/bin` → `/usr/bin`）导致 `dpkg -S` 字面路径匹配失败。**假警报** |
| 11 | `ls -l` 的日期当"文件年龄" | 那是 **mtime（打包时间）**；"什么时候装进来的"看 `stat` 的 **birth** |
| 12 | 我说 `wall` 是 SGID | ❌ 实测无 SGID，现代 Ubuntu 用 systemd-logind 代替 |

> **第 8 条是这一批最贵的教训**：抄错字符是手滑，**发明一个听起来专业的原因来解释矛盾**才是真问题 —— 那等于把"核对输入"这一步彻底跳过。

# 七 自测题

1. `cat t.log | cut -d"/" -f3 | sort | uniq -c | sort -nr` 里，**为什么 `sort` 出现两次**？
2. `sort -nr` 里的 `n` 不加会怎样？`-s` 是干什么的？
3. `http://IP/path` 用 `/` 切分，IP 是第几段？为什么不是第 2 段？
4. 统计连接数时用 `cut -d":" -f1` 去端口，遇到 IPv6 会出什么问题？
5. tcpdump 里 `[S]` `[S.]` `[P.]` `[FP.]` `[R]` 分别是什么？
6. tcpdump 抓 SSH 时，**为什么能看到 `OpenSSH_9.6p1` 这种信息**？这有什么安全含义？
7. `tcpdump … >> log` 之后，`wc -l` 为什么**不包括** `10 packets captured` 那几行？
8. `chattr +i /etc/passwd` 之后 `adduser` 失败，但系统里为什么多了一个组？
9. SUID 和 SGID **加在目录上**时，效果一样吗？
10. `/tmp` 的 `1777` 里，那个 `1` 解决了什么矛盾？
11. `find / -perm -4000` 查出 18 个文件，怎么判断有没有可疑的？为什么 `dpkg -S` 会误报？

<details>
<summary>答案</summary>

1. **第一次 `sort`** 是为了把相同行**聚拢**（`uniq` 只合并相邻行）；**第二次 `sort -nr`** 是按次数**降序**输出。
2. 不加 `-n` 按**字典序**：`1 → 10 → 2`（因为字符 `1` < `2`）。`-s` = **稳定排序**，平局时保持原顺序。
3. 是 **`-f3`**。因为 `//` 之间是空内容，**算一个空字段**，占了 `-f2`。
4. IPv6 地址本身含冒号，`cut -d":" -f1` 会把 `2a04:4e42:…` 截成 `2a04`。用 `ss -tan4` 或 `grep -v '::'`。
5. `[S]` SYN 发起 · `[S.]` SYN-ACK 同意 · `[P.]` 带数据的 ACK · `[FP.]` 主动关闭（FIN+PSH） · `[R]` RST 拒绝。
6. **加密开始前双方必须先交换版本号字符串**。安全含义：抓包就知道对端**系统 + 软件 + 精确版本**，可直接拿去对 CVE；所以加固建议改 banner。
7. 因为 tcpdump 的**统计摘要走 stderr**，而 `>>` 只重定向 **stdout**。要一起收得 `> file 2>&1`（顺序不能反）。
8. 因为 `adduser` **先写 `/etc/group` 造组，最后才写 `/etc/passwd`** —— `i` 属性在最后一步才挡住，组已经写进去了。所以要锁就锁 `/etc/passwd` `/etc/shadow` `/etc/group` `/etc/gshadow` 全部。
9. **不一样**。加在文件上＝执行时改变有效组；加在**目录**上＝**目录内新建的文件/子目录继承目录的组**（这才是常用功能）。
10. 解决"**人人可写**"与"**不能删别人的**"这对矛盾：`777` 允许所有人建文件，粘滞位 `1` 限制只有属主/目录属主/root 能删。
11. 用 `dpkg -S` 逐个认领，**查不到 = 可疑**。误报来自 **usrmerge**：包记录的是 `/bin/xxx`，实际路径是 `/usr/bin/xxx`（`/bin` 是符号链接），而 `dpkg -S` 按字面路径匹配。

</details>

# 八 一句话总结

> **142：四阶段管道 —— 截取 → 排序（聚拢）→ 计数 → 排序（降序）。`sort` 必须出现两次。**
> **144：tcpdump 负责拿数据，管道负责把数据变成结论；`host … and port 22` 不是为了好看，是不加就只剩噪音。**
> **145：权限划分 = 权限对象 + 四条因素（分离 / 最小 / 少 root / `chattr`）；`chattr +i` 连 root 都挡，但只锁一个文件会漏。**
> **146：SUID 是"临时以别人身份跑一次"，SGID 目录是"把新文件属组钉死"，Sticky 是"人人可写但删不了别人的"。审计 SUID 要能回答"你凭什么当 root"。**
