## 五、救砖（**动手前必须先知道**）

板子刷坏**不等于报废** —— 瑞芯微方案有 **Maskrom 模式**，是从芯片层强制进入下载模式，**只要芯片没坏就能救回来**。

大致流程（**具体按键/短接位置以实物为准**）：

```
断电 → 让板子进入 Maskrom（按键或短接）→ 插 USB 到电脑 →
电脑上 RKDevTool 显示"发现一个 Maskrom 设备" → 重新烧固件
```

**我会在动手前带你确认：**
1. 你这块板子**怎么进 Maskrom**（按键？短接？）
2. **插哪个口**（丝印确认，插错不识别）
3. 进 Maskrom 后**电脑上怎么验证**（RKDevTool 的提示长什么样）

> 🔴 **绝不在"不知道怎么救"的情况下开始刷机。** 这是硬规矩。

## 十、ADB 连接（2026-11-13 打通，含踩坑）

### 环境事实
- **adb**：`winget install Google.PlatformTools` 装的官方版（**在 PATH 里**，直接敲 `adb`）
- **不要用** RKDevTool 自带的老 adb（1.0.40）—— 会与新版 server 版本冲突（`server version (40) doesn't match this client (41)`）
- **板子 IP**：`192.168.88.103`（**注意网段是 88**，2026-11-13 实测；DHCP 可能变）

### ⭐ USB ADB 打通的完整条件（缺一不可）
| # | 开关 | 位置 |
| --- | --- | --- |
| 1 | **USB 调试** | 设置 → 系统 → 开发者选项 |
| 2 | ⭐ **USB OTG 模式切换 = 打开（Device 模式）** | 同一个页面，**这是最容易被忽略的一条**（关闭=Host 模式，电脑永远认不到） |
| 3 | USB 用途选「**文件传输**」 | 通知栏那个 USB 通知 |
| 4 | 数据线插 **板子中间那个 Type-C**（数据口），**电源另接右边 Type-C** | 手册接口图 |
| 5 | Windows 侧驱动**只能有一个** `Android ADB Interface` 实例 | 有重复/黄叹号时：卸载 → 重新插拔 |

### 无线 ADB 两种方式
**① 临时（`tcpip 5555`，重启失效）**
```powershell
adb disconnect
adb shell "ip addr show wlan0 | grep inet"   # 取 IP
adb tcpip 5555                                # restarting in TCP mode port: 5555
# 拔掉数据线（电源独立，不影响板子）
adb connect 192.168.88.103:5555
```

**② 永久（无线调试 + 配对码，重启不用插线）**
```
板子：开发者选项 → 无线调试 → 打开 → 允许该网络
     「IP 地址和端口」= 连接端口（如 45235）
     「使用配对码配对设备」= 配对端口（如 44309）+ 6 位配对码
电脑：
     adb pair   192.168.88.103:<配对端口>    ← 输入 6 位码
     adb connect 192.168.88.103:<连接端口>
```

> 🔴 **两个端口不一样！** 用配对端口去 connect 永远连不上 —— 这是本步骤唯一的大坑。

**③ ❌ mDNS 服务名连法 —— 在 Windows 上不可用（2026-11-13 实测失败）**
配对后 `adb devices` 会多出一条看似服务名的条目：
```
adb-93f733f5d6fc6fa2-Y33cBI._adb-tls-connect._tcp    device
```
**但那只是 adb 显示的别名，不是可用连接路径。** 实测：
```powershell
adb connect adb-93f733f5d6fc6fa2-Y33cBI._adb-tls-connect._tcp
# → cannot resolve host '...' : 不知道这样的主机。(11001)
```
**原因**：`adb connect <名字>` 走**操作系统级 DNS/mDNS 解析**，Windows 默认**没有 Bonjour/mDNS 解析器**，所以解析失败。`adb mdns services` 也返回空，印证这一点。
**结论：Windows 上只能用 `IP:端口`。** 端口每次重启会变 → 重启后要回板子「无线调试」页面看一眼端口。

> 📌 **学习者的决定（2026-11-13）：不固定 IP、不设静态 IP。** 每次重启都手动连一遍，用重复来加深记忆。
> **因此每次要从板子「无线调试」页面同时读出 IP 和端口**（DHCP 会让 **IP 也可能变**，别凭记忆写 IP），然后：
> ```powershell
> adb connect <板子上那一行的 IP:端口>
> adb devices
> ```

### ⚠️ 常见坑
| 现象 | 原因 / 解法 |
| --- | --- |
| `error: more than one device/emulator` | **触发条件是「≥2 个处于 `device` 状态的设备」**。实测：`1 个 device + 1 个 offline` **不会**报错，命令照常执行。出现多条 `device` 时 → `adb disconnect` 清空后只连一条，或用 `adb -s <设备> shell` |
| `adb shell ls / \| head` 报 `head 不是 cmdlet` | **管道在 Windows 跑了** → 加引号成 `adb shell "ls / \| head"`，让管道在板子里跑 |
| `device` vs `unauthorized` | `unauthorized` = 板子上没点"允许 USB 调试" |
| `cat /proc/cmdline` → Permission denied | **Android 收紧 procfs 限制**，不是文件权限问题（普通用户看不了） |
| `getenforce` → `Permissive` | 官方开发板镜像**放松了 SELinux**（只记录不阻止）→ 能改的东西更多，也更容易搞坏 |

### Android 侧的关键认知（实测）
- 分区表（`/dev/block/by-name/`）：`security, uboot, trust, misc, dtbo, vbmeta, boot, recovery, backup, cache, metadata, baseparameter, **super**, **userdata**`
- **`super` = dm-0~dm-7 的来源**（动态分区，装着 system/vendor/product/odm…）
- **`/data` 用 f2fs**（不是 ext4）；`/sdcard` 是 FUSE 视图，真实位置 `/data/media/0`
- `zygote64(446)` → `system_server(653)` 是 Android 进程树的根
- **16GB 内存**：开机 + 几个 App 只用约 2GB，剩约 13GB 可用
