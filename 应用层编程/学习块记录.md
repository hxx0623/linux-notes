### 复测（2026-11-21，补讲后换角度再测）

| 题 | 考点 | 结果 |
| --- | --- | --- |
| A | 静态链接 glibc 的程序，服务器 glibc 升级修了漏洞，还受影响吗 | ✅ 对（答「受」） |
| B | `undefined reference to 'add'` 该先怀疑什么 | ✅ 方向对（少给了 .o） |

**A 题他答对了关键那层**：静态链接把旧的 glibc 代码复制进了自己的可执行文件，系统升级动不了它 —— 所以漏洞仍在，必须自己重新链接才行。这正好是第 1 题「更快」那个错误的反面，说明补讲吃进去了。

### 实测验证（2026-11-21）

在 `~/helloworld` 真跑了一遍：

```
$ make clean        → rm main hello.o main.o
$ make              → gcc -c hello.c / gcc -c main.c / gcc hello.o main.o -o main
$ touch hello.c
$ make              → gcc -c hello.c / gcc hello.o main.o -o main   ← 两条，传导确实发生
```

**结论：他的 Makefile 写得对，第 3 题错在「说不清」而不是「不会」——属于隐性知识，不需要重讲，只需要把它语言化。**

### 三个缺口

1. **静态链接不是"更快"** —— 它的取舍是「体积变大、库更新要重链接」换「自包含、不挑运行环境」。运行速度没有差别。
2. **make 的依赖会传导** —— 改了 `hello.c` 不只是重编它，`hello.o` 一变，`main` 也就过期了，必须重新链接。他只看了一层。
3. **符号解析的反向判断** —— 看到 `gcc -o main math_util.o`，要问「谁被漏了」；漏掉含 `main` 的那个 `.o`，链接器报的是 `undefined reference to 'main'`。

### 复测（同日）

### ⭐ 重要发现：课件错了

课件写「make 命令最终以返回码 **1** 推出了」。

**错的。** 那个「错误 1」是 `rm` 的退出码；make 自身遇到错误返回 **2**（GNU make 手册：0 成功 / 1 是 `-q` 且目标需更新 / 2 出错）。

**教学口径：课件是教学材料不是标准，有疑问以 `man make` + 实跑为准。** 用户先答对了 2，再实测确认。

## 块 003 · 集 20–24：fopen / fclose / fputc / fputs / fprintf

- **日期**：2026-11-21
- **docx 对应**：`C标准I/O库函数回顾 → 打开/关闭文件（fopen、fclose）/ 向文件中写入数据（fputc、fputs、fprintf）`

### 出题与结果

| # | 类型 | 考点 | 结果 |
| --- | --- | --- | --- |
| 1 | 基础事实 | 六个打开模式里哪些能创建文件、哪些必须已存在 | ✅ 对 |
| 2 | 改条件 | `"w"` 与 `"a+"` 打开后立刻关闭，对已有内容的影响 | ✅ 对 |
| 3 | 预测 | `fputc('A')` 与 `fputc(65)` 的内容与返回值 | ⚠️ 半对：内容对，返回值只说「非负整数」 |
| 4 | 找茬 | 不写 `fclose`，`return 0` 后文件里有没有数据 | ❌ 错：答「没有，还在缓冲区」 |

### 复测（同日）

| 题 | 考点 | 结果 |
| --- | --- | --- |
| A | 把 `return 0` 换成 `_exit(0)`，数据还在不在 | ✅ 对：没有（`_exit` 不 flush） |
| B | `"r"` 模式打开后 `fputc` 的返回值 | ✅ 对：`-1`（EOF） |

**结论：初测 2 对 / 1 半 / 1 错 → 补讲 → 复测 2/2 → 通过。**

### 两个必须记住的点

1. **`fputc` 成功返回写入的字符值**（`'A'` 和 `65` 是同一个东西，都返回 65），失败返回 `EOF`（-1）。用「永远 ≥0 的返回值 vs -1」来区分成败。
2. **`fclose` 的真正意义不是「防丢数据」，是「及时释放 fd」**。
   - `return` / `exit()` → **会 flush**，所以不写 `fclose` 数据一般也在
   - `_exit()` / `_Exit()`、段错误、`kill -9` → **不 flush**，数据真丢
   - fd 默认上限 1024，长跑程序不关文件会耗尽
